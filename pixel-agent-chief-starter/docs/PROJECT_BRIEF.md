# 项目执行基线（PROJECT_BRIEF）

## 产品定位

一个 AI Native 的像素风“盒子世界”个人助理：用户以“神谕”方式提出现实任务或世界环境指令；Agent 的真实任务执行在世界中通过角色、工坊与进度可视化表达。无任务时世界由本地规则运行，不依赖 LLM 持续驱动。

## 已确认设计方向

- 纯 2D 正交像素风；像素完美和原生分辨率可读性优先，关闭抗锯齿模糊并使用整数缩放。
- 当前设计决策为 **Phaser 3 + TypeScript + Vite**。Bevy、Godot 等内容属于历史备选或迁移讨论，不得因此重新启动选型，除非真实仓库或用户最新决定要求重新评估。
- Tiled 作为静态底图/Zone 标注工具；动态运行时空间由自研 `WorldGrid` 管理。
- 建筑和装饰使用数据化 Prefab/JSON 与 Aseprite spritesheet；寻路方案记录为 EasyStar.js。
- 采用轻量数据组件/系统函数，不引入重型 ECS；数据状态与 Phaser 表现层解耦。
- 状态与事件使用集中 `GameState` 和 Phaser 事件机制；Agent 通信采用异步 WebSocket/消息队列，支持重连、心跳与错误处理。
- 首期使用伪光照：全局调色、发光贴图和混合模式；完整动态 Light2D 属于后续评估项。
- LLM 只产出语义/意图层结构化提案；所有输入经过 Schema 与确定性校验，失败走模板或 Mock 降级。程序持有事实、空间、状态机、资源账本和生命周期。
- 不做主动键鼠游戏玩法；用户通过指令/“神谕”影响世界。
- 不需要语音陪伴、TTS 或主动语音播报；语音能力定位为用户语音输入指令。MVP 1.0 按原范围先使用文本输入框与预设按钮，不自动追加语音输入，除非用户明确调整样品范围。

## MVP 1.0 范围

### 必须包含

- 一张固定预制地图。
- 2–3 个小人。
- coding、research、生活三个工坊；每个工坊先做 Idle/Operating 两种状态。
- 高质量 Mock 驱动的神谕路由；LLM 可选地用于意图解析和气泡文本，核心流程必须可离线降级。
- 晴/雨天气切换及户外角色躲雨行为。
- 模板式 DOM 日报。
- JSON 存档，单存档槽。
- 简单上帝调试面板：实体列表与事件流。
- 一个文本“用户下指令”入口。

### MVP 1.0 暂不包含

自由生成世界、自动修路/复杂布局评分器、完整 Utility AI/行为栈并发、季节与完整昼夜、完整编年史叙事、命名系统、多存档/云同步、完整可视化编辑器、语音输入、多轮对话，以及完整动态 Light2D。后续若调整，必须由用户批准并记录 ADR。

## 样品验收目标

1. 原生分辨率下，3 秒内能指出主角、当前神谕状态以及正在工作的工坊。
2. 输入研究任务后，角色礼仪响应、走到对应工坊、播放工作动画/进度并生成日报，全链路无卡死。
3. 输入下雨指令后，雨幕出现、户外小人躲雨；TTL 后恢复默认天气。
4. 关闭重开后，世界状态、编年史与资源账本能恢复。
5. LLM 离线时 Mock 仍能跑通以上流程。

## 质量与安全原则

- 可运行性优先；每个 Phase 结束都要有可演示成果。
- 先写并批准 3 分钟演示剧本，再大规模施工。
- Mock-first，真实 Agent 后置。
- 主分支保持可运行；严格 TypeScript，避免未定义 `any`。
- 状态事实与视图分离；外部通信异步，渲染循环不等待网络/LLM。
- LLM 输出必须经 Schema 校验和确定性验证；不可信提案不得直接修改 GameState。
- 每项任务记录证据、测试结果、已知问题和下一步；未经实际验证的状态一律标“未验证”。
