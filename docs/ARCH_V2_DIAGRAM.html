A · 模块与数据流（§2.3 模块关系、§5.2 事件清单）

右侧竖带 = 事件总线，横切所有后端模块，每个模块向右发事件（附录 C 第 2 条）。虚线直角框 = 数据，不执行（第 3 条）。
主通路（契约 → 派单 → 验收 → 交付） 人工 / 失败出口 记忆写回 · 实线 = 事实（promoted/confirmed） 记忆写回 · 虚线 = 经验（distilled） 事件上报

B · 时间轴 + 泳道（附录 C 第 5 条、§5.7 事件脚本 e1–e17）

横轴是 §5.7 的真实时间戳（相对 e1），纵轴是四条泳道。同一竖线上的方块 = 同时发生—— t≈1.0s 时 Task 已 DISPATCHED 而 Step 在 RUNNING；t≈2.0s 打回（T16）与第二次 VERIFYING 交叠。 不是「上一页 / 下一页」。

C · BLOCKED 分支（附录 C 第 1 条、§4.2 状态集、§4.4 迁移表、§4.6 失败分类）

BLOCKED 是一个状态，不是一个分支族。它带两个必填字段：reason（5 个取值）与 resume_to（4 个取值）。没有 resume_to 的阻塞等于把任务丢进黑洞（§4.2 :441）。 右侧五个方块是 reason 的取值，不是并列的状态。
