## 完整卡为什么仍不能直接采用

版本卡的前三条建议是固定版读取、预览、取得确认后保存，主要受共同契约及成功过程支持。四个证据 ID 都真实、不同且属于该来源，分别指向读取、预览、成功保存和冲突拒绝。程序接纳正确地保留了原模型内容，没有人工修正。

第四条建议是：

> 若 confirm 返回 base_version_conflict，需重新 preview 获取最新 base，不可假设已保存。

“不可假设已保存”有实际冲突回执支持；“重新 preview 获取最新 base”没有。失败过程中只观察到冲突后未写入，随后 read 仍返回固定 V1、`selected_version_is_current=false`。共同契约定义 preview 基于固定当前基底产生候选，没有提供刷新或重新绑定基底的能力。由真实冲突引用，不能推导出一个未执行、契约也不支持的恢复办法。

两份独立 Codex 定性复核均指出这一问题。局部卡只能检查已公开片段，其中对截断、重复定位失败的停止条件处理不足；进度卡没有公开内容，无法作语义评价。这些意见不是人类打分或准确率，未回写为自动语义通过。B 在一次结构检查中额外看到包装字段，访问偏离在其 metadata 明示，未用作判断依据；这里不称为严格盲评。
