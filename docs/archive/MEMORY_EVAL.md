# 小规模真实记忆抽取评测入口

2026-10-13。项目 A 阶段的运行工具已实现；用户明确选择项目推理配置和 `step-5-preview` 后，首轮真实运行已完成，见[实际记录](../eval/research/memory_live_review_20261013.md)。此前的程序合同探针用人工候选检查规则，本入口用模型公开输出经过实际抽取器、管理器、存储、检索和临时库重开验证。流程完成和合成替身测试通过均不代表实际语义准确率。

## 固定输入与边界

输入为 [memory_live_cases.json](../eval/research/memory_live_cases.json) 的 12 组合成题：雇主/岗位、跨轮独立事实、明确纠正、歧义冲突、第三人引述、假设与扮演、助手断言后用户“继续”、临时状态、无关检索、明确偏好、删除后回放、关闭再开启后回放。

每题独立临时 SQLite 库，用户原话先保存再抽取；期望仅在人工评审表，不进入提示词，也不通过 remember/upsert 写入期望答案。来源和生命周期守卫应拦截的输入不调用模型。助手消息保存在合成聊天日志用于核对来源，不作为抽取证据。检索只检查实际数据，不另调用生成模型回答；因此本轮不测未知问题的生成弃答能力。偏好题检查事实抽取，不自动创建或升格结构化长期行为偏好。

固定最多 **12 次提取 × 每次 800 个请求输出 token = 9,600 个请求输出 token**，重复 1 次，单次超时 45 秒，每次最多 1 个 HTTP 尝试，没有隐藏重试。全局及每题均有预算守卫，调用前先落盘预约。费用还受输入、模型价格、服务商计费和实际遵守输出上限影响；这个数字不是人民币封顶。付费运行需用户明确选择服务与运行范围。本轮用户沿用项目配置，完成12次请求，服务商报告输入8099、输出3676 token；账单金额尚未核对。

## 默认仅生成计划

在项目目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/eval_memory.py
```

默认生成唯一新路径 JSON，状态为 `planned`，不导入服务端、不读 `.env`、不打开数据库、不调用模型。现成可审阅计划为 [memory_eval_plan_20261013_a_stage.json](../eval/research/memory_eval_plan_20261013_a_stage.json)，其中调用数为 0。

计划与报告不覆盖旧证据。若指定 `--output` 且路径存在，会拒绝；真实运行每步保存中间结果，错误或中断保留 `partial`，不伪称完成质量评估。

## 显式真实运行

仅在确认模型和费用范围后执行；凭据放在指定环境变量中，命令和报告不填写密钥：

```powershell
.\.venv\Scripts\python.exe scripts/eval_memory.py --live --provider <服务商> --base-url <HTTPS兼容API地址> --model <模型名称> --reasoning-effort low --api-key-env MEMORY_EVAL_API_KEY
```

`--live` 必须显式提供 provider、HTTPS base URL、model 及非空环境密钥。没有 `.env` 或生产 `LLM_API_KEY` 自动回退；mock、缺失配置、嵌入凭据的 URL 均拒绝。运行时先把服务端配置限定为 mock / 空密钥 / 内存全局库，再用显式依赖注入创建仅供本次评测的客户端及临时库；真实用户库不参与。退出关闭客户端并清理临时数据库，报告保留。

`--reasoning-effort` 是显式枚举，默认空表示不下发，指定 `low` 等值会记录在报告并透传。授权首轮由一次性启动程序仅取项目 LLM 连接与抽取强度，模型覆为 `step-5-preview`，密钥转到当前进程专用变量；评测 CLI 没有新增默认读取项目凭据的行为。模型名称与强度是请求配置，报告未独立验证网关解析的模型身份或强度执行效果。隐藏推理仍不记录，模型公开响应保留。

## 结果如何判断

报告保留公开回复原文（有长度上限和截取标记）、解析候选、丢弃原因、实际写入决策行、当前/历史记录、前后检索及重开结果；记录白名单 usage、finish reason 与耗时。隐藏 reasoning、密钥、任意服务商错误正文不保存。调用超时/失败占用预约次数，不重试；usage 超出请求输出上限会停止后续运行。缺失 usage 保留缺失，不能估造费用。

`status: complete` 仅表示固定步骤执行完。首轮 12 个场景中，9 个实际调用模型，共 12 次提取；第三人、假设和关闭输入的拦截属于程序守卫证据。`manual_review` 保持 null，不能把无异常或关键词匹配称为含义被证据支持。人工复核至少逐项检查：

1. 候选主体、属性、范围与来源是否被原话支持，而不仅是引用确实存在。
2. 独立事实是否保留；纠正、歧义和重复是否作出恰当决策。
3. 删除/关闭后的旧输入是否零调用、零复活；重开后的真实数据是否一致。
4. 无关检索、冲突与历史是否按契约隔离；没有候选究竟是适当弃取还是遗漏。

边界不足、临时状态误记和词法过滤误拒均作为失败或遗漏保留，后续扩题或对照模型前固定评分口径。当前不是完整 60 例题族，也不测事实有效时间、同义属性合并、生成回答或跨日实际使用效果。

离线验证入口：`python -m unittest scripts.test_memory_eval`，**19项通过**。其中合成 provider 驱动的是实际保存消息→抽取→决策→检索→重开链路；HTTP MockTransport 检查单次尝试、默认重试兼容和错误正文处理，另覆盖双字段用量超限与显式推理强度。历史合同证据见 [MEMORY_EVIDENCE.md](MEMORY_EVIDENCE.md)，路线见 [PROJECT_DIRECTION.md](PROJECT_DIRECTION.md)。
