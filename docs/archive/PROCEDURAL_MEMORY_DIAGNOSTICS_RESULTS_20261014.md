# 公开输出诊断与失败教训结果

日期：2026-10-14。运行：`procedural_memory_diagnostics_v1_live_20261014T021550_bbb6764a`。模型：`step-3.7-flash`，`reasoning_effort=low`，temperature=0.1。

提高输出预算在一组固定输入上伴随公开输出恢复，但没有解决所有输出契约或经验判断问题。新失败教训正确描述了冲突未保存，并给出当前流程的停止条件；第三项却把公开正文已经可以核对的替换适用性笼统写成未知。候选保持原样，没有接入生产。

## 六个预定输出对照

| 固定输入 | 请求输出上限 | 实际输出 token | 公开字符 | 结束 | JSON对象完整 |
|---|---:|---:|---:|---|---|
| 简单控制 | 1200 | 38 | 21 | stop | 是 |
| 简单控制 | 3600 | 41 | 21 | stop | 是 |
| V2 局部修改 | 3600 | 1174 | 563 | stop | 是 |
| V2 局部修改 | 1200 | 1021 | 417 | stop | 是 |
| V2 进度改写 | 1200 | 1200 | 0 | length | 否 |
| V2 进度改写 | 3600 | 1035 | 426 | stop | 是 |

每个配对输入的指纹完全相同，其余请求参数固定。没有隐藏重试，3600请求属于事先规定的对照。局部输入这次1200也正常结束，区别于旧V2的截断；进度输入1200再次空输出、3600正常结束。每格仅一次，随机性、缓存、时序和顺序仍存在，不能断言预算是唯一原因或估计稳定完成率。

服务商这些回执的 `reasoning_tokens=0`，空输出只能记录公开现象，不能据此推断内部生成过程。服务商实际返回的公开文本均未被host截断。正常结束且JSON可解析，只衡量公开对象是否完成。

另一个可直接核对的契约问题是：局部1200和进度3600的完整对象都将 `evidence` 写成字符串数组，而V2要求 `[{"observation_id":"..."}]`。它们没有因为JSON完整而成为合格经验。这是原输出的字段形状观察，不是使用失效历史来源进行候选接纳；所有诊断重放输出仅用于诊断，未入库，也未进行完整语义评分。

## 一条真实失败归纳

单独执行一次版本冲突来源的真实临时领域操作，再用3600预算请求一次，没有提供手写答案或成功来源。输入1687、输出2721，共4408 token；公开954字符，stop。原输出含三项主张、五项逐字段引用，全部引文字段、原值和类型与当前公开来源一致，临时保存及重开一致。

| 原始主张 | 定性判断 |
|---|---|
| confirm操作因base_version_conflict失败，未执行写入 | 冲突回执和write_observed=false直接支持；仅指本次确认，不抹去别的窗口已做的更新 |
| 当检测到base_version_conflict时，应停止确认流程 | 当前绑定旧基底的流程及共同契约支持停止；不能解释为永久禁止后续新流程 |
| 无法确定预览的替换是否仍适用于并发更新后的内容 | 表述过宽：完整V2公开正文中目标旧文本仍唯一存在；未验证的是重新绑定V2后操作的能力与授权，不能把文本匹配也归为未知 |

完整V2正文实际为：

```text
等待复核。
窗口间需要保留各自修改。
另一个窗口新增了复核人。
```

原替换为“等待复核”→“正在复核”。新正文未截断，旧文本仍出现一次；字符串层面的适用性可核对。当前read/preview/confirm路径仍绑定旧V1，不能从“文本还能匹配”推出“旧提案现在可以写入”；同样，冲突拒绝也不能证明文本匹配未知。

两份独立Codex定性复核均指出第三项的边界问题，没有发现候选虚构已验证恢复步骤。复核不是人类评分，也不是严格盲评，原始report的semantic_scores/manual_review及候选semantic_review保持null。引用通过与语义成立继续分开。前两项还主要重述已给定的失败契约，不能凭此宣布学到了新的迁移能力。

## 执行记录与限制

实际7次预约、7次HTTP完成、0假调用，恰好预约18000输出token上界；实际输入31703、输出7230、总计38933 token。没有目标执行、留出评估或线上记忆使用。

运行使用15文件的 `diagnostics_v1` 冻结副本，父子manifest哈希、配对输入、实际脚本/LLM/领域模块路径、逐请求一次与结束验证全部一致。旧schema1/13文件副本仍可验证；首轮清单绑定的7份材料保持原哈希。历史输入在准备时独立核对原V2报告及消息指纹，运行时核对冻结输入自身。报告是历史材料，运行后源库关闭。

离线检查共79项：78通过，1项因Windows符号链接权限跳过；另有无需该权限的reparse检查。其中诊断新增15项全通过，新增profile与旧兼容也受测试覆盖。测试证明执行、预算和引文契约，不证明中文归纳正确。

## 下一步

下一轮先评估一个更准确的判断边界：公开数据是否足够、当前工具是否能执行、当前操作是否有授权，分别判断。具体测试要区分完整新正文仍唯一匹配、新正文匹配已改变、正文不完整，以及有无重新绑定能力；不能一见版本冲突就全部归为未知，也不能一见匹配就直接保存。

先在开发来源上冻结这套判定和独立语义评分规则，再选择新的来源家族与目标做留出实验。对照仍保留无记忆/原始经历/模型教训，核对最终行为而不只看卡片。当前继续留在评测阶段，不增加生产记忆层或Agent框架。
