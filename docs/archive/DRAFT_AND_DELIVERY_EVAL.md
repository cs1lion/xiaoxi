# 草稿事实边界与流式交付验收

## 草稿边界

新增 [drafting.py](../server/interaction/drafting.py) 作为普通对话/助手决策层共用约束：只用已提供资料和真实回执；任务存在不等于完成；未知进度、状态、指标使用占位；模板固定文字也不预设成功；虚构示例明确标识。

助手入口补充可确定的模板标签规则：写作final含【】且缺少模板/待填写/虚构标识时加“模板（待填写）”。这不是事实核验器，不能证明所有句子有证据。

## 真实模型证据

脚本 [eval_draft_grounding.py](../scripts/eval_draft_grounding.py) 通过实际AssistantService._decide调用当前step-3.7-flash，而非用替代prompt。临时独立库，无历史记忆、无执行工具；每轮四种输入，一次样本，无统计性结论。

- [第一轮](../eval/draft_grounding_01.json)：已有占位但一句开头未标模板；大模板仍有“完成【事项】”“确保达成”等暗含成功，不能仅凭有占位就判通过。
- [第二轮](../eval/draft_grounding_02.json)：补中性模板约束与确定标签后，无资料场景显示待填写，完整模板改为“实际状态”“已核实进展”；有资料的登录错误保持“持续排查中”，未升级成解决；虚构场景保留明确标识。

残余：一句开头仍使用“重点推进了【事项】”等模板句式，但明确标模板且事实槽未填。未对任意长文进行蕴含校验；不能承诺零幻觉。技术知识准确性与角色语气仍需独立评测。

## 流式验收

已实现并通过17项隔离流式测试：规范化和长度预算发生在交付之前，累计text_delta等于done与存储文本；音频索引连续含尾段；音频故障不冒充成功；中断回收任务。保持句级输出，不等整个回答生成完再开始。测试覆盖首句即时交付、长回复预算、分片情绪标签、未知标签及正文括号、多句尾段索引、TTS异常、LLM异常、取消及aclose回收。

故障语义：TTS某段失败会发error，继续后续段，done表示文本完成而非全部音频成功；成功音频索引连续。真实TTS挂起仍有单次30秒超时。边界收口：done.delivery携带text_status=complete/limit_reached/partial，audio_status=synthesized/partial/failed/none，成功和失败段数，playback_confirmed恒false（后端合成不证明扬声器播放）。limit_reached表示主动预算停止，不断言必有遗漏，前端提示“可能尚未展开完整，可以继续”。可恢复TTS/生成错误携带recoverable=true，应用WebSocket转发而不终结轮次，前端不清空播放队列，最终在气泡追加非正文状态提示。真实生成中断标partial，不冒充完整回答。供应商静默截断若没有错误或finish reason事件仍不能被此层识别。未知标签可能作为正文保留，以避免误删事实。

父级复核17项流式测试通过（已加入delivery状态断言），WebSocket 3项含可恢复错误后done状态透传通过，前端语法与协议检查通过；本轮新增气泡提示未做浏览器视觉验收。此前原任务与偏好浏览器测试通过。浏览器旧夹具两次失败分别是并行新增task-card模块未提供、任务卡片文案已更新；仅更新夹具依赖及语义定位，不改用户现有任务卡实现。

测试为合成流与模拟TTS，不代表真实扬声器播放或外部TTS音频内容正确。长回答受配置硬上限约束，不承诺无限长度完整朗读。首句本身超过预算时仍可能字符级截断，因此不能保证超长代码/占位结构和语义完整；应另行设计文档交付而非无限延长语音。

另一个跨域风险：旧清洗器把短括号内容全部视作动作描写，可能删除【实际状态】占位、列表和坐标。流式规范化必须区分已知开头情绪标签与正文括号；不能为去掉表演性动作而吞掉技术事实或草稿槽位。

草稿回归：HTTP/服务5项、broker 10项、回应策略13项、Agent Loop 8项已通过；真实草稿调用两轮8次成功，语义结论以逐条原文为准，不把调用成功等同事实正确。
