# 保存的原稿，隔天仍从同一处继续

2026-10-13 实施记录。本轮把个人便笺、共同事项、主聊天和声音连接到同一组明确选择的对象。

2026-10-14 更新：有共同事项时，笔记来源改为[本事项明确关联的当前稿](SHARED_THREAD_MATERIALS.md)，不再自动组合个人笔记选择。下方个人关联流程仍适用于没有选定共同事项的情况；事项内保存新版后应在事项资料中明确更新版本。

```text
保存演示稿 v1 → 点击「关联之后的对话」
保存演示稿 v2 → 仍关联 v1，提示存在新版
重开页面 / 重建服务 → 恢复同一事项和原稿 v1
用户：接着昨天
阿栖：播报当前选定的事项、下一步、便笺版本及新版提示
用户明确载入并关联 v2 → 后续请求才使用新版
```

“接着昨天”是恢复所选对象的入口，不推断这些内容是在昨天发生，也不重新执行以前的操作。

## 已实现的闭环

- 便笺每次保存保留不可覆盖的版本。明确关联固定 `note_id + version`；打开、编辑、保存不会自动改变关联。关联通过独立 `revision` 比较更新，另一页已变更时返回 409，保留当前编辑内容，刷新后由用户重新决定。
- 共同事项复用现有持久选择。`ActivityFacade` 只读组合两种对象，提供稳定 `activity_id`、对象引用、版本状态和确定性接续摘要；不再按“最近更新任务”猜测当前工作。
- 笔记页启动时恢复已选版本；旧版只读，提供载入当前版的入口。主页显示版本差异、下一步和准确链接；切换标签保留同一个编辑器文档，未保存草稿不会加入模型资料。
- 新连接的“接着昨天”“继续上次”等明确恢复句直接返回已保存状态，随后沿用有声交付器。无模型归纳、工具重做或虚构完成记录。普通“继续”保留原聊天/事项流程，不自动读取便笺正文。
- 明确笔记或起草请求可读取所选保存版。普通聊天的资料以单独的 `user` 数据消息加入，位于当前请求之前；不写入聊天记录、不充当系统行为策略、不作为本轮记忆抽取证据。行动澄清和确认继续固定最初使用的便笺版本，不采用后来另一页选择的对象。
- 增加只读工具 `note.search`、`note.read(note_id, version)`、`thread.read(thread_id)`、`run.receipt(run_id)`。读取回执只返回真实状态和工具观察，不恢复运行，不返回隐藏上下文。

## 数据与接口

仍使用本地 SQLite；便笺当前行与历史快照在 `notes.db` 同一事务保存，事项选择复用 `threads.db`。没有增加图数据库或额外模型服务。

| 接口 | 行为 |
|---|---|
| `GET /api/activity` | 所选对象元数据、下一步、摘要及 `object_refs`；不读便笺正文 |
| `GET /api/notes/selection` | 关联版本、当前版本、选择修订、稳定活动 ID、missing/stale 状态 |
| `POST /api/notes/selection` | 精确字段 `{note_id, version, expected_revision}`；用两个 null 取消关联；冲突 409 |
| `GET /api/notes/{id}?version=N` | 读取准确保存版；省略 version 才读取当前版 |
| `GET /api/notes/{id}/history` | 最近 50 版元数据；更旧版本仍可按版本号读取 |

`ObjectRef` 统一为 `{type, id, version}`，便笺 version 是保存版本，事项 version 是事项修订。读取接口设置 `Cache-Control: no-store`。写入沿用同源检查。

## 资料边界与生命周期

自动资料正文最多 4000 字符，显式 `note.read` 最多 6000 字符，提供截断标记；标题、来源、下一步和正文均过滤凭据模式。公开工具结构还限制嵌套、字段和列表，并按紧凑 JSON 总字符上限 8000 裁剪，查询/事项/回执结果标记可能裁剪。这些是局部边界，整轮上下文的统一预算仍未完成。

普通闲聊、引用、假设、否定及对笔记软件的讨论不自动读取正文。关闭记忆时，生成链路与只读工具不读取活动资料；用户主动打开笔记页的 CRUD/只读 API 仍可使用。资料标签不构成模型外权限校验，也不证明真实模型会完全遵守；写工具继续要求参数绑定的明确确认。

旧数据库只补存已有当前版，无法重建之前未保存的原文。删除便笺同时删除全部版本，原关联在同一事务清除；不删除此前已经创建的任务。取消关联只解除选择，保留笔记。版本默认保留到便笺删除；SQLite 逻辑删除仍不等于安全擦除或备份清理。

这是单个本地共享工作面：选择在同一数据库的窗口间共享，并非每个聊天独立或多用户隔离。稳定活动 ID 在换选、清除、删除后继续保留，它是工作面身份，不表示每次换工作都创建了新活动时间线。两库只读组合不是跨库原子快照。

刷新和重连会建立新对话 session；恢复的是显式所选对象，未将断开的澄清、确认或执行重新绑定到新连接。随后已实现聊天中的原稿修改候选、差异审阅、确认保存与原共同事项的精确版本成果回执，见[修改建议实施记录](NOTE_REVISION_PROPOSALS.md)。候选卡保留独立审阅，不自动覆写笔记编辑器草稿。播放完成 ACK 和完整三日真实设备验收尚未完成。

## 隔离验证

验证从真实保存和明确选择开始，经过服务重构、新连接、实际路由、普通聊天提示与有声交付；不直接把最终答案塞进记忆库。浏览器 fixture 检查页面状态；另有真实路由与临时数据库的接口测试。供应商、麦克风和真实扬声器表现不在这些结果范围内。

最终 Python 回归集合 **293 项通过**，其中本轮的版本/活动/提示接入/跨连接声音用例共 **48 项**。还覆盖既有上下文、澄清确认、共同事项、语音轮次和台词动作。浏览器 **12 组完整网络 fixture 检查**、**3 组真实页面→真实 FastAPI 路由→临时 SQLite 场景**通过；原助手确认浏览器 7 组回归通过。协议、相关 Python/JavaScript 语法与空白检查通过。

运行中也固定了首次行动的事项绑定：活动资料和执行回执复用同一个已捕获的事项 ID，另页恰在读取时切换选择，不会把两者分派到不同事项。

原稿修改建议现已落地：引用固定 base 版本，用户确认后保存新版本；原稿冲突保留编辑草稿并要求基于新版重新生成。保存不会自动改变对话关联，用户另行明确关联新版后，“接着上次”才能继续到这个新成果。
