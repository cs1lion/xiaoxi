# 有原话依据的偏好并存与时间限定

2026-10-13。继续项目 A 阶段，处理首轮真实抽取发现的具体反例：用户“长期最喜欢喝绿茶”，随后“最近红茶也挺喜欢，还没决定改习惯”。原模型公开输出没有声称红茶取代绿茶，旧管理器却因相同属性把红茶排除为冲突。本轮修改程序，未追加付费模型调用、读取真实用户库或重启生产。

## 现在的行为

| 用户原话 | 程序处理 |
| --- | --- |
| 长期最喜欢绿茶；最近也喜欢红茶 | 两条都保留为当前记录，分别带最喜欢/喜欢、长期/最近及原话日期 |
| 喜欢绿茶；也喜欢红茶 | 同一属性下的独立普通喜好可并存 |
| 最喜欢绿茶；最喜欢红茶，没有明确替换 | 新最爱待核对，不覆盖旧值；并列最爱暂未支持 |
| 现在最喜欢喝的茶改为红茶 | 受支持的明确变化可退役旧最爱；其他普通喜好继续保留 |
| 现在不再喜欢绿茶 | 退役该对象的旧正向偏好，保留其他对象，新增带原话时间限定的否定偏好 |
| 修改或忘掉其中一条 | 只操作该成员的版本链，其他并存成员保留；显式按 key 忘记仍删除整个属性 |

规则只在有限中文句型中生效。未知句型、多个对象无法分别归属、来源弱或旧记录语义不明时，保留原有保守路径。模型声明和随机 key 不能授予新的集合写入权限。

## 证据与身份

key 保持稳定属性，例如 `饮食:饮品偏好`，不加入绿茶、最近或随机后缀。`identity_slot` 由程序按原话对象与时间范围生成，用于区分成员；程度不进入身份，同对象同范围改变程度仍要核对。界面不展示内部 slot。

仅带有效已保存 user 原话的 `stated fact` 可获得 `preference_target`、`preference_level`（like/favorite/dislike）、`preference_scope`（long_term/recent/current/unspecified）。完整分句、对象、否定、程度和时间同时核对；裁掉“最”“不”“最近”不能取得并存权限。抽取器、管理器和最终写事务共享验证规则；显式结构非法时整条拒绝，模型时间、状态和版本编号不作为权限。明确变化还检查完整消息中的未定或否定限定，不能裁去“没决定”后自动更新。

集合权限只开放八个固定属性：`饮食:饮品偏好`、`饮食:食物偏好`、`饮食:偏好`、`游戏:偏好`、`影视:偏好`、`音乐:偏好`、`运动:偏好`、`兴趣:偏好`。属性别名和对象同义词未普遍归一；宽泛属性仍可能把不同子领域的最爱保守地判成冲突。

## 时间、退役与人工维护

`preference_as_of` 来自已保存消息时间，模型不能填写。最近/现在只是当时自述的标签，检索上下文与面板显示日期及“未确认延续至今，未设定过期日”；不猜七天或三十天期限。长期自述也不证明以后永久不变。

检索仍按相关性排序，**没有实现完整时间范围过滤**。“最近喜欢的茶”可能同时找出绿茶和红茶，模型应参考各自限定；本轮也未测试生成回答是否正确使用这些限定。

明确变化在写事务记录 `retired_by_message_id`。替换后的新最爱后来又被否定，迟到的旧最爱也不能复活；同对象跨范围的旧相反偏好受相同保护。另一连接和重开后仍有效，独立对象的早到普通喜好不受整个属性统一水位误拒。消息 ID 表示保存顺序，不能证明同一消息中分句的真实时间先后。

手动纠正保留选中成员的内部 slot，产生手动版本，清除旧结构化对象、程度、范围、时间及原话关联；同值或仅空白变化的 PATCH 也执行清理。忘记成员删除其完整版本链并清理版本引用；原始聊天日志仍存在，持久维护水位阻止旧消息重新抽取。

SQLite schema 增量升级至 v3；旧 v0/v1/v2 行保留原 ID、内容、证据、使用计数、历史及维护水位，新增字段为空，不猜旧偏好。迁移失败回滚，拒绝打开更高版本库。本轮仅在合成临时副本验证，真实库尚未应用。
