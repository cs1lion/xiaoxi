# ADR: 世界变活（时辰、神谕石板、有来源的摆件）

- **状态**：已批准（用户，2026-10-21）。切片 0、1a、1b、1c 已落地，1d 起待开工。
- **日期**：2026-10-21
- **决策范围**：`pixel-world/` 的渲染层、世界层、存档 schema；不改主产品 `server/`，不改 `web/`，不新增 WS 事件
- **上游**：用户 2026-10-21 拍板「形态 B（神谕小镇）」与「角色 = 手，不是 Agent」
- **依据**：本 ADR 附带的原型 `pixel-world/proto/day-phase.html` 与本轮实测数据

## 一句话

三个切片让世界第一次同时具备「自己的时间」「记得你说过什么」「你伸手能改变它」，且不引入货币、不引入惩罚、不伪造任何台账状态。

## 背景

世界现在有三样已经成立的东西：黄昏、雨、夜三种视觉态（`night.ts` 纯渲染态）；一套不撒谎的台账投影（`projection.ts` 单向映射，`determinate: false`）；一套不惩罚的日常作息（`routines.ts` 纯函数，不因你缺席而退化）。

缺的是闭环。用户的原话是「你不是在经营一座镇子，你是在被一座镇子记住」。要兑现这句话，需要三件事：世界有自己的时间、世界记得神谕、世界会因为你做的事改变。

## 决策

### 1. 形态选 B，保留 A 的入口

世界既是 Agent 的可视化投影，也能离线独自玩。两种模式代码已支持（`?ledger=on` / `?ledger=off`），本 ADR 不新增模式，只把「神谕、回响、记忆」补成完整循环。

不选 A：游戏性只做氛围，兑现不了「被记住」。
不选 C：种田、货币、升级会长出最优解与每日打卡，与「不惩罚」「不经营」两条底线冲突。

### 2. 时辰只改光，不改作息

**这是本 ADR 最重要的边界。**

四刻（晨雾、正午、黄昏、夜）由真实本地时间推动，但**只作用于渲染层**。`Simulation` 不读墙钟，不新增时段字段，不改行为。原因有三条：

1. `Simulation` 的契约是固定步长、无内部时钟、可确定性回放（`README.md` §三条硬约束）。把 `Date.now()` 喂进逻辑层，测试就得注入假时钟，回放就不再成立。
2. 用户的提案里有一条「夜里关铺子拒绝派活」是要避免的。光变而活照干，这条自然成立，不需要专门写规则。
3. 时辰一旦进存档，就要回答「世界内时钟怎么保存、怎么回放、跨天怎么算」，那是独立的时钟语义，不是一个切片的量。

神谕「天亮/天黑」是**视图覆盖**，刷新即回真实时间，不落盘。

#### 四刻配方

配方只动三样东西：压暗浓度与颜色、亮光强度、内容态（亮窗数量、萤火）。色仍是 24 色，不新增第 25 色。

| 刻 | 压暗 | 压暗色 | 亮光 | 内容态 |
|---|---|---|---|---|
| 晨雾 | 0.16 | `cloakDark`（冷） | 0.25，贴地雾带 58px，雾浓度 0.38 | 无亮窗 |
| 正午 | 0 | 无 | 0 | 无亮窗 |
| 黄昏 | 0.08 | `ink`（暖墨） | 1.20，屋脊受光 0.55 | 两扇亮窗 |
| 夜 | 0.46 | `deepShade`（冷） | 1.00 | 两扇亮窗，萤火 |

#### 实测：为什么不是「只改压暗浓度」

最初的方案是「一天四刻 = 三档压暗浓度」。原型量出来的结果是：

| 对比 | luma 差 | 变化像素占比 |
|---|---:|---:|
| 晨 / 午 | 5.66 | 14.4% |
| **晨 / 昏** | **3.43** | **1.3%** |
| 晨 / 夜 | 2.39 | 0.9% |

晨与昏在数值上几乎重合，屏幕上分不出来。改成「压暗色不同」后，晨与午反而只差 2.07。最终采用「冷压暗 + 暖亮光 + 内容态」三件一起变，量到：

| 对比 | luma 差 | 变化像素占比 | 建筑区变化占比 |
|---|---:|---:|---:|
| 晨 / 午 | 7.25 | 20.0% | 8.1% |
| 晨 / 昏 | 9.28 | 19.1% | 4.0% |
| 午 / 昏 | 4.9 | 2.3% | 5.0% |
| 昏 / 夜 | 8.44 | 18.4% | 37.2% |

午与昏的全屏差异只有 2.3%，因为差异集中在建筑区（屋脊受光、窗灯、檐口），草地几乎不变。这一对靠**色温**区分（均值色偏移 3.5 对 5.3），不靠亮度。验收时不能只看 luma。

#### 验收阈值

- 任意两刻的建筑区变化像素占比 ≥ 3%。
- 四刻平均 luma 严格递减：晨 > 午 > 昏 > 夜。实测 62.84 / 58.68 / 56.12 / 47.98。
- `audit-palette --strict` 仍是世界 24 色，退出码 0。
- 夜雨时萤火隐藏（现有行为，`night.ts` `drawFireflies`）。

### 3. 神谕石板只存改变了世界的话

**不存全量日志。** 每句话都存就是没人读的日志，20 条之后全是噪音。

存的条件是「这句话导致世界发生了变化」，即派活成功、天气改变、撤销生效。认不出的输入（`unknown`）不存进石板，而是触发一次回问。回问要记住上下文（上一句说了什么），所以回问本身带一个 `question` 记录，但它不是世界事件。

石板形态：

- 每条记录原话、世界回执、逻辑时刻（`sim.now`）。
- 封顶 20 条，超出丢最旧。
- 只存独立项目自身产生的事件，不复制台账内容（台账是真相源，不复制）。

### 4. 摆件来源，这是「被记住」真正的落点

现在的信仰结算（`faith.ts`）每交付一单攒一点，三点落一个摆件，按固定循环 lamp → tree → banner。缺口有两条：

1. 摆件跟任务类型无关，代码活和查资料落同一种东西。
2. 摆件不知道自己从哪来。

改法：

- `nextProp` 增加按 `TaskKind` 选型的映射表：code → 灯与齿轮（复用 `lamp`），research → 书与望远镜（复用 `tree` 的外观改绘），writing → 砚台与旗（复用 `banner`）。
- `WorldProp` 增加 `sourceTaskKind`、`sourceTaskId`、`sourceSummary`。纸面要能说「这盏灯是那单爬虫换来的」，而任务结算后就被删掉（`removeTask`），`settled` 只留 id，所以摘要必须在落摆件时抄一份。
- 纸面状态行能说「这盏灯是那单爬虫换来的」。玩家碰到摆件时看到的是具体来源，不是一个抽象计数。

不新增 `PropKind` 枚举值，避免改动 `PROP_KINDS` 常量与 `save-validate.test.ts` 里的逐项断言。外观差异靠 `sourceTaskKind` 驱动绘制分支。

**对原方案的修正**：原计划只加两个字段（kind + id），实际落不了地——id 指向的任务已经不在 `tasks` 里，纸面拿不到摘要。补 `sourceSummary` 是这一片唯一超出原 ADR 的字段。

### 5. 编年史从快照推导，不落档

沿用 `report.ts` 已经定下的先例（`README.md` 目录说明第 79 行：「神谕日报，从快照推导，不另存真相」）。编年史是 `settled` 与 `tasks` 的只读投影，不新增存档字段。

同理，门口石板的磨损从 `settled` 计数派生，雨后水洼与屋顶湿润是视图内衰减，都不落盘。能派生的一律不进存档，v2 只多两处：石板的问回记录、摆件的来源字段。

### 6. 三件神迹

`WorldCommand` 新增 `miracle` 动作，走同一条 `enqueue` 队列，有回执、有测试、可存读档：

- 点灯：指定一盏已有的灯或一扇窗，亮起来。
- 种树：在网格合法位置落一棵树。
- 召唤猫：生成一个只做氛围的环境实体，不参与任务。

种树要与信仰摆件去重：同一格不能同时被神迹与里程碑占用。不做冷却，不做货币，因为那会把神迹变成资源管理。

### 7. 角色是手，不是 Agent

用户 2026-10-21 拍板。这是本 ADR 的既有事实确认，不是新机制：

- 角色与世界之间没有「Agent 身份」绑定，`assignFromLedgerTo` 是「谁闲谁接」。
- 台账的 `agentName` 只做展示，不参与派活。
- 世界记住的是「你和这座镇子的事」，不是某个 Agent 的事。
- 「Agent 记得」属于主产品 `server/memory/`，需要另开 ADR 并动主库，本 ADR 不做。

### 8. 存档升 v2，先做空壳

石板与摆件来源都要落盘，而 `save.ts` 的 v1 是 99 条叶子路径加指纹常量冻结的。加字段必然让 `save-fingerprint.test.ts` 失败。所以：

1. **切片 0 单独一个 PR，只升版本、写迁移、补 v2 样例与新指纹，不带任何功能。** 已有 v1 档必须能迁移。
2. 迁移函数骨架已经在 `save.ts:731` 躺着（`MIGRATIONS[1]` 是一条从未跑过的 1→2 样例迁移，因为 `CURRENT_SCHEMA_VERSION` 一直是 1）。

v2 新增的叶子路径共七条，样例从 99 条涨到 106 条：

```
world.props[].sourceTaskKind
world.props[].sourceTaskId
world.props[].sourceSummary
world.oracle[]
world.oracle[].at
world.oracle[].raw
world.oracle[].receipt
```

（`world.oracle[]` 是数组容器本身，也单独计一条。`sourceSummary` 是切片 1b 补上的，见 §4 的修正说明。）

## 非目标

- 种田、货币、维护、每日打卡。
- 夜里关铺子、拒绝派活。
- 假造 7 个 Agent，或伪造工具故障（`shouldOverheat()` 仍恒为 `false`）。
- 让 LLM 生成像素或自由生成地图。
- 造物模式（暂停、幽灵预览、网格校验）与章节法则：放到第二阶段，那时才有「章」的时钟定义。
- 把时辰写入存档或让时辰驱动作息。

## 为什么先「世界变活」

1. **造物主的计量单位是「章」，而章没有时钟就不成立。** 先做造物主，等于在没有时间轴的情况下发明章节。
2. **没有记忆，造物不可读。** 新长出的楼如果没有任何东西指向它，玩家只会觉得场景变复杂了。
3. **成本差一个量级。** 四刻主要是光照配方加一次 schema 升级；造物模式要暂停、幽灵预览、网格校验、LLM JSON 校验、每章限一次。

## 风险

| 风险 | 处置 |
|---|---|
| 时辰进逻辑层 | 本 ADR 明确禁止；四刻只在 `src/render/` |
| 存档 v2 迁移写坏老档 | 切片 0 独立 PR；迁移失败即拒绝加载；已有坏档拒绝路径不变 |
| 晨雾洗灰画面 | 原型实测：全屏渐变雾把草地洗成一片灰，改为贴地 58px 窄带 |
| 午昏难分 | 实测全屏仅差 2.3%，靠色温与建筑区差异验收，不靠 luma |
| 摆件与神迹抢格 | 落点校验统一走 `grid.isWalkable`，落前查占用 |

## 附录 C：本轮核对到的事实

写 ADR 前逐条核对了提案里引用的代码位置，以下五处与提案不符，已按代码修正：

1. 「苔灯」全仓零命中，只有 W21 `moss` 色。ADR 不使用这个名字。
2. 摆件不是随机，是 `faith.ts:14` 的固定循环 lamp → tree → banner。
