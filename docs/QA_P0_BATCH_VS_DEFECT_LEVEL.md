# QA 复验结果补充：P0 批次优先级 vs 缺陷等级

> 追加于 2026-10-20，由 Chief 拍板。**不改动 §6 的 P0–P3 定义**，本节只补充两者的区分。

## 1. 两个不同的轴

本项目同时使用两套编号，**它们不是一回事**，混用会导致判定冲突：

| 轴 | 记号 | 含义 | 谁定 |
|---|---|---|---|
| **修复批次** | P0-1、P0-2、P0-3、P0-4、P1-1… | 这一轮**先动哪块代码**，看的是性价比、依赖顺序、改动风险 | Chief |
| **缺陷等级** | P0 / P1 / P2 / P3 | 这个问题的**严重程度**，判据见 §6 | QA |

**关键点**：批次号里的 "P0" 不代表该缺陷是 P0 级。按 §6 的判据，视觉类问题最高到 P1；「通铺网格线」「地形零过渡」等实际是 **P2（局部美术不一致 / 影响可读性）**。

把它们排进第一批，是因为**改动小、见效快、可独立回滚**，不是因为它们严重到 P0。

**S-L544（overlay 400% 亚像素越界）** 按 §6 应判 **P2**（一般回归 / 可定位修复），不是 P0——它不影响功能可用性，但会让断言红。

## 3. 对复验的要求

复验报告里请**同时标注两个轴**，例如：

> P0-1（批次）· 删通铺网格线 · 缺陷等级 P2 · 复验结论：通过

这样既不影响批次推进，也不混淆严重度。
