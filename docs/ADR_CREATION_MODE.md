# ADR: 造物模式（第二阶段）

- **状态**：提案，待用户批准
- **日期**：2026-10-22
- **决策范围**：`pixel-world/` 的世界层与场景输入层；不改主产品，不改渲染管线的绘制方式
- **上游**：`docs/ADR_WORLD_ALIVE.md`（第一阶段已完成：切片 0、1a、1b、1c、1d）
- **一句话**：把「点一下按钮长出一栋楼」换成「选位置、看预览、确认施工」，并让 LLM 只做选择题而不是画图。

## 背景

第一阶段的五个切片已经落地。世界现在有：自己的时间（四刻）、记得你说过的话（石板）、会因为你做的事改变（有来源的摆件）、以及三件神迹。

造物现在只有一个入口：`build(prefabId)` 直接调 `findBestSlot` 挑一处最靠近祭坛的空地，施工 3.2 秒。这条路径全部是「系统替你决定」。ADR_WORLD_ALIVE §6 把造物模式留到了第二阶段，理由是需要先有「时间」与「记忆」作为地基——现在两者都在了。

## 现状核对（写方案前查过代码）

| 事实 | 位置 |
|---|---|
| 落位只有一个入口，位置由 `findBestSlot` 选，调用方不能指定 | `setup.ts:82` |
| 蓝图注册表有 4 个 prefab，其中 `workshop_plot` 不接活、只占地方 | `src/world/prefabs.json` |
| 施工时长 3200ms，施工期间该楼不接活 | `simulation.ts` `CONSTRUCTION_MS` |
| 同一 prefab 不能建第二栋 | `build()` 里的重复检查 |
| 场景目前**没有任何指针输入**，只有键盘 `N` 与 DOM 表单 | `SandboxScene.ts` |
| `findBestSlot` 已经是纯函数，入参是蓝图与锚点 | `grid.ts:134` |

**最关键的一条**：`placeBlueprint` 把「选位置」和「建楼」焊在一起了。造物模式要求玩家指定位置，所以必须先拆开：校验归校验，落位归落位。

## 决策

### 1. 拆开「选位置」与「建楼」

新增一个只读校验入口，返回某处能不能放、不能放的原因：

```
checkPlacement(prefab, origin) →
  | { ok: true }
  | { ok: false; reason: 'outOfZone' | 'occupied' | 'margin' | 'doorBlocked' | 'edge' }
```

`placeBlueprint` 增加可选的 `origin` 参数：给了就用玩家的位置（先过校验），没给就走原来的 `findBestSlot`。这样旧调用点零改动，新路径显式。

这是本 ADR 唯一触及既有签名的改动，必须保持向后兼容。

### 2. 造物模式是一次显式会话，不是常驻状态

进入造物模式 → 选蓝图 → 移动幽灵 → 确认或取消 → 退出。**不引入新的世界状态**：模式只存在于场景层（`SandboxScene`），`Simulation` 完全不知道有这回事。

理由：世界层只管确定性回放。把「玩家正在拖一个幽灵」写进世界状态，会让存档 schema 多出一堆只在交互中存在、回放时毫无意义的字段。

暂停也只在场景层：进入造物模式时停止推进 `sim.update`，退出时恢复。**不新增命令**。

### 3. 幽灵预览只用现有 24 色与 alpha

幽灵画成蓝图轮廓：合法位置用 `trim` 描边，非法位置用 `ember`（故障色）描边。填充用 `ink` 低 alpha。

沿用 `ART_SPEC §2.4` 的 alpha 纪律：这里属于「压暗」类用法，不新增第 25 色。

### 4. 网格校验复用既有规则，不另写一套

幽灵每一步都调 `checkPlacement`，规则与 `findBestSlot` 内部完全一致：分区、占地、留白、门口可通行。**不允许出现两套判定**——那样玩家看到合法、真建时却被拒。

### 5. LLM 只做选择题

ADR_WORLD_ALIVE 已定的边界继续保持：模型输出 `{ prefab_id, placement, palette }` 这样的 JSON，不生成像素、不生成地图。

本 ADR 的切片 2 只做**玩家手动**的造物模式。LLM 选择层单独排到切片 3，因为它需要：模板注册表的版本化、JSON 校验器、缓存、失败回退，以及「什么时候触发」的产品判断——那是另一片的工作量。

### 6. 「每章限一次」先不做

ADR_WORLD_ALIVE 提过「每个章节只允许一次」。但**「章」到现在还没有定义**：四刻是时钟，不是章节；石板是流水，不是章节。

没有章节定义就实现「每章一次」，等于发明一个没有依据的计数器。所以本 ADR **不实现章节限制**，只保留现有的一条硬约束：同一种 prefab 不能建第二栋（`build()` 里已有）。

等哪天定义了「章」（例如按真实日期切分，或按交付里程碑切分），再单独决定它约束什么。

## 非目标

- LLM 生成造物（切片 3）。
- 章节与里程碑法则。
- 撤销已建的楼（世界只增不减，与摆件口径一致）。
- 自由绘制地形、移动已有建筑。
- 造物消耗任何资源。没有货币，也不引入。

## 落地顺序

| 切片 | 内容 | 验收 |
|---|---|---|
| 2a | 拆出 `checkPlacement`，`placeBlueprint` 接受指定位置 | **已落地**：11 项单测，五种理由各可达；旧调用点行为不变 |
| 2b | 造物模式会话：进入、选蓝图、幽灵预览、确认、取消 | 真机：拖到非法处被拒且理由正确；取消后世界无变化 |
| 2c | 键盘与指针输入 | 真机：鼠标移动幽灵、Enter 确认、Esc 取消 |

2a 是纯逻辑，可离线测；2b/2c 必须有真机证据。

## 风险

| 风险 | 处置 |
|---|---|
| 两套判定不一致 | 幽灵与真实落位都调 `checkPlacement`，测试同时覆盖两条路径 |
| 造物模式漏掉退出导致世界冻结 | Esc、取消、确认、切标签页四条路径都要恢复推进；冒烟测试覆盖 |
| 幽灵盖住角色导致看不清 | 幽灵用轮廓不用实心；深度压在建筑层之上、UI 之下 |
| 旧调用点被新参数破坏 | `origin` 可选；2a 的测试必须跑一遍既有 `build()` 全路径 |

## 附录 A：与第一阶段的衔接

造物模式落下的楼，与既有 `build()` 走完全相同的施工与接活逻辑（`CONSTRUCTION_MS`、施工期不接活、铺路）。唯一的差别是位置由玩家给定。

摆件、石板、神迹都不受造物模式影响：它们走各自已有的命令，不新增交互。
