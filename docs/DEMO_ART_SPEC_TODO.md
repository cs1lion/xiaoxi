- **建议规格**：先按 D1 裁决定“资产帧尺寸”（建议 16×24 或 24×32）；脚底中心 pivot (w/2, h)，逻辑占 1 格；建筑原点左上、baseY=底边；可排序物一律 depth=baseY，天气/UI 固定 8000+；影子固定 16×6/alpha 0.35；伞/气泡等挂件定义包围盒上限（不得高于两格）。

#### B4 角色动画槽（idle/walk/work/report/shelter/watch）
- **现状证据**：逻辑模式 7 种（`types.ts:74-82`、`simulation.ts:545-587`），但渲染**没有任何帧动画**：身体由静态矩形一次性画出（`villager.ts:92-129`），只有行礼 -2px、交付 -1px 的位移（`:68-70`）；进入 `working` 时 `visible=false`（`simulation.ts:680`），所谓“工作动画”实际是“人消失、铺子冒烟”；没有 `watch`（神谕落地全场抬头 1.5s）和 `report`（铺子汇报）槽；设计文档要求“2 帧呼吸待机、跑步 6 帧、Aseprite tag 导出、待机 4–6fps/跑步 10–12fps”（`source/01…:211-221`）。
- **缺什么**：槽位表（槽名/触发/帧数/fps/循环/可中断点）、素材、walk 步态、work 循环、report 收势、shelter 撑伞姿态、watch 抬头；以及“人进屋后工作动画归谁”的规则。
- **建议规格**：ART_SPEC 先给最小集：`idle` 2 帧 4fps 呼吸；`walk` 4 帧 10fps + 1px 弹跳；`work` 3 帧 6fps（画在铺子门口/窗口剪影，因为人不可见）；`report` 2 帧 8fps；`shelter` 2 帧（含伞）；`watch` 1 帧抬头 1.5s；动画时钟独立于 10Hz 逻辑，用状态进入时间做相位。
- **验收方式**：固定 seed 录屏逐帧抽样；6 个槽都能在 1 秒内被指出；中断（行礼/下雨）不打断帧序到崩。

#### B5 建筑与装饰规格

- **缺什么**：分层规范（即使代码绘制也按层拆）、材质像素簇方向、门窗/出檐/烟囱尺寸、招牌规则、施工阶段视觉、装饰密度上限、建筑与地面的接触阴影。
- **建议规格**：四层（地基 2px、主体、屋顶出檐 3px、前景遮挡）；窗 8×6、门 10×14、烟囱 7×10；每区可交互物 ≤8（架构预算）；`clearMargin=1` 固化；招牌不进 canvas（见 B9），改用 DOM 标签或图标；施工三阶段（0–33% 骨架/33–66% 封顶/66–100% 亮灯）。
- **验收方式**：400% 截图查接缝/遮挡；纯黑剪影 0.5s 能分出三栋；施工三阶段截图各一张。

#### B6 天气与伪光照
- **现状证据**：雨 140 滴、splash 18、压暗 `0x0a1420` alpha≤0.28（`weather.ts:6-9,38-68`）；淡入 1.8s、45s 自动退场（`world/weather.ts:17-18`）；雨幕/压暗层 depth 8000–8002，盖在所有世界标签之上（`weather.ts:18-26`）；无昼夜、无窗光/灯光的时段语义（`README.md:103`）；`05-build.png` 里天气已切晴，但气泡仍写着“下雨了，快躲！”、作息标签仍是“在屋檐下看雨”，说明切晴后残留的旧雨状态没有被立刻清掉（气泡 2.2s、作息标签 2.5s 的生命周期），现场会被读成“世界还在下雨却报晴”；角色轮廓在夜里/雨里也没有额外描边保护。
- **缺什么**：天气等级与阈值、压暗上限与对比度底线、雨的层次/视差、水洼/屋檐滴水是否做、伪光照规则（全屏 multiply 第一层、窗光）、天气与 DOM 状态同步、覆盖层不压文字。
- **建议规格**：定义 rain 0/0.5/1 三档及进入/退出阈值；压暗 ≤0.28 且“主角轮廓与背景亮度差 ≥ 可测阈值”；雨幕分近/中两层（不同速度）但不增加颜色数；窗光只做静态 alpha；明确“完整 Light2D/昼夜进 1.0 之后”（`PROJECT_BRIEF.md:36` 已把完整 Light2D 列为暂不包含）；`kind` 与 `intensity` 的展示文案要一致（避免“晴+旧雨文案/旧雨视觉”）。
- **验收方式**：`04-rain.png` 与晴天的同机位对比，主角仍能在 1 秒内指出；状态行与画面天气一致；亮度差/对比度有读数。

#### B7 DOM 纸面 UI 排版与中文字号
- **现状证据**：`index.html:7-118` 自建深色主题；实测字号 body 13 / 状态 12 / 回执 12 / 输入 13 / 报头 13 / 日期 11 / 标题 17 / 正文 13 / 页脚 11（`12-metrics.json`）；字体 `ui-monospace`（页）与 `"Noto Serif SC", "Songti SC", serif`（纸）；纸面宽 720（`index.html:85`）、画布 960、状态/面板 720；纸面最多 3 行（`report.ts:15`），且“天气+她现在做什么”这一行会被其它行挤掉（`report.ts:22-57`）；390px 下横向溢出到 677（`10-mobile-390.png`）；日期是“第 X 分 YY 秒”不是日期；`08-paper.png` 显示标题与 2 条正文，留白充足但没有网格/九宫格纸面质感。

- **建议规格**：中文 DOM 最小 12px（正文 13、次要 12、标题 17、报头 13）；纸面标题 + ≤3 条正文，超长省略但可展开；日期用真实日期或“第 N 日”（需决策）；宽度统一 960 或明确“画布 960 / 面板 720”的双列理由；390 断点降到 1x 或给横向滚动提示；对比度按 `docs/UI_VISUAL_AUDIT.md:38-44` 的方法测到 ≥4.5。
- **验收方式**：DOM 计算样式断言（字号/宽度）；390 无横向溢出；`08-paper.png` 与 ART_SPEC 排版表逐项对照；对比度读数入档。

#### B8 动画帧率（12fps）与逻辑 10Hz
- **现状证据**：逻辑固定 10Hz（`SandboxScene.ts:31,165-179`），渲染 rAF 每帧重读快照；快照位置只在 10Hz 逻辑拍更新，**没有插值**，所以走路实际是 100ms 一格的台阶（3 格/秒 → 每拍 4.8px）；所有动效每帧重画，脉冲用 `sin(scene.time.now/240)`、`/120`（`buildings.ts:158,167`），粒子每 3 拍发射（`SandboxScene.ts:268-271`）；**没有任何 12fps 采样**。而架构笔记写“逻辑 10Hz、动画 12fps、渲染跟着屏幕”（`ARCHITECTURE.md:59,66`），设计文档写“待机 4–6fps、跑步 10–12fps”（`source/01…:219`）。
- **缺什么**：12fps 的语义（是角色帧动画采样率，还是渲染限帧？）、实现方式（动画累加器/Phaser `fps.limit`）、10Hz 逻辑与渲染之间的插值策略、性能预算。
- **建议规格**：明确“逻辑 10Hz / 动画帧采样 12fps / 渲染 60fps”三层；角色与环境帧动画用 12fps 累加器；位置在两次逻辑拍之间做线性插值（或把逻辑提到 30Hz，需决策）；性能预算引用“10 小人 + 20 发射器 + 50 建筑、原生分辨率 60fps”（`source/01…:629`）。
- **验收方式**：录屏逐帧看走路是否 100ms 跳格；DevTools Performance 记录帧时间；帧动画采样率可数（1 秒 12 帧）。

#### B9 可读性红线：中文不进 canvas
- **现状证据**：明确违反 6 处——角色名/气泡 `scene.add.text`（`villager.ts:32-46`，气泡内容来自 `simulation.ts:409,426,475,602,746` 等中文串）、建筑招牌（`buildings.ts:75-80`）、祭坛“神谕祭坛”（`SandboxScene.ts:155-162`）、施工“施工中 x%”（`:345-351`）、摆件“路灯/一棵小树/一面旗”（`decor.ts:101-108` + `faith.ts:15-17`）；字号 9/10/11px，均低于 README 自己写的“像素中文低于 12px 不可读”（`README.md:79`）。证据图：`04-rain.png`、`05-build.png`、`06-faith.png` 的“路灯+神谕祭坛”叠字；`13-canvas-400pct.png`、`15-altar-zoom.png` 的 10px 中文被 2 倍放大后糊成笔画团。DOM 侧的状态行/回执/纸面是正确的（`oracle-panel.ts`）。
- **缺什么**：修复方案（DOM overlay 跟随世界坐标 vs 彻底去掉世界内中文）、世界内 UI 的像素字体/图标方案（中文没有现成像素字体，只能 DOM）、实施优先级。
- **建议规格**：canvas 内**零中文**；世界标签改为 DOM 绝对定位 overlay（`pointer-events:none`，随快照投影，字号 ≥12px，带描边/底板保证对比度）；或者首版直接删除所有 canvas 文本，只保留剪影/图标 + DOM 状态行。无论选哪条，必须补一条自动检查：`src/render` 与 `SandboxScene` 不得把含 CJK 的字符串传入 `add.text`。
- **验收方式**：代码审计（无中文 text）；400% 截图无中文；DOM overlay 与实体位置误差 ≤2px；状态行完整可读。

#### B10 垂直切片验收标准
- **现状证据**：设计文档的 7 项验收（`source/01…:271`）：角色剪影可辨（✅ 三种剪影+深色斗篷）、2 帧呼吸待机（❌ 无帧动画）、工坊四层拆分+冒烟+窗光（⚠️ 冒烟✅/窗光静态✅/四层❌）、地面无接缝+像素簇方向一致（⚠️ 无接缝✅/像素簇方向❌，随机 1px 噪点 `tilemap.ts:36-53`）、气泡/进度条可读（⚠️ 气泡可读；台账活无进度条是有意的，`README.md:83`）、晴/雨全局色调（✅ 有压暗，但无昼夜）、3 秒内指出主角/路径/神谕状态（❓ 未验证）。此外 `canvas.toDataURL()` 在本实现下全黑（WebGL 未开 `preserveDrawingBuffer`，`11-canvas-native.png` 全 0），说明验收方法本身要写死。

- **建议规格**：ART_SPEC 附一张验收表：每项写“观察条件 / 截图文件名 / 通过条件 / 判定人”；拍摄方法固定为“浏览器元素截图（961×641）→ Pillow 最近邻 2x = 400%”；3 秒可读性用“给未看过的人看原生 480×320 静帧，问三个问题（主角/路径/神谕状态），3 秒内答对”做测试；只有验收表全绿才把 ART_SPEC 标为 V1（`source/01…:271`）。
