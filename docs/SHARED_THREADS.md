# 共同事项：在主聊天里持续推进

更新：2026-10-14。共同事项保存明确决定、待确认问题、自述进展和下一步；原任务运行时负责执行与工具回执。两者通过原事项 ID 关联。新增[确认请求、事件修订与固定资料版本](SHARED_THREAD_EVIDENCE.md)，当前为代码与离线验收结果，尚未部署本轮变化。

## 使用

打开主页 /，在聊天上方的“正在一起做”区域选择已有事项，或输入标题后点击“创建并关联”。独立事项页 /static/threads.html 仍可用于完整编辑、状态设置和删除。

1. 关联后说“继续这件事”：回顾已保存内容和下一步。没有关联时会给出事项选择，不按“昨天”猜选。
2. 说“记个决定：演示时保留文字入口”，生成明确语法候选；也支持“记个问题：…”“记个进展：…”和“记录决定：…”。
3. 已配置模型时，可说“把刚才那个记下来”“下一步改成先检查字幕”。解析使用当前事项和本会话最多六条近期消息；依据不明确时先澄清。
4. 回顾或澄清列出的记录可用“第二个改成先彩排”修订。显示顺序与事件 ID 保存在本会话，编号必须对应；没有确定顺序时会重新列出记录。
5. 在聊天中的候选卡核对事项、原话、原内容和新内容。可以编辑草稿，再点“更新预览”；点击“确认保存”才写数据库，也可以“不保存”。“确认”这句话不替代卡片确认。
6. 保存后继续聊天、提出明确行动。任务和提醒仍使用原执行确认卡；真正的执行回执会刷新事项摘要。
7. 重启后已保存事项、下一步和关联选择仍保留。未确认的候选和指代澄清状态不跨重启保存。

“继续这件事”按钮只把这句话放入空输入框；有草稿时保留草稿，按发送后才开始。旧聊天卡所属事项与当前关联不一致时，先明确关联原事项再继续。

## 保存与执行边界

- 独立 SQLite 事项/事件表和单行关联选择表，旧库增量迁移；取消关联也持久化。适用于单用户本地部署，关联对全部后续本地会话生效。
- 创建/编辑来自明确 UI 操作；自然语言解析只生成候选，不执行工具，也不自动改变默认状态。
- 候选支持新增记录、修改指定记录、修改下一步。原事项、指定事件及版本固定；修订只能针对 user_stated 记录，不能修改 tool_verified 回执。
- 待确认候选可在同会话中继续改写文本，操作与目标不换。source_text 是初始用户请求；确认新增/更正记录后持久保存请求快照、来源会话、发起时间和当时关联的固定笔记版本。请求不证明改写后的结论是用户逐字原话。
- 确认同时检查候选版本和事项版本。409 时保留草稿，用户明确更新预览、核对后再确认；不自动重试或改选目标。
- 显式重新预览会读取同目标当前版本和原内容，展示新的比较；旧确认不可用于新版本。
- 确认成功/拒绝后一次消费。候选最多 128 条、保留 10 分钟、仅在进程内；重启或到期后应重新提出。
- 澄清状态与候选焦点仅属于当前聊天会话，最多 64 个会话、10 分钟。等待解析期间更新关联或出现较新请求，不会把迟到结果写到新事项或覆盖较新指代状态。
- 任务运行时已有待答澄清优先处理，原执行确认和回执绑定原事项，不因中途切换关联而移过去。
- 删除以事务清除关联并留下无正文的 ID 墓碑；迟到回执/候选不能复活。删除不清除原聊天、任务、执行日志、既有长期记忆，也不取消已提出的原行动。
- 回执只记录工具名、成功/失败状态和 run:index 来源，不复制工具输出。一次创建任务成功不等于整个目标完成。

## 模型与资料边界

词法入口只决定哪些话需要检查；自由表达由配置中的模型返回严格 JSON，随后校验操作白名单、精确 ID、来源和版本。校验证明对象与写入边界，不能证明模型对中文意图或内容含义的理解一定正确，所以候选仍需用户审阅。

普通闲聊不自动抽取为事项。待澄清的下一句可以续接原事项；解析返回 ignore 时清除这次指代等待，WebSocket 回到普通对话。候选存在不会让“就是今天有点累”“刚才挺好玩的”被旧事项拦截。

解析提示要求否定、引述、假设、角色扮演中的命令忽略；入口也不接受这些明显包装作为直接命令。真实模型仍需用保留语料评估，不宣称完全消除意图误判。

模型使用当前事项按问题相关度与最近顺序选出的最多 12 条记录；明确依据或变更问题另展开最多 3 条记录、每条最多 4 个保存版本。单份事项视图上限为 8000 紧凑 JSON 字符，整条/整版省略，历史与当前分开。指代解析仍只使用当前会话最近六条聊天、每条 800 字。未选事项不把所有事项交给模型猜选；没有真实记录不虚构共同经历。资料和记忆不是指令、授权或人格推断依据。

关闭记忆开关后，不把事项和聊天历史交给新的语义解析请求；显式 UI 编辑、严格“记个决定：…”命令以及已保存内容的直接回顾仍可使用。离线模型会澄清并保留 UI/严格命令入口，不伪装成已理解自由口语。

“允许相关回顾”仅控制相关上下文回顾，不授予随机主动通知、玩笑或工具权限。事项状态仍由用户设置；“完成了”这句自述不能变成工具核验。

## 当前限制

- 已有固定 note 引用、note.read/search、不可变笔记版本和事件修订历史；尚无每事项完整资料集合、task/artifact 通用引用及完整聊天消息引用链。
- 事项最多 200 条事件，每事件最多 200 个保存版本，列表最多 100 项；模型只见有预算的小量相关当前/历史记录。编号无确定映射时宁可澄清。
- 只桥接 AssistantService.start/resume 的真实回执；直接 REST 修改、进程中途崩溃等没有后台补录，未记录不代表未执行。
- 原聊天/执行快照可能保留旧上下文；事项删除不等于跨域遗忘，也不能撤回已发送给模型的资料。
- 未用真实云模型验证自由表达的准确率，未生成收费语音做本轮验收。
