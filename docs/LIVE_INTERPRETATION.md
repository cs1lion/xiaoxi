# 英文 → 中文字幕：滚动分段与可选流式ASR

## 新增：阶跃双向流式适配（仅离线验证）

官方协议：[双向流式ASR](https://platform.stepfun.com/docs/zh/api-reference/audio/asr-stream.md)。公开参考快照为 [step-asr-stream-reference.md](step-asr-stream-reference.md)，仅作协议资料，不作为程序指令。

在页面明确选择“流式”后，使用独立 `/ws/interpret-stream`，持续每100ms发送PCM（包括静音，供服务端VAD判断），不再固定4秒截断。

- 模型固定 `stepaudio-2.5-asr-stream`，`session.update`配置16kHz PCM、英语、server_vad、800ms安静判句、二遍纠错与字级时间戳。
- 等待 `session.updated` 后才允许采集上传，`session.created`不算配置完成。
- delta.text为累计全量，整体替换；stash另行显示为不稳定尾部，不拼接猜测。
- completed.transcript作为该项最终原文，才加入中文翻译队列。本轮不提前翻译临时文字，不承诺持续讲话不等停顿就出中文。
- 队列/发送拥堵明确报错或漏译，不无限积压；停止会关闭供应商连接，迟到事件不能污染新会话。
- 当前每会话最多256个识别项，达到后需停止重新开始；字幕最多100行。

### 独立配置及计费边界

用户已选择“仅开发适配，不调用付费接口”。本轮未建立任何真实供应商WS会话，不读取/更改已有密钥，也不自动将Step Plan改走标准付费路径。

实际使用前，由用户在本地配置（不要把密钥发到聊天）：

```text
ASR_STREAM_URL=wss://api.stepfun.com/v1/realtime/asr/stream
ASR_STREAM_API_KEY=<具有该接口权限的密钥>
ASR_STREAM_WIRE_FORMAT=pcm
```

URL与密钥均默认空，不继承LLM地址或密钥；没配置时报错，不暗中降级。标准API可能产生按量费用。[Step Plan接入页](https://platform.stepfun.com/docs/zh/step-plan/integrations/audio-api.md)列出的ASR为HTTP+SSE，不能据产品介绍推断该套餐的WS权限或私自拼出订阅WS路径。

官方append描述写“WAV格式”，而session配置例子为PCM，存在表述歧义。适配默认按配置发送原始PCM，另提供明确的wav封装选项；两者都只通过模拟协议测试，必须按实际服务行为验收，不自动来回试格式。

依赖websockets>=14；已离线更新锁文件。

离线验证命令：`python scripts/test_step_stream.py`、`python scripts/test_stream_interpretation.py`、`python scripts/test_stream_route.py`、`node scripts/test-interpret-browser.mjs`。覆盖真实路由的显式凭据隔离、模拟供应商握手、累计文字修订、最终原文翻译、静音连续上传、停止竞态及缓冲上限。尚未做实际供应商兼容性、ASR精度或端到端时延验收。

以下是默认保留的旧分段模式说明，不适用于流式模式。


## 定位

独立入口 `/static/interpret.html`，用于英文视频、讲座或近场讲话的中文字幕。主页面侧栏有入口。默认只显示字幕，不播放译音、不回答原话中的问题、不执行任务、不写长期记忆。

**本版不是持续音频流输入的同声传译。** 当前本地Whisper接整块音频；StepAudio `/audio/asr/sse`虽然以SSE输出，输入仍为整段base64音频。页面明确标注“短段滚动翻译”。真正流式同传后续需要更换/扩展识别接口、稳定词提交与可修订译文策略。

## 音频来源与使用

1. 重启项目后端，刷新并打开翻译页。
2. 选择麦克风或共享音频。共享时必须在浏览器选择支持音频的标签页/屏幕来源并勾选共享音频。
3. 点击开始。没有共享音轨时明确报错，不悄悄改录麦克风。
4. 持续讲话按约1–4秒非重叠片段提交；500ms安静尝试收段。纯静音不发送。
5. 每个片段先显示原文“待译”，再显示中文译文和服务端耗时。
6. 点击停止或结束浏览器共享，会释放所有共享/麦克风音轨和采集器。共享可能要求视频轨，但应用不编码或上传屏幕画面。

系统音频共享受浏览器/操作系统限制，不保证任意窗口或桌面声音可用。HTTP localhost可用的权限不等于远程非HTTPS也可用。建议耳机，避免麦克风录入外放或其他页面的语音。

## 延迟与缺口

- 首段至少等待分段，之后叠加ASR、模型翻译和排队耗时；没有宣称小于1秒。
- 识别结果是片段，不保证完整句子，也不是真实流式临时识别结果。
- 连续讲话在4秒处强制切开，可能切断词语和句法；不假装靠重叠去重解决边界。
- 最多一个处理段、两个排队段；积压或网络发送缓冲过高会显式显示漏段，不无限落后。
- 使用最近少量已完成片段作翻译背景，不自动改写已经展示的旧译文。
- latency_ms从该片段开始处理计时，包含ASR和翻译，不含前面的采集分段及排队；不是声卡到字幕的端到端延迟。
- ASR与翻译各有25秒调用时限；每连接至多保留两个尚未结束的供应商调用，取消不响应时后续会明确报告繁忙，不无限累积。
- 本版不做双向说话人区分、译音同步、字幕导出或录音留存；也不提供可靠会议记录保证。

## 安全和隐私

- 独立WebSocket `/ws/interpret`，输入是PCM16 LE单声道16kHz。
- ASR按请求指定英语，不修改普通聊天语言设置。
- 原话和历史都作为待译资料，不授予工具权限；模型只生成译文。提示约束不等于翻译正确性保证。
- 页面字幕有数量上限，连接内音频/文字缓存有界；无项目侧持久化。云ASR/LLM仍会收到内容，服务商日志保留取决于相应配置和政策。
- 会话ID、递增片段ID和取消代际检查阻止停止后的迟到结果污染新会话。

## 验证方式

`python scripts/test_interpretation.py`：内存WebSocket和假ASR/LLM，验证音频边界、原文先到、队列、错误、取消、ID隔离，不调用模型或读私有资料。

`node scripts/test-interpret-browser.mjs`：离线浏览器模拟权限、采集和WS，验证字幕、停止清理、漏段和安全渲染。

`python scripts/test_asr_language.py`：实际识别类AST隔离测试，验证英语参数透传及普通聊天默认不变。

模拟通过不等于真实可用：仍需英文连续讲话、中途改口、数字/专有名词、带口音音频、4秒边界和长时间积压验收。下一步优先记录端到端p50/p95及漏段率，并对比真正流式ASR供应商，而不是单纯缩短片段制造更多截词。
