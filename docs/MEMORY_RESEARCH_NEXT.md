## 1. 当前实现与可复现基线

history 原始日志和普通 memory 在同一 SQLite 库的不同表中；相处偏好有独立存储与 broker。普通事实抽取、事实检索、偏好协调是三个不同能力，不能用一个“记住了”判断。

当前可利用的能力：

- 普通 memory 已有独立模型抽取、来源标签、版本关系、保守相关性门槛和注入预算。
- 偏好已有证据记录、activity/session/topic 范围、有效期、候选/冲突/修订和逐轮重新读取。
- 当前请求可以影响本轮策略，明确设置偏好是可信入口；自动归纳并升格长期偏好尚未开放。

已有 [PERSONALITY_MEMORY_RESEARCH.md](PERSONALITY_MEMORY_RESEARCH.md) 的“结构化 scope 尚未实现”是早期状态；当前应理解为：偏好存储与 broker 已支持 scope，自动识别场景/主题和普通事实 scope 仍不完整。

### 本轮隔离验证

导入应用模块前固定 `DB_PATH=:memory:`，关闭模型调用，用项目虚拟环境运行。记忆检索、偏好、broker、composer 共 48 项测试通过；核心 38 项检查通过。**86 项通过只说明原检查通过，不证明新增契约已经满足。**

诊断入口：[probe_memory_contract.py](../scripts/probe_memory_contract.py)。原始记录：[memory_contract_probe_20261013.json](../eval/research/memory_contract_probe_20261013.json)。8 个探针中两个控制例满足预期、六个拟定契约尚未满足：

| 探针 | 实际观察 | 研究含义 |
|---|---|---|
| 同批“在甲公司工作”+“岗位是设计师” | 只保留岗位 | 抽取后解析已丢掉独立事实 |
| 分轮写入相同两条信息 | 公司被标为 superseded | 同主题不等于同一个事实 |
| 明确喜欢某游戏，随后写入相反推测 | 明确记录失效，推测 active | 来源标签尚未形成更新权限 |
| 无任何消息证据的 stated 候选 | 校验接受并赋 confidence=0.95 | 需要可校验的证据契约 |
| 旧简短 + “详细解释并举例” | 策略仍 short，当前覆盖为空 | 含“举例”的整句被当成假设过滤 |
| “帮我写个批量重命名文件的脚本” | scene=chat，技术偏好排除 | 场景范围存对了，识别仍可能错 |

源码定位：

- [extractor.py](../server/memory/extractor.py)：`parse_extraction` 无原消息/证据输入；同批按主题删先前项。缺失 source 默认 stated，confidence 由标签直接映射。
- [manager.py](../server/memory/manager.py)：`_persist` 对 fact/self_state 按主题覆盖；没有完整 ADD/NOOP/UPDATE/CONFLICT 决策与来源保护。
- [store.py](../server/memory/store.py)：有 session、创建/更新时间和 supersedes；没有消息证据跨度、事实有效时间或 scope。写入消息不返回可供记忆引用的 ID。
- [composer.py](../server/dialogue/composer.py)：`preferences` 将包含“举例”的整句排除，误伤当前明确要求。
- [broker.py](../server/interaction/broker.py)：技术场景目前由少量关键词识别；普通编排没有可靠 topic 输入。

现有三轮真实模型记录的 current_override 均为 `length=short`、`current_overrides={}`，回复却展开了。应修正 [PERSONALIZATION_EVAL.md](PERSONALIZATION_EVAL.md) 的归因：这些样本证明模型按当前原始请求展开，不能证明 broker 成功覆盖旧偏好。生成、策略和后处理必须分别评分。

## 2. 阅读研究时要更新的认识

本轮直接核对论文摘要及官方仓库相关段落；不是截至今日所有最新论文的全面综述，也未复现论文排名。

| 一手资料 | 核对到的机制 | 本项目要验证的问题 |
|---|---|---|
| [Mem0 2025 论文](https://arxiv.org/abs/2504.19413) | 抽取、整合已有记忆、按需检索；研究图结构版本 | 语义比较能否减少重复，同时避免误更新独立事实？ |
| [Mem0 官方仓库，固定版本](https://github.com/mem0ai/mem0/blob/d26ba5e4518cef7fff3c66d4f715b21adf9feabe/README.md) | “New Memory Algorithm (April 2026)”声明 single-pass ADD-only、实体关联、多信号检索与时间推理 | 保留全部事实版本，在读取时选当前版本，是否比写入时更新更稳？ |
| [Zep](https://arxiv.org/abs/2501.13956) / [Graphiti 官方仓库](https://github.com/getzep/graphiti) | 带时间关系，记录事实变化和来源 | “现在在哪工作”与“去年在哪工作”能否分别答对？ |
| [A-MEM](https://arxiv.org/abs/2502.12110) | 含上下文、关键词、标签的记忆笔记；关联和表示更新 | “之前那个自动化练习”能否通过关联找回，同时不生成伪关联？ |
| [LongMemEval](https://arxiv.org/abs/2410.10813) / [作者仓库](https://github.com/xiaowu0162/LongMemEval) | 抽取、多会话、时间、更新、弃答；拆分 indexing/retrieval/reading | 怎样定位最终失败发生在哪一层？ |

Mem0 新算法是官方软件变更说明，不能当成 2025 论文结论。README 的分数属于作者报告，且注明来自含专有优化的 managed platform，不能当成 OSS 成绩；本轮没有复现。ADD-only 指自动抽取路径，当前软件仍有显式按 ID 的 update/delete，并非用户不能修改或删除。其“agent-generated facts are first-class”也不能直接迁移：陪伴角色编造的经历不是用户事实，真实工具结果则应带独立的 tool_verified 来源和明确验证范围。

因此，研究不应预先认定必须 UPDATE，或认定只追加天然更好。**保留原始证据**是共同要求；写入时维护当前状态与读取时解释变化，是可对照的工程选择。

## 3. 先定义可验证的数据契约

建议普通事实采用原始消息、候选声明、关系/决策、检索视图四层。仍可用 SQLite，无需先换向量数据库。

候选最小字段（设计提议，尚未实施）：

```json
{
  "kind": "fact",
  "subject": "user",
  "predicate": "learning_language",
  "value": "Python",
  "topic": "学习",
  "source": "explicit_user",
  "evidence": [{"message_id": "msg_101", "quote": "我最近在学 Python"}],
  "scope": {},
  "asserted_at": "消息时间",
  "recorded_at": "写入时间",
  "valid_from": null,
  "valid_until": null,
  "status": "candidate",
  "supersedes": null
}
```

topic 用于检索分类，不能充当事实唯一键。用户在甲公司工作、岗位是设计师分别是 employer 和 role；改学 Rust 只更新 learning_language，不应顺便丢掉 automation_goal。

程序先校验消息存在、角色、原文片段及用户归属，再处理主体、引用/假设、时间和范围。原文存在只是第一层校验，仍需检验候选含义是否由原文支持。不能让模型自己写的 explicit_user 或 confidence 代替这一判断。

明确区分 ADD、NOOP、UPDATE、CONFLICT。更新要求同一主体、属性、匹配范围及可信的变化依据；无法确定时保留冲突。推测不得自动使明确事实失效。偏好继续只产生 candidate，显式确认或管理面板设置才进入 active。

时间至少区分消息时间、写入时间、事实有效时间。“最近”不能未经定义就编出具体截止日；不确定时保留原表达与未解析状态。当前事实和历史事实分别查询。

后台任务应按原消息序号处理修订；旧输入即使后完成抽取，也不能压过新纠正。删除/关闭引入取消或版本守卫，避免待写任务把已删除记忆重新写回。

## 4. 用一组原始聊天做对照实验

先制作 12 类题族，每类 5 种中文改写，共 60 个虚构会话 fixture。数量是本项目试验初值，不是论文标准；将开发集与保留测试集分开，不为某一句话堆关键词。

题族：正常事实、多轮代词、第三人/引用、假设/角色扮演、临时/长期、同主题独立事实、明确纠正、歧义冲突、时间查询、当前要求覆盖、未知弃答、删除/关闭与并发。每条记录原始消息、时间/角色、应保存与不应保存的声明、后续问题和判定理由。

完整链路：

```text
虚构聊天与原始消息 ID
→ 实际抽取输出
→ 校验与写入决策
→ 独立库保存 / 重启 / 新会话
→ 检索与有效时间、范围过滤
→ broker 策略 / prompt
→ 真实生成
→ 最终后处理与交付
```

先用确定性候选检查存储、比较、策略契约，再用真实抽取模型跑同一批原始聊天。mock 结果和真实模型结果分开记录。不要往数据库塞期望答案后声称端到端成功。后台写入用 `Orchestrator.drain()` 等待完成，不靠固定 sleep；并发题人为控制旧/新任务完成顺序。

### 第一轮：定位瓶颈

固定同一回复模型、参数、提示预算和测试集，对比：

| 组 | 输入条件 | 用途 |
|---|---|---|
| H | 近期 history，没有长期记忆 | 跨会话基线 |
| M | 当前实现 memory | 测量现实系统表现 |
| E | 原始聊天抽取并经新证据/范围/比较机制 | 测量候选改进的端到端收益 |
| O | 人工核验的相关证据与正确策略 | 上限诊断：正确材料给到模型后还会不会错 |

O 组只是诊断上限，不能当成抽取系统成绩。先在 12 个保留场景的小样本试跑，每组重复 3 次，再根据错误分布扩大；不把一次成功当成稳定成功。

偏好题另设无偏好、正确偏好、相反偏好、错范围偏好；保持事实材料相同。看回复是否适当改变，而不是只看字数。当前明确要求应覆盖所有旧偏好条件。

### 第二轮：比较记忆维护方式

在共同的正确证据准入和检索预算下，仅改变更新机制：

1. U：保留所有证据，写入时维护 active/superseded/conflict 视图。
2. A：事实声明只追加，检索/读取时根据来源、时点和纠正关系选择。

分别测独立事实保留、当前/历史答案、未解冲突、来源保护、读取成本与延迟。两组都必须响应删除，不把“追加”解释为永不允许用户删除。先证明有收益，再考虑混合检索或关联图。

### 第三轮：检索与关联

只有写入和当前版本可靠后，再对比现有字符 TF-IDF、词法+语义混合检索、增加有证据关联三组。使用同一记忆集合，不让不同抽取结果混进检索比较。

历史和当前输入消歧后的检索 query 同样保留来源；不得把生成的 query 扩展反向写成用户事实。关联可以是 derived，原文和原始声明不可被自动“演化”覆盖。

## 5. 指标与阶段验收

各层独立报告，按题族给分母和失败例，不合成一个“记忆总分”：

- 抽取：应记事实 precision/recall；引用、第三人、助手内容的错误写入率。
- 证据：message_id/quote 有效率、含义支持率、时间与范围正确率。
- 比较：ADD/NOOP/UPDATE/CONFLICT 判定；独立事实误失效率、推测越权更新率、重复率。
- 检索：相关证据 recall@k、无关/过期信息注入率、当前与历史版本准确率。
- 策略：当前要求覆盖率、scope 正确选用率、冲突拒用率。
- 生成：请求完成、事实准确、虚构回忆、未知弃答、偏好遵循、无必要档案复述。
- 交付与成本：最终用户收到的内容是否保持原答案含义；语音分段/裁剪；tokens、p50/p95 延迟、写入可见延迟。

人工评审隐藏实验组，交换答案顺序。自动字数与关键词检查只辅助筛选；模型裁判可以辅助，但不能单独判定证据、语义与技术事实正确。

第一阶段验收先要求上述六个契约探针及其改写反例满足；来源、当前优先、范围、删除和并发不得退化。之后看保留集的端到端表现是否优于 M 与 H，成本是否可接受。小样本 100% 通过不等于生产中零错误。

## 6. 开发顺序与本轮产物

建议按依赖推进：

1. **实验入口与证据链**：隔离数据库；原始用户消息先落库并返回 ID；抽取只接收带角色/ID 的证据列表；记录阶段 trace。
2. **独立事实与来源保护**：修正同主题误合并；引入属性、范围、明确更新/冲突关系与消息顺序守卫。
3. **时间与策略识别**：事实有效时间；“并举例”等当前请求与假设区分；脚本、Rust 等场景改写；可靠 topic 来源。
4. **端到端对照**：先小样本，分层评分；通过后比较 U/A，再测混合检索和有证据的关联。

旧 `scripts/eval_scenarios.py` 和 `scripts/inspect_extract.py` 使用全局 store，并包含清库操作，不能按默认配置用真实库跑研究。现 `test_core.py` 自行隔离；本轮对所有测试又在进程导入前显式设置了内存路径。新探针同样如此。研究入口应长期改成显式依赖注入，而不是依赖操作者记住环境变量。

复现本轮探针，选择一个未存在的输出路径以保留旧记录：

```powershell
& .\.venv\Scripts\python.exe -B scripts\probe_memory_contract.py --output eval/research/memory_contract_probe_repeat.json
```

本轮成果是可复现的问题清单和实验设计，六个产品契约缺口尚未修复。下一项具体工作应是**证据链和同主题独立事实保护**，随后用原始聊天验证，不先更换向量库或开放自动长期偏好升格。
