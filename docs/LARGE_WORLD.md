## 派活规则

台账的活是本地确定性工作，只去镇内铺子；你派的神谕活是探索性的，优先去郊野。
郊野忙时退回镇内。判定用 prefab id 而不是距离——镇内书斋实测落在离祭坛 23 格处，
按距离会被误判成郊野，导致神谕活全派给镇内铺子。

| 迷雾 | 交付越多揭示越大；只压暗与拦建造，不拦通行 | `src/world/fog.ts`，`test/fog.test.ts` 6 项 |
| 视野裁剪 | 地形与迷雾烘焙成纹理，指令从 77 万降到 475 | `src/render/bake.ts`，`scripts/check-render-budget.mjs` 6 项；研究见 `docs/VIEW_CULLING_RESEARCH.md` |
| 建筑来源 | 建出来的楼记得自己是怎么来的 | `test/placement.test.ts`，日报写出来由 |

## 导播的两条规则

**闲置 15 秒才接管**，用户一拖一缩立刻退出——导播不该跟人抢镜头。

**候选里必须有多个点**。两个角色都闲在祭坛时，如果候选只有祭坛一个位置，
导播「接管」了却无处可去，镜头一动不动，看起来像坏了。现在候选顺序是
正在忙的人 → 运转中的铺子 → 祭坛 → 其它铺子。

## 迷雾的设计约束

**迷雾不拦通行，只拦建造。** 存档里没有网格数据，读档时按建筑坐标重建；若迷雾
让格子不可走，一栋落在迷雾里的建筑读档后就成了孤岛。

揭示半径由交付单数决定（每 4 单扩一格，上限 44）。渲染用冷色 `water` 而不是夜里的
`deepShade`：两者都压暗，但迷雾要读成「还没去过」，不是「天黑了」。

边缘雾团在漂移，见 `src/world/fog-drift.ts`：14 团沿揭示边界慢慢绕，

两条实现约束：

- **雾团不进烘焙**。迷雾本体是烘焙纹理，若每帧重烘整张图，视野裁剪省下的
  性能会全部吃回去。雾团是十几块独立小对象，每帧代价可以忽略。
- **不能用硬边矩形**。矩形在像素风里读成「半透明贴纸」。用 8px 小块按距离
  平方衰减拼出来才有绒感。4px 时一团上百块、总量六万条，超渲染预算。

## 地图为什么从 80×60 扩到 96×72（2026-10-22）

80×60 装不下「镇内 + 郊野 + 未探索」三层：郊野已经占到 40 格，最远角才 50 格，
迷雾只能盖住 3% 的边角。实测数据：

| 迷雾起点半径 | 覆盖面积 |
|---:|---:|
| 34 | 28% |
| 38 | 16% |
| 42 | 6% |
| 44 | 3% |

先试过压缩分区而不放大地图：镇内压到 21 格、郊野压到 34 格，但两者在
19.7–21.3 格重叠——**任何布局都分不开**。分区最小尺寸由 5×4 工坊加留白
（7×6）决定，压不下去。

所以扩到 96×72：

| | 距离范围 |
|---|---|
| 镇内四块 | 6.7–20.6 |
| 郊野四块 | 23.3–35.0 |
| 迷雾 | 38 之外，约 38% 面积 |

渲染代价：地形与迷雾都是烘焙纹理，地图大 44% 但每帧指令量不变，
帧率仍是 60（`check-render-budget` 6 项全过）。

## 持久化的验证陷阱

验证「刷新后状态恢复」时，**不要在每次导航都清 localStorage**：

```js
// 错：刷新时也会执行，把刚存的档清掉
await page.addInitScript(() => localStorage.clear());

// 对：只在首次导航前清一次
await page.addInitScript(() => {
  if (!sessionStorage.getItem('cleared')) {
    localStorage.clear();
    sessionStorage.setItem('cleared', '1');
  }
});
```

这个坑花了不少时间：表面看是「存档写入成功、刷新后丢失」，实际是测试脚本自己
在刷新时清掉了槽位。产品代码没有问题。

## 与方案不一致的地方

方案写的是 `TileSize = 32px`，未采纳。图块放大与世界扩大互相抵消：同样一块屏幕，
图块翻倍就只看得到一半地图内容，还要重画全部地形纹理。保持 16px、只加格子，
才拿得到「辽阔」的观感。

方案写的 `walkCost`（石板 0.4、森林 2.5）方向对，但数值按实测定：石板 0.8 时
绕上大路根本不划算（绕路 18.8 > 直穿 16），0.6 才开始出现「先上大路」，
取 0.5 避免为了上大路绕太远。

## 实现中抓到的六个真问题

每一条都是真机或测试先失败才暴露的：

1. 未覆盖格子的默认分区是 `street`，大世界 72% 变成石板路。默认改草地。
2. 雾与雨按画布尺寸建，大世界里只覆盖视野。改按世界尺寸。
3. 雾带按世界底边定位，永远落在视野外。改成跟着镜头走。
4. overlay 用 `worldView` 换算，而它由 `preRender` 更新、场景 `update` 先跑。
   改用 `scrollX/Y`。
5. overlay 的 `gameWidth` 传了显示像素（960）而非逻辑像素（480），2 倍显示下偏一半。
6. 0 毫秒的 `cam.pan` 不当帧生效。直接 `centerOn`。

## 郊野的辨识：两处变化（2026-10-23）

郊野铺子原本只是「换了配色的同款建筑，走过去更久」——实测单程 25 格约 8 秒，
镇内约 3 秒，**多走的 5 秒没换来任何不同的体验**。

补了两处：

### 1. 郊野的活更久

`taskDurationFor(kind, isWild)`：郊野铺子的活是镇内的 1.8 倍。

1.8 是实测定出来的。倍率再高会让等待变得烦人——1.8 让「去了一趟」有分量，
又不至于等到忘了。短活不受影响（它本来就不进铺子）。

### 2. 郊野常明灯

`isWildLanternOn`：郊野铺子**不分时辰**，白天也亮一盏灯。

与镇内窗灯是两套语义：
- 镇内窗灯跟**作息**走（黄昏与夜才亮）；
- 郊野灯跟「**有人在野外守着**」走，什么时候都亮。

理由：荒地里的一个人造光点，本身就说明这里有人。不新增 `WorkAccent` 枚举、
不动存档、不扩色——只用现有的 `warmLight` 与 `amber`。

呼吸按 300ms 一档刷新，不每帧重绘光晕（渲染预算实测无变化）。
