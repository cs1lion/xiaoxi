日期：2026-10-13。按[实现计划](AVATAR_CALIBRATION_PLAN.md)把长图的固定坐标、分项测量与证据流程接入现有 Three.js / VRM。使用 Daily 技术模型；没有把教程角色当作阿栖最终造型，也没有修改模型资产。

本文保留第一轮的结果与限制。后续已完成独立眉毛形变候选、实际 GPU 计时与第二轮动态证据，见[第二轮结果](AVATAR_CALIBRATION_V2_RESULTS.md)。第一轮的软件渲染性能不能与第二轮 D3D11 数字解释为优化收益。

## 调参和观察

| 表情 | 参数变化 | 实际观察 | 本轮决定 |
| --- | --- | --- | --- |
| 日常 | 不变 | baseline/candidate 整张 PNG 像素一致 | 保留 |
| 开心 | 左右开度 0.90→1.03；笑眼 0.40→0.28 | 金色阈值像素左眼 871→947，右眼 842→926，约增加 8.7% / 10.0%；截图中虹膜露出更多 | 保留试调参数，表情神态仍由人工评估 |
| 困困 | 左开度 0.44→0.38；右 0.46→0.40 | 金色阈值像素 723→577 / 667→515，约减少 20.2% / 22.8%；完整眨眼后恢复原持续开度 | 保留试调参数 |
| 疑惑 | 本轮最终保持 0.34 / -0.04 | 加大眉高曾使眉重心下移；撤回后 baseline/candidate 整张 PNG 像素一致 | 暂缓纯单侧抬眉，保留现有左右眉形差 |

以上面积是手工眼区内 HSV 阈值选中的金色像素，不是整只虹膜总面积，也不是角色还原准确率。阈值为 hue 25–65°、saturation 0.45–1、value 0.25–1；低饱和度眼睑边缘排除，但暗虹膜可能漏检。眼区截短以避免脸颊颜色混入，眉区也经蒙版目视检查。

原生眉形方向见[独立调查](../eval/avatar/calibration/brow-direction/README.md)。实际顶点与投影确认 Seed/Daily 的 `eye_brow_up` 同时改变位置和曲率，并非纯抬眉；交换 up/down 会更差。能力报告已标记近似通道，并新增读取真实 GLB 形变数据的测试。真正的独立垂直抬眉需要另外校准或新增形变。

## 固定场景与动态检查

正式集包括 32 张 720×720 截图：八种预设、修改前基线、日常/开心/困困的 25/50/75/100% 眨眼及恢复、四向注视、开心开口。所有截图使用同一相机、灯光和头身姿态；32 帧的独立头部锚点最大投影漂移为 0 px，不通过重新对齐消除误差。

三种全闭截图的金色阈值像素均为 0，蒙版与中间帧目视未见明显虹膜残留或穿插。该结论只覆盖采样姿态，阈值可能漏掉暗部，不能据此宣称所有动态姿态都正确。自动检查保留 `humanReviewRequired`，没有把原生 blink 权重作为像素闭合成功的替代证据。

实验室新增“眉眼校准”：固定场景、修改前后参数切换、表情幅度、眨眼步进、注视和开口、区域框、PNG / JSON 导出。校准期间暂停生产 Avatar 的原有 RAF，不建立第二条驱动循环；退出恢复原状态，包括后来加入的手势过渡控制器。模型、镜头、窗口或外观变化会拒绝继续比较，缩放后恢复新尺寸的镜头比例。

## 正常播放性能样本

使用正常 Avatar 更新和实际 `renderer.render`，没有跳过中间渲染。环境为 Windows、无头 Chromium 149、SwiftShader Vulkan，720×720 画布；每场景约 5 秒。原始帧间隔和每帧数据见[performance.json](../eval/avatar/calibration/2026-10-13T11-37-50-095Z-36876/performance.json)。

| 场景 | 实际更新帧 / 时长 | 观察 FPS | rAF 间隔 P95 | Avatar 帧 CPU wall 平均 / P95 |
| --- | --- | --- | --- | --- |
| 正视 | 53 / 5.03 s | 10.54 | 133.35 ms | 3.32 / 5.38 ms |
| 自动环视 | 54 / 5.10 s | 10.59 | 156.64 ms | 3.30 / 5.84 ms |
| 开心说话 | 53 / 5.04 s | 10.52 | 124.17 ms | 3.17 / 4.64 ms |

采样显示 54 draw calls、73,188 triangles。CPU wall 包含驱动、VRM 更新和 WebGL 提交，不包括完整 GPU 执行时间；未测 GPU timer。本轮未隔离本机其它任务，数字仅描述这次无头软件渲染运行，不能据此判断用户设备是否达标或承诺优化收益。实际设备性能与最终角色的审美验收仍为后续工作。
