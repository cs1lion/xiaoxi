# 方案：像素世界换向到「灯潮界」（2026-10-24）

**状态**：待用户拍板。本文只给方案与成本，不动代码。
**来源**：用户 2026-10-24 提供的 `像素异界设定集（以《千与千寻》为参照）v0.1`。
**前置**：`docs/SPEC_PIXEL_FIRST_20261024.md`（入口反转，已落地 `05db039`）。

---

## 1. 这次换的是什么

不是换色板，是**换世界观的骨架**。

现在的世界是「工坊小镇」：一位镇长、七间铺子按工种分（炼码工坊、观星书阁、墨坊）、一座祭坛、郊野、昼夜四刻、Fog of War。所有命名、分区、预制体、剧本都在这个隐喻里。

设定集给的是另一个隐喻：**「灯潮界」**——现世黄昏的背面，潮水每晚带来迷路的东西，灯火通明的建筑把它们接住、清洗、重新交付。核心规则是灯油即寿命、潮汐即时钟、名牌可抵押、渡有仪式、清洗即还原。

两套隐喻不兼容。硬套会得到"给工坊挂灯笼"的四不像，那正是设定集 §1 警告的失败模式。

## 2. 三个换法

### 方案 A · 只换皮（不推荐）

保留工坊小镇的结构，把配色换成设定集 §8.1 的十一色，加灯笼和纸签边框。

**成本**：约 1 天。改 `palette-data.ts`、`prefabs.json` 的 palette 槽位、UI 的 CSS 变量。
**得到的**：好看一点的工坊小镇。
**代价**：设定集里真正有价值的部分——规则驱动画面、区域各有主色、折返结构——一样没进来。而且世界观文案（莞尔、铺子、神谕）与视觉气质互相打架。
**为什么列出**：如果这轮只想要视觉升级，这是唯一的低成本选项。但它不满足"按这个重构"。

### 方案 B · 换叙事与分区，保留引擎与模拟（推荐）

**保留**：`simulation.ts`（2146 行）、`grid.ts`、`save.ts`、`ledger.ts`/`projection.ts`、`intent-*`、渲染管线（tilemap / buildings / villager / weather / day-phase / fog）。这些是引擎，与隐喻无关。

**换掉**：

| 现在 | 换成 | 依据 |
|---|---|---|
| 六个 zone（industry / scholarly / agriculture / living / street / altar） | 六个区域：渡口站台、灯街、叠浪楼、炉底层、浅滩轨道、积尘滩 | 设定集 §3 |
| 12 个 prefab（炼码工坊、观星书阁、墨坊…） | 区域内的建筑语汇：瓦顶+洋式老虎窗、朱红栏杆、格子窗、三种光源并存 | 设定集 §4 |
| 祭坛 | 保留。设定集里"渡有仪式"需要一个中心锚点，祭坛正好 | 设定集 §2 规则 4 |
| 24 色，以木/草/石为主 | 设定集 §8.1 十一色为基底，扩到 24 色预算内 | §8 |
| 昼夜四刻 | 黄昏 → 入夜 → 深夜 → 黎明（设定集 §8.2 的色调推移，正好四档对应现有四刻） | §8.2 |
| 莞尔、阿雾 | 保留莞尔（世界里的手），新增可选的灯芯伙伴 | §5.3 |
| 天气（雨/晴） | 潮汐（涨/退）。雨可以留，但"潮位"是新的一维 | §2 规则 2 |

**新增的一条世界规则**：`灯油`。这是设定集里最有画面感的一条（亮度=余量，灯暗则发灰变慢），而且**它天然对应台账里的耗时/进度**——一单跑得越久，灯越暗。这条能直接映射到现有数据，不是装饰。

**成本**：约 6–8 个工作日，分四刀：
1. 区域与预制体换名换形（引擎不动），存档 v3 + 指纹重算
2. 色板换成设定集基底并扩到 24 色（须走 ADR，项目红线）
3. 灯油系统（纯渲染层读台账耗时，不改 Simulation 的确定性）
4. 文案与 UI 语言：纸签、木牌、朱红印章

**风险**：存档格式变 v3，`ADR_SAVE` 的字段校验与指纹测试要一起动；96×72 地图的既有验收数字（`LARGE_WORLD.md` 里那些实测）会全部作废。

### 方案 C · 完全重做（不推荐）

按设定集从零建 2–4 屏的入口仪式、六区、剖面式叠浪楼。

**成本**：数周。**代价**：把 14,881 行里能用的全扔掉，包括所有已经调通的渲染与模拟。设定集自己也说 §12「先挑一个区域做完整的场景设定页」，说明它本来就不是一次做完的东西。

## 3. 我推荐 B，但先做一件事

**先只做「渡口站台」一个区域，做完给你看，再决定其余五个区要不要跟。**

理由是设定集 §12 的第 2 条建议，也是它自己的方法论：一个区域的完整做完（色板、瓦片、光源、NPC 站位）才看得出这套隐喻在像素尺度上到底成不成立。如果渡口站台做出来像"换了个名字的工坊小镇"，那剩下五个区也不用做了，省下五天的返工。

这一刀的成本约 2 天，且不触碰存档与调色板 ADR（新区域可以先用现有 24 色里的已有色值）。

---

❓ **Q2 · 先做一格还是一口气做完**：按 §3 先做渡口站台验证，还是六个区一起换。

➡️ 先做渡口站台。这是设定集自己给的方法论；也是唯一能在两天内知道这套隐喻成不成立的方式。

---

❓ **Q3 · 灯油规则接不接台账**：设定集里灯油既是货币也是寿命。我们世界里没有货币系统，最有价值的映射是「灯亮度 = 这单跑了多久」。

➡️ 接，但**只做渲染**。台账耗时进渲染层，不进 `Simulation`——保住「固定步长、无内部时钟、可确定性回放」这条契约（`ADR_WORLD_ALIVE` 已定）。

---

❓ **Q4 · 存档与既有验收数字**：换区域会改存档结构与 96×72 地图的实测数字（`LARGE_WORLD.md` 那批）。

➡️ 存档升 v3 并保留 v2 迁移；`LARGE_WORLD.md` 里那批数字加过期横幅，按 `AGENTS.md` 的「记录某一刻」口径补 HEAD 锚，不追改。
