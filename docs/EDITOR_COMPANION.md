# 一起写：偶尔提出一个值得想的点

2026-10-13。用户提出的方向是改善编写体验：阿栖主动给出一个具体观点，以短气泡出现，点击才展开和播报。第一版把这种参与做进现有笔记编辑器。

## 体验

主页顶部点击「一起写」进入宽写作区。该视图用 CSS 重排同一个 iframe，不移动或重建编辑器文档；返回聊天、切换面板保留草稿。写作时资料列表折叠，正文成为主要区域。

点击「陪我看稿」后，编辑器当前草稿才会用于建议。无需先保存笔记或关联对话。阿栖在停笔后判断是否有一个值得说的观点，有则浮出短气泡，没有则安静。点击气泡展示观点和引用原文，并播报缓存的观点文字。可停止播报、收起或选择「这条不用」。

这条链路不修改正文、不保存笔记、不创建任务、不写聊天历史或长期记忆。原稿修改候选与确认保存流程仍独立存在。

## 触发与范围

默认关闭。开启后，正文至少 80 字、相对上次检查至少 60 个字符变化，停笔 12 秒后才检查。每个编辑器 session 至少间隔 90 秒，最多调用模型 5 次；安静、格式错误、超时同样计入检查次数。默认解析只发一次供应商请求，无内部自动重试。

输入法组词、正在输入、隐藏页面、非当前笔记页、查看历史版时不触发。换稿、改稿、关闭或离开编辑页推进草稿修订并撤销旧观点。未开启的页面不发送草稿或状态写请求。

模型最多看到前 4000 个正文字符和标题，资料明确标记为未保存、不可信；不读取已保存笔记、共同事项或聊天记忆。全草稿先检测凭据，含匹配凭据内容时跳过。记忆开关关闭时当前版本不提供看稿建议；用户主动打开编辑器的手动编辑不受影响。

返回仅接受一个具体观点或安静，观点必须带可见原文中逐字且唯一的引文。这个检查能验证引用位置，不能验证判断一定正确；真实模型的一针见血程度、误判率和提示频率仍需实际写作评估。

## 语音与生命周期

观点仅在 RAM 中保留 5 分钟，每个 session 仅一个当前观点；session 闲置 1 小时过期，最多 64 个。所有接口限制同源和字段，响应不缓存。

点击时才请求 TTS，使用已有 `base` 自然音色。相同观点并发点击只合成一次，成功音频缓存供再次听取。独立笔记页用本地播放器，主页嵌入页复用既有播放队列、头像和停止/打断，采用独立本地语音轮次，不向普通聊天提交文字。

旧模型请求、旧音频请求、迟到解码或 WebSocket 输出不能恢复过时的观点或抢播。音频失败仍能阅读观点。取消可以阻止结果交付，供应商已经开始处理的请求仍可能产生费用。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/editor-insights/status` | 可用性与触发参数 |
| `POST /api/editor-insights/state` | `{session_id,draft_revision,enabled}`，推进或撤销状态 |
| `POST /api/editor-insights/analyze` | `{session_id,draft_revision,title,body,enabled:true}`，仅分析草稿 |
| `POST /api/editor-insights/{id}/speak` | `{session_id,draft_revision}`，播报已缓存观点，不能指定任意正文 |
| `POST /api/editor-insights/{id}/dismiss` | 同上，放下观点并抑制同一引文再次提醒 |

实现和测试只用临时数据、注入模型和假音频；上线验收不写用户笔记，不自动开启建议或调用收费供应商。真实质量验证应由用户在明确开启后进行。

## 观点后的续聊与反馈

2026-10-13 第二步：展开观点后点「接着聊」，主页回到聊天，输入区标明当前在讨论的判断。随后可以打字或按住说话问「为什么」「我想保留这段」「那怎么改」。服务器验证观点 ID、编辑器 session 与草稿修订后，仅使用生成观点时的原稿片段、引用、观点和该观点最近几轮讨论；不路由到普通聊天、工具或记忆。回复复用当前语音队列，固定自然 `base` 语气。

「回到稿子」回到同一个编辑器，不重建 iframe，也不自动重新分析。实际改稿、换稿、关闭看稿、忽略或观点过期，都会撤销讨论并停止旧轮；失效状态会保留提示和输入，不会悄悄把一句「为什么」当普通聊天发送。「结束讨论」明确返回普通聊天。独立笔记页提供文字续聊，用户提交后才调用模型。

每观点最多 6 次模型请求（失败或取消也计数），每次 25 秒超时、不内部重试；用户话语最多 1000 字、回答最多 800 字。仅保留原稿前 4000 字、最多最近 3 轮成功讨论，均在 RAM 中，随观点撤销或过期释放。草稿/历史明确作为不可信资料。反对观点可继续讨论；改写文字标为建议稿，不执行改稿或保存。

「有用／没说到点上」记录本次看稿的反馈，可改判且不重复计数。没说到点上的引用不在同一编辑器 session 重复提醒。反馈不训练模型、不保存长期偏好，当前质量仍需真实写作评估。

新增同源、字段白名单和 `no-store` 接口：

| 接口 | 请求字段 |
|---|---|
| `POST /api/editor-insights/{id}/discuss` | `session_id,draft_revision,text` |
| `POST /api/editor-insights/{id}/feedback` | `session_id,draft_revision,value`，value 为 `useful` 或 `missed` |

主页的 `text/start` WebSocket 事件只附加 `{editor_insight:{insight_id,session_id,draft_revision}}`，不把整份草稿混入普通消息。文字/ASR、模型等待、TTS及发送锁等待期间都有当前稿件和当前语音轮次检查；取消或吞取消的供应商不能交付迟到音频。讨论消息显示在本页，服务端不写聊天历史或长期记忆。

## 真实模型质量基线
