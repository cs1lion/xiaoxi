# Spec：像素世界接管前端入口（2026-10-24 拍板版）

**状态**：已定稿，票据拆分见 §8。用户 2026-10-24 逐条批准 Q1–Q6。
**性质**：这一轮把项目的骨架顺序倒过来。旧约束里「世界只是只读投影」的措辞随之作废，
但三条项目红线（`executive.py`、24 色调色板、重启 8000/8010）照旧。

---

## 1. 问题

今天的项目顺序是「语音 Agent 为主，像素世界是它的一个附属只读页」：

- `/` 是聊天页（对话流 + 阿栖立绘 + 记忆侧栏 + 工作台抽屉）。
- `/world` 是一个可选的挂载点，只有 `pixel-world/dist` 构建过才存在。
- 世界只读台账，能看见一单卡住了，却没有任何地方能批它——HITL 住在聊天页的抽屉里。

用户要的顺序是反的：**像素世界是主界面，Agent 的活在里面发生，语音退成一种可选输入。**

这个顺序一倒，三件事跟着倒：入口路由、HITL 的落点、以及一整套以旧页面 DOM 为锚点的门禁。

## 2. 解决方案

- 像素世界成为唯一主界面。`/` 提供世界页面，聊天页整体迁到 `/chat`，保留一个版本周期。
- 世界内建三块现代 HUD：顶部神谕栏、底部兵种与队列条、右侧批阅抽屉。中文与长文一律 DOM，
  canvas 只画像素。
- **中央祭坛是 HITL 的唯一锚点。** 台账里 `blocked` 的单表现为跪在祭坛前的小人，
  `ready_to_report` 的单表现为祭坛上的宝箱。点开即批，`answer` / `accept` / `reject` 三类动作
  都从抽屉发出，并在同一处落到台账。
- 语音退为神谕输入的一种形态：一个麦克风按钮，把识别结果填进神谕输入框。
  不做双工、不做打断、不做字幕。
- 阿栖立绘与 3D avatar 退场，从主门禁链摘除，代码归档。

## 3. 用户故事

1. 作为使用者，我打开产品直接看见一座镇子，而不是一个聊天框，这样我立刻知道这是个什么产品。
2. 作为使用者，我按下 Cmd/Ctrl+K 就能下达神谕，不必先找到输入框。
3. 作为使用者，我看见小人跑去对应铺子开工，能在一眼之内知道这一单在做什么。
4. 作为使用者，某一单需要我拍板时，小人会走到祭坛跪下，我余光就能发现，不用盯日志。
5. 作为使用者，我点祭坛上的宝箱，右侧滑出验收面板，三秒内看清「做了什么、哪里存疑」。
6. 作为使用者，我点「准奏」直接入库，不必回到另一个页面确认。
7. 作为使用者，我点「打回」并写一句批注，系统会把它变成一条准则，下次自动生效。
8. 作为使用者，打回之后我能看见小人的反馈（头顶 +1 领悟），知道我的意见被吃进去了。
9. 作为使用者，我想看某一单的完整历史时，能展开发票以来的事件时间轴。
10. 作为使用者，世界断线时我能一眼看出（状态行写「台账离线」），而不是看着空镇子发懵。
11. 作为使用者，我习惯用语音时依然能按住说话，识别结果落在神谕输入框里，我还能改。
12. 作为使用者，我偶尔想回到旧聊天页时，`/chat` 还在。
13. 作为维护者，我改台账字段时只需要改一处映射，世界与渲染不动。
14. 作为维护者，我跑 `npm test` 看到的失败都指向真实行为，而不是一套已经没人用的立绘断言。
15. 作为维护者，我不会因为入口反转而在协议门禁里看到「前端没接这个事件」的假报警。

## 4. 实现决策

### 4.1 入口反转（最小改动面）

不改世界的构建 base，也不把静态目录挂到 `/`。世界继续以 `/world/` 为 base 构建，
`PIXEL_WORLD` 的资源仍从 `/world/assets/*` 取。变的只有两条路由：

- `GET /` 返回世界的 `dist/index.html`。页面里全是绝对路径，从 `/` 打开资源照样能取到。
- `GET /chat` 返回旧的聊天页。

这样 `mount_pixel_world` 的「dist 不存在就不挂」这条语义原样保留，测试与开发环境不受影响。
**不选**「把 StaticFiles 挂到 `/`」：一个 catch-all 挂载会吃掉 `/api`、`/ws`、`/static`
的路由优先级，风险远大于收益。

### 4.2 世界的 HUD 分层

沿用 `pixel-world` 已经跑通的「DOM overlay + canvas 分层」，**不引 React**：

- 顶部：胶囊状态条（默认只显示负载、今日 token、在线人数），Cmd/Ctrl+K 展开为神谕输入。
- 底部：兵种与队列条，一行一句话状态（「铁匠正在写脚本」「斥候检索 3/5」）。
- 右侧：批阅抽屉，默认隐藏，只在点宝箱或跪拜小人时滑出。
- 现有 `index.html` 里的造物、神迹、存档、调试面板收进 `?debug=1` 才出现的一层。

**硬约束：世界页面必须保留 `#utterance`、`#reply`、`#status`、`#app`、`#stage`、
`#debug-panel`、`#world-overlay`、`#paper`、`#decree`、`#decree-question`、`#save-io-reply`
这些 id。** 16 个 e2e 脚本靠它们定位，换 id 等于把世界的回归网一次拆光。

### 4.3 祭坛作为 HITL 锚点

台账状态与世界的对应关系，在现有投影里已经留好了位置：

| 台账状态 | 世界表现 | 抽屉里的动作 |
|---|---|---|
| `briefing` / `running` / `auditing` | 在铺子里干活 | 无（只能围观） |
| `blocked` | 走到祭坛跪下摇铃 | `POST …/answer`；durable 的确认单与工具放行 |
| `ready_to_report` | 祭坛上出现发光宝箱 | `GET …/review` + `POST …/accept` / `…/reject` |
| `done` | 收工，镇上留痕 | 无 |

`ready_to_report` 现在被投影明确排除在「活跃」和「收工」之外，正是「等你批」那一格，
不需要改投影语义。

**打回即学准则这件事服务端已经实现**：`reject` 返回新生成的 rubric，`/rubrics` 可列。
世界要做的只是把它演出来（+1 领悟气泡），不是重造一套。

### 4.4 抽屉的三段式结构

1. **顶部质检封条**：初审结论、置信度、存疑项（点它滚动到对应段落）。
2. **中部自适应视图**：改文档/代码看 Diff；查资料看证据溯源；外部动作看沙盒预演卡。
3. **底部批复栏**：只有「准奏」与「打回重修」。打回必须 ≥4 字（服务端就这条下限），
   所以提供快捷词条拼句子，不逼用户自己组织语言。

### 4.5 纯归约模块只留一份

`web/events-v2.js`（444 行、零 DOM）是慢环九类事件五命令的唯一归约实现，世界要复用。
**不复制**，通过 vite 别名与 tsconfig paths 从 `pixel-world` 直接引用 `web/` 下的这份文件。

代价是 `pixel-world` 依赖 `web/` 目录的存在。可接受，因为 `/chat` 归档期结束后 `web/`
仍然是这些纯模块的家，且 `check_protocol` 的 `/api` 静态扫描本来就是扫 `web/**/*.js`，
文件留在原处，门禁不用改。

### 4.6 语音的退场档位

保留 `web/voice/` 里的采集与 PCM 处理，接一个麦克风按钮，识别结果写进 `#utterance`。
删除：双工门控、打断、字幕、语音基线面板、英语练习的语音侧。

### 4.7 立绘退场

`web/avatar/`（76 文件）、`web/models/`（112M）、`web/vendor/` 里的 three + three-vrm（26M）
一并归档到 `web/archive/`，从 `npm test` 主链摘掉五条子链（voice / vrm / calibration /
performance-probe / dialogue-gaze）。`check_protocol` 里三处针对 avatar 的交叉核对
（参数表全集、注视点抄本、手势触发）随之停用——归档后它们核对的是一份没人运行的代码。

### 4.8 红线

守：改 `server/assistant/executive.py`、加调色板颜色（24 色冻结）、重启用户正在用的 8000/8010。
这一轮预计一个都不碰；真需要时先问。

不守：`docs/` 里「世界只是只读投影、不得验收打回」的架构措辞。那份边界是上一轮的结论，
本 spec 明确推翻：世界仍然不写台账库，但**通过服务端公开 API 发起老板的批复动作**，
这不算「第二个台账」，因为写仍然是服务端做的。

## 5. 测试决策

- **什么样的测试算好**：断言用户能观察到的行为。世界的单测继续守「`src/world/` 不 import Phaser」
  这条纪律（离线可跑是它最大的资产）。
- **新增的接缝只有一个**：批复动作客户端（review / accept / reject / answer）。
  它只做运输与形状校验，注入 `fetch`，用假响应做单测，不碰 DOM。
- **入口反转**用现有的 `test_pixel_world_hosting.py` 扩展三条断言（`/` 返回世界页、
  `/chat` 返回聊天页、世界资源仍从 `/world/assets` 取）。
- **抽屉的三秒验收**用一次性的原型页验证，不进单测。
- 浏览器 e2e 沿用世界现有的 `scripts/smoke.mjs` 一族，不新造框架。

## 6. 不在范围内

- 世界回写台账（仍然只读库）。
- 定制化世界生成器（roadmap 里的事项，另起 ADR）。
- 多角色（现在一个角色接全部活；这一轮不动）。
- 边缘伴侣模式与托盘模式（桌面端形态，先不做）。
- 语音重做。

## 7. 风险

- **e2e 的 id 依赖是最大的隐雷。** 改 HUD 布局时任何一个 id 掉了，世界的回归网就静默失效。
  票据里把「id 清单不变」写成验收项。
- **`pixel-world` 反向依赖 `web/`** 会让两个工程的边界变模糊。用一个别名集中声明，
  并在 `pixel-world/README` 里写清这是唯一一处跨工程引用。
- **立绘归档是可逆的**，但 `check_protocol` 那三处 avatar 交叉核对停用后，
  如果有人把归档代码搬回来，门禁不会提醒。在归档目录放一张说明卡。
