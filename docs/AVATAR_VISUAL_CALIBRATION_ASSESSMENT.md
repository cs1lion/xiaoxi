## 它讲的是什么

一套半自动的角色制作与纠错流程：指定参考用途 → 固定坐标 → 分别测位置、轮廓、颜色 → 局部修改 → 拆分部件并编排动画 → 保留图像、参数和浏览器证据。

两个案例分别以简化胶囊眼和接近原插画的眼睛为目标，使用不同表情策略。后一个案例基于 SVG 分层、眼部纹理、轻量投影、透明播放缓存和 JavaScript，形成有限的 2.5D 效果。图中明确说明它不是 Cubism 模型，也不提供完整三维头部。

CV 部分是在人工指定眼区后，用颜色阈值、连通区域、重心和人工轮廓辅助定位；并不证明存在自动识别所有角色部件或自动完成高质量建模的系统。

主要方法：

1. **参考用途明确。** 身份参考、构图参考、确认稿和当前输出分别登记，避免把别的角色造型误当目标。
2. **修改前冻结比较坐标。** 用平移、旋转和等比缩放配准；修改后继续用同一矩阵。否则新一轮对齐可能消除需要检查的位置错误。眼睛对齐只能用于局部轮廓，不能同时证明眼睛在脸上的绝对位置正确。
3. **指标分别回答问题。** 锚点偏移检查位置，IoU 和边缘距离检查轮廓，宽高比与厚度检查眼形和眉形，局部色差检查颜色。拟合分数不是独立验证的角色准确率。
4. **形状与质感分别修改。** 虹膜、眼白、眼影、反光、睫毛和眉毛需要各自保留层次；只增加白色高光或把整只眼睛缩放，无法重现原图神态。
5. **部件有归属和遮挡。** 稳定名称、父部件、转轴、前后顺序和被遮挡底层都需明确。部件能单独存储，不等于露出后的区域有完整内容。
6. **动态与静态分别验收。** 检查半闭、全闭、回张、左右注视和组合表情；真实性能采集全部帧间隔和 P95。缓存是在特定 SVG 工作负载上验证过的优化，并非任意渲染器的通用收益。

## 对当前项目的判断

**有明显价值，最优先迁移的是视觉校准和验收方法。** 当前 Three.js/three-vrm 驱动已经能合成表情、注视、眨眼和口型；下一步需要证明确实表达出目标神态，并识别资产缺少的形变。主线可以保留现有 VRM，2.5D 作为正面头像方案另行比较。

| 长图方法 | 当前项目已有基础 | 可以补什么 |
| --- | --- | --- |
| 明确参考与受保护特征 | 模型来源、日常造型说明和许可证 | 确认阿栖的中性脸与几种目标表情，记录哪些参考只用于动作、比例或材质 |
| 固定坐标、同条件比较 | 眼部近景、模型截图和浏览器测试 | 固定模型版本、相机、姿态、灯光、视口、注视及眨眼相位；以独立头部锚点检查位置 |
| 轮廓、厚度、颜色分开 | 参数值、原生 morph 权重及能力报告 | 眉眼局部叠图和有针对性的指标，配合人工整体审美检查 |
| 眼球、眼睑、眉毛分离 | 预览驱动与 native morph 适配器 | 按目标补左右独立笑眼、眉角/眉曲率，确认上下睑是否可分别表达笑意与困倦 |
| 动态中间帧、遮挡检查 | 完整眨眼及恢复、20/30/60 FPS、视线和语音叠加检查 | 25/50/75% 闭合截图，极限注视、笑眼加说话组合，确认虹膜泄漏和眼皮穿插 |
| 性能对照实验 | 实验室有页面刷新率提示 | 实际设备固定场景采集帧间隔/P95，再据结果检查 VRM CPU 更新、draw calls、透明材质与像素负载 |

当前 [眼部适配器](../web/avatar/render/eye-morph.js) 明确报告独立瞳孔不可用。原 Seed/Daily 的笑眼、睁大和虹膜大小为双侧联动，眉形可左右独立。实际校准确认其眉高接口混合位置与曲率，并非纯垂直抬眉。第二轮独立候选新增了完整眉毛组件的纯局部 Y 平移；独立眉角、眉曲率和左右笑眼仍不属于该候选能力。Sample 的若干眉形通道是双侧语义形变近似。增加预设参数无法凭空增加资产能力。

高光当前控制已有高光的可见度；长图展示的透亮虹膜还依靠局部纹理、上暗下亮、反射轮廓与睫毛层次。若要改善质感，需检查眼材质和贴图，而不是只扩大高光滑块。

[眼部浏览器测试](../scripts/test-eye-browser.mjs) 的 54 项断言支持运行行为，包括原生 morph 输出与组合眨眼。它在确定性步进中跳过中间光栅化，最终再渲染，所以并未测量完整实际播放性能，也没有逐帧证明所有中间眼皮姿态的美术正确性。实验室 `metrics` 显示的是页面 rAF 频率，也不能独立代表 GPU 渲染耗时。

## 迁移时需要改写的部分

- SVG 的 path、clipPath、补底和遮挡顺序，在 VRM 中对应眼皮 mesh/morph、纹理、深度和透明材质；实现代码不能直接照搬。
- 图中的眼球近似球面投影，是弥补二维图层深度的方法。当前 VRM 应继续使用原有 bone/expression LookAt，并对其实际输出做校准。
- 图中的 65 档眼睑缓存与静态身体合图用于其二维渲染路径；VRM 应先做设备性能测量，再选择优化。
- 图中 0.22 px 等结果是对案例人工轮廓的拟合残差；12.8→119.4 FPS 是某台 Mac、某个 SVG 场景的作者记录。两者均不适合作为本项目的验收阈值或性能承诺。
- 当前 [日常造型验证](../scripts/validate_seed_daily.py) 保护原脸部顶点、morph 和表情绑定，适合换发型/服装。如果另建表情升级模型，应制定单独验证范围，允许明确的新形变，继续保护原骨架、拓扑、已有眨眼、元音与 LookAt 绑定。

## 建议下一步

先建立一个小的眉眼校准集：中性脸、开心、困困、疑惑各一张目标示意，并记录上睑、下睑、眉高/眉角、虹膜可见面积和嘴角的表达意图。对实际模型固定相机和姿态，生成同条件前后图及组合眨眼中间帧，一轮只调整相关通道。

例如“开心像困倦”，先检查下睑是否上扬、上睑是否过度下降、眉形和嘴角是否配合；“疑惑不明显”，先检查单侧挑眉和眉角通道。现有 morph 能表达时校准预设，无法表达时再制作候选资产形变。每次把模型 hash、输入参数、原生输出权重和截图保存到一起。

在明确了表情目标之后，再开展虹膜材质和反光层次优化。这样每次改动都有可说明的原因和可复查的结果。
