# 像素资产管线：约束与现状

- **状态**：约束生效；当前全部为手绘，未引入外部资产
- **日期**：2026-10-22
- **适用**：任何往 `pixel-world/` 加美术资产的人或 Agent

## 一、现状（写约束前先核过）

| 项 | 现状 |
|---|---|
| 外部图片资产 | **零**。`public/` 只有字体，`src/` 与 `public/` 下没有任何 png/jpg/webp |
| 地形与建筑 | 全部是 `Phaser.GameObjects.Graphics` 手绘，逐格/逐块调用 `fillRect` |
| 小人 | 手绘，但已有**分层雏形**：`villager.ts` 里 `MAIN_STYLE` 与 `VILLAGER_STYLE` 是两套配色，`drawBody` 按姿势重绘 |
| 调色板 | 24 色，冻结在 `src/world/palette-data.ts`（ADR_PALETTE_24） |

这个状态是好的：手绘 Graphics 天然像素对齐、色值受控、无需外部许可。

## 二、三条硬约束

### 1. 不让生图模型在运行时生成像素贴图

Midjourney / SD 产出的「伪像素画」有三个问题：

- **像素点大小不一**（mixels）：同一张图里既有 4px 也有 7px 的方块；
- **边缘带半透明脏点**：抗锯齿残留，放进像素场景里立刻违和；
- **没有统一网格基准**：无法与 16px 图块对齐。

放进 Phaser 与地图拼在一起，读起来就是「贴图糊了」。

**允许的用法**：用生图模型做**参考图**、**配色探索**、**构图草稿**，再由人按 16px
网格重画。产物必须经过网格对齐与调色板收敛才能进仓库。

### 2. 若要引入外部资产包，必须同时回答三个问题

- **许可**：MIT / CC0 / 已购商用许可。写进 `docs/` 并附来源链接。
- **网格**：16×16 还是 32×32？**与当前世界不一致的不要引**——混用两种网格
  会让地形拼接边错位，而这套拼接边是逐格判定画出来的（`terrain-edges.ts`）。
- **调色板**：外部包有自己的色表。引入等于**扩色**，而 24 色是已批准的 ADR。
  要么把资产重映射到 24 色，要么另开 ADR 扩色。

第三条是最容易被忽略的：资产包好看，但一旦引入，`audit-palette --strict` 会红。

### 3. 小人用分层组合，不用整张替换

现在的 `villager.ts` 已经是这个形状：`drawBody` 按姿势与风格重绘。要扩到
「造物主生成新小人」，只需要让风格变成一个**数据组合**：

```
{ hair: 'spiky_blue', outfit: 'blacksmith_apron', tool: 'hammer' }
```

而不是一张整图。理由：

- 组合出上千种长相，画风天然统一（同一套绘制函数）；
- 生成方（LLM）只需要输出 JSON，不碰像素；
- 与「造物主只做选择题」的既有边界一致（`ADR_CREATION_MODE.md`）。

## 三、当前不做的事

- **不引入外部资产包**。现有手绘地形与 24 色是配套的，换资产包等于重做地形层
  并触发扩色 ADR。
- **不实现纸娃娃分层**。当前只有一个角色（莞尔）+ 一个助手（阿雾），
  两套配色够用；收益要等「生成新小人」这个功能出现。

两条都记在这里，等真要做时按第二节的三个问题逐条回答。

## 四、加资产时的检查清单

- [ ] 来源与许可写进 `docs/`，附链接。
- [ ] 网格与 `TILE_PX` 一致（16），或明确说明为什么例外。
- [ ] `node scripts/audit-palette.mjs --strict` 仍退出 0。
- [ ] 100% / 200% / 400% 截图下像素边缘无渗色（非整数缩放会糊）。
- [ ] `test/palette-budget.test.ts` 仍通过（它逐 token 锁值）。
