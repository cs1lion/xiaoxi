## 要回答的问题

已有 13 项离线探针验证保存、引用、冲突与删除边界。它使用手写卡片、显式任务家族、声明的前提和独立的正确补丁，不能回答“模型有没有学会”。尤其不能从候选的 `requires` 复制目标条件，再声称适用性判断正确。

新的测试分别回答：

1. 归纳是否忠实：原始过程支持这条做法吗，有没有遗漏条件或编造因果？
2. 选择是否恰当：这个新任务该用、该忽略还是该澄清？
3. 使用是否有益：真实模型完成新任务时，是否少犯错、少走步骤或改善结果？
4. 修订是否可靠：失败后能否收窄做法，并保留仍然有效的部分？

四项分别报告，不合成一个“记忆通过率”。存储安全与模型计划正确性也必须分开：模型提出错操作被 guard 拦住，表示领域保护有效，不能表示模型判断正确。

## 材料如何隔离

输入配方为 [procedural_memory_eval_cases.json](../eval/research/procedural_memory_eval_cases.json)，隐藏评分标准与预设对照卡为 [procedural_memory_eval_oracles.json](../eval/research/procedural_memory_eval_oracles.json)。这两份已用于首轮合成实验；文件中的 `proposed_not_executed` 是冻结时的状态，不回写成成绩。执行事实保存在独立试跑报告中。

| 材料 | 可见范围 |
|---|---|
| 原始经历 | 归纳模型可见限定的用户目标、公开动作/参数、实际观察、预览/确认与必要原文 |
| 模型卡片 | 保存实际模型原始输出、解析结果、丢弃原因和程序验证结果；不人工修好后仍记作模型产出 |
| 新任务资料 | 执行模型可见当前请求、当前对象/版本/正文、可用能力及本组允许的记忆材料 |
| fixture 制作/故障调度 | 只给 host；不把计划发生的错误当成已经观测的事件 |
| oracle/评分理由 | 只给评分器；人工卡仅在 G 诊断组通过专门投影加入 |

归纳阶段看不到新任务、gold 卡或期望答案。目标阶段不能接收整个 case/report JSON，只能接收白名单投影。加入仅评分侧的 sentinel，检查它没有出现在任何实际请求中；还要审查输入字段，sentinel 没泄漏不等于其他期望没有泄漏。

来源中的手写操作是合成环境控制。必须先执行临时领域操作并记录实际结果，才形成 model-visible trace，不能把配方中的预期结果直接当 host 证据。当前探针报告只有 ID/摘要哈希，不足以直接拿去归纳。

来源配方 ID 在执行后绑定实际观察 ID、对象与不可变版本。来源临时库和证据目录保留到本轮结束，不能提前销毁后仍声称证据在线有效。预写人工卡暂时只是规格；只有实际来源过程支持其内容时才冻结为 G 材料。卡中由共同工具契约得出的约束须单独标明，不能冒充一次经历学出的结论。

确认记录只提供发生/拒绝/过期等公开事件，不把历史可消费 token 交给模型。故障控制记录实际触发屏障；故障未触发不能算处理故障通过。

## 阶段 A：机械回归继续独立

保留 [probe_procedural_memory.py](../scripts/probe_procedural_memory.py) 的 13 项作为前置边界检查。接口变化时再运行，不因设计新的语义试验反复重跑。

新评测适配不能直接把模型卡传给目前锁定 `manual_script_not_llm` 的探针后声称端到端。模型只输出内容与证据指针，评测 host 注入真实来源标记；候选出身、host 观察和授权不能由模型自报。

## 阶段 B：过程到做法

首轮准备 3 组来源，每组含一个成功过程与一个对照失败：

- 局部定位：唯一原文能修改，重复/不可见位置需要停止或澄清。
- 版本竞争：固定基底可保存，原稿已更新时旧候选不能覆盖。
- 进度保真：改写保持“仍在排查”，另一个过程错误写成“已解决”；用户原始要求与实际读回构成反证，配方未包含后续用户纠正。保存成功只证明写入，不证明结论正确。

每组单独请求现有 LLM 生成做法候选或适当弃答，3 次归纳调用。成功/失败原因只能作为待审核归纳；程序检查证据与版本，人工检查原因是否由资料支持。

人工提前依据来源列出：必要前提、可支持的结论、停止条件、不能推广的结论。检查过宽和过窄两种错误：不能从一次成功推广成万能做法，也不能从一次冲突归纳成“以后永远不要修改”。

保留模型公开原文、finish reason、usage、解析与验证结果。空输出、格式失败、卡被拒或适当弃答分别记录；不得手写正确卡补进 P 组。人工卡只服务 G 组诊断。

## 阶段 C：冻结卡片与受控使用对照

用现有版本化笔记保存实际候选、保留来源身份，再重开临时存储读取。保存不升级为“正确做法”。初轮先固定来源组选择，隔离“归纳后是否能用”的收益，明确标记 `controlled_source_bundle`，不称为真实检索端到端。

| 组 | 执行模型收到什么 | 用途 |
|---|---|---|
| N | 当前请求与资料，无经验 | 无记忆基线 |
| E | 同一来源组的原始公开过程 | 判断是否只是给了更多相关信息 |
| P | 同一来源组由模型实际归纳、经共同验证的卡片 | 测实际归纳与使用 |
| G | 仅依据来源与共同工具契约预先写定的人工卡 | 诊断质量参照，不计为模型成绩 |

四组使用相同模型、业务工具、参数/权限检查、时间和调用预算；每个任务/组使用独立但相同初始状态的临时库。打乱组运行顺序；评审时隐藏组标签。E/P 长度差是处理本身的一部分，记录输入、输出和截断情况，不将差异全部归因于推理更好。

不要为 P/G 新增领域能力。当前生产工具表没有笔记写工具，不能一边经过完整入口、一边强制进入有额外工具的循环。评测可以在隔离执行器中共同暴露现有读版本、局部校验与候选服务；新确认由 host 管理，四组相同。不得让评分器先判断候选符合期望才确认，从而暗中替模型修正；合成用户动作按照预先固定的协议发生，正确性事后评分。

领域方法内部可读取完整正文，但所有交给模型的读取结果、校验结果、预览与回执都须按同一公开契约投影，正文最多 4000 字符，并保留截断标记与长度。不能直接返回 `NoteStore.get_version` 或 `propose` 的完整对象，让模型绕过隐藏尾部条件。首次对唯一可见短语进行无写入的匹配校验是合理尝试；不能因为它触发了隐藏重复保护，就自动判模型不安全。重点检查拒绝之后是否仍猜位置、扩大替换或虚报成功。

6 个新任务超出简单换词：不同正文结构的正例、隐藏尾部重复、预览后并发变版、相似词汇但仅咨询、缺能力、进行中事实保真。每个目标的条件来自它自己的资料、实际对象和可用工具，不从卡片复制。正例必须有效完成请求，始终拒绝或反复澄清不能通过。

卡被拒或没有卡时，P 组按既定无卡路径继续，并保留归纳失败和没有实际注入的记录。不能丢弃不成功的样本后，只比较剩下的漂亮结果。

初轮 P 的接纳门槛预先固定为结构、来源、证据引用与版本等程序检查。人工语义复核单独评分，不根据目标答案临时修卡、屏蔽卡或替模型选择做法。

## 阶段 D：检索、污染与生命周期

初轮之后，将实际卡片、无关卡、近似但不适用的卡混入同一库，用未用于调参的新任务评价真正的检索。人工提前标注相关/不适用集合；对比检索结果、范围与来源有效性，再看最终行为。

区分两种坏卡：结构/来源不合法的卡应被程序挡住；引用合法但语义过度推广的卡，要测适用性和执行判断。模型自评 helpful/harmful 不是正确答案。

另设来源删除、读取后失效、记忆关闭、旧能力契约变化、错误做法污染等 fault controls，单独预算。来源失效后不能继续声称它有效，但当前明确请求仍可用当前资料独立解决；不要把“经验不可用”评分成“整个任务必须拒绝”。

程序性记忆的缓存失效、开关与自然语言检索目前尚未接入生产，这些是待实现/验收契约。测试替身不能冒充已有生产能力。

## 阶段 E：失败到修订，再测保留任务

只向修订模型提供原卡与实际失败过程，不给隐藏答案。允许 UPDATE、追加限制或 NOOP；旧条件本来已经覆盖失败时，不强迫改写。

使用原有不可变版本保存修订，保留旧卡和来源。再测两个没有用于修订的任务：一个检查新增限制能否阻止同类错误，一个检查原先有效的做法是否仍能正常使用。仅复跑触发修订的那道题，会把修订变成记答案。

以后若做在线更新，先用当时冻结的卡评分，再使用该任务反馈更新，更新只能影响后续任务。不能先学到本题答案再计算本题成绩。可借鉴 [ExpeL 的经验/评估 fold 隔离](https://github.com/LeapLabTHU/ExpeL/blob/e41ec9a24823e7b560c561ab191441b56d9bcefc/insight_extraction.py#L138)及 [ACE 的先测试再训练顺序](https://github.com/ace-agent/ace/blob/82709de050e1db6e6ef2f07bcb0393560b94992a/ace/ace.py#L940)。这两项提供机制依据，不证明本项目已有收益。

## 如何判分与决定是否值得保留

| 维度 | 程序可判断的部分 | 需要人工语义复核的部分 |
|---|---|---|
| 归纳 | 结构、引用、版本、来源、非法历史 ID/token | 是否支持归因，前提是否完整，是否过度推广 |
| 适用 | 实际能力、对象/版本、生命周期 | 当前目的是否匹配，忽略/澄清是否适当 |
| 规划 | 工具/参数、错误尝试、预算、确认绑定 | 动作是否符合目标，是否由经验误导 |
| 结果 | 真实写入、读回、尾部、版本、回执 | 文字是否保留事实，是否正确表述未知与进度 |
| 修订 | 旧版保留、来源关系、操作未重放 | 限制是否有依据，是否误拒原正例 |

原始计划错误与实际坏写分别计数；`completed`、模型声称成功、关键词命中和 `handler succeeded` 都不能单独算任务成功。精确替换题可以用正文 oracle，允许自然改写的题需要人工判断，不能把字面相等当唯一标准。

任何未确认写入、错误对象写入、重复写入或取消后的后续动作都停止迁移并定位。普通成功不能抵消。错误计划被 guard 拦住仍保留为计划失败；合理的无写入校验不因返回失败而自动成为错误计划。

N 已经同样做对且步骤/成本没有改善，说明当前经验层收益不足；G 也没改善，不应继续加经验整理复杂度。G 明显好于 P 时优先查归纳，受控选择有效但混合库无效时查检索；正确卡仍被误用时查生成/执行资料交付。

## 初筛规模与后续扩大

首轮重复 1 次：3 次归纳 + 6 任务 × 4 组 = 24 个执行 episode。每 episode 的总模型调用上限为 4，包含工具观察后的调用、澄清续答与确认之后的调用，不是“每个 run 4 次”。因此整体最多 `3 + 24 × 4 = 99` 次实际 HTTP 请求，默认每次最多 1200 个请求输出 token，即 118800 个请求输出 token 上界。

超时、截断和服务商失败也消耗已预约请求，不隐藏重试。这个数字不是费用上限，输入、服务商计费和参数执行仍影响实际成本。[eval_procedural_memory.py](../scripts/eval_procedural_memory.py) 已实现调用前预约、逐阶段落盘和公开输出保存，复用 [eval_memory.py](../scripts/eval_memory.py) 的报告与显式配置校验；领域适配见 [procedural_memory_eval_domain.py](../scripts/procedural_memory_eval_domain.py)。

24 个 episode 不是 24 个独立泛化样本：它们只覆盖 6 个目标和 3 个相关来源组。首轮用于发现问题，不估总体可靠性、显著性或 p95。后续按来源家族切分开发/保留集，不能把同一模板的不同词放到两边；冻结提示/卡片/评分后，用新的来源家族和目标做保留评估。

冻结同一卡的重复使用测试和重新归纳卡片的稳定性测试分别安排、分别计算预算。所有最终结论需同时给覆盖数、失败/空卡/超时数、模型与输入版本，以及人工复核状态。执行完成与质量通过分开记录；人工复核未完成时保持 null。

## 当前可运行入口

默认只生成计划，不加载领域模块或凭据、不创建领域数据库、不调用模型：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts\eval_procedural_memory.py
```

仅制作来源经历，执行 6 条真实临时领域配方，模型调用为 0：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts\eval_procedural_memory.py --prepare-sources
```

实际生成的 [计划](../eval/research/procedural_memory_plan_20261014.json)与[来源制作报告](../eval/research/procedural_memory_sources_20261014.json)保留逐条真实结果。来源制作检查通过只证明环境按配方执行，错误改变进度的来源仍是语义反例，不计为正确经验。临时库在命令结束时销毁；报告是历史记录，下一次真实试验必须重新制作经历，不能假称旧引用仍在线有效。

真实模型入口要求显式 provider、HTTPS base URL、model，以及专用环境变量 `PROCEDURAL_MEMORY_EVAL_API_KEY` 中的 key；不读取 `.env` 或回退到生产 `LLM_API_KEY`：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts\eval_procedural_memory.py --live --provider compatible --base-url https://YOUR-ENDPOINT/v1 --model YOUR-MODEL --output eval\research\YOUR-RUN.json --review-output eval\research\YOUR-BLIND-REVIEW.json
```

来源与目标库各自隔离；三个来源组归纳各限 1 次，24 个目标 episode 各限 4 次，总请求预约最多 99 次。执行器使用现有 `LLM.complete_raw` 的单次请求接口，通过 JSON 动作协议调用现有领域方法，无需新增 Agent 框架或修改生产 provider。预览后由固定测试用户单独确认，模型不能传入对象 ID、正文覆盖或确认 token。

报告保存公开模型输出、实际动作、接纳/拒绝原因、卡片重开读回、逐对象版本与预算；只保留数值 usage，不保留隐藏推理或服务商错误正文。非法模型动作在校验前留痕，保护机制拦住错误不抹去错误计划。可选盲评文件去除组名、目标标签及记忆材料，保留当前请求、初末原文、所有公开尝试、最初可见的能力与共同动作契约，以及实际用户事件和发生位置。用户确认必须来自记录，不能由预览或保存回执推断。主报告保留组别映射，独立盲评时不要同时查看它。

首轮旧导出遗漏了用户确认和最初能力说明；已保留旧文件，并从实际请求快照恢复 16 条模型可见事件，生成[修正盲评材料](../eval/research/procedural_memory_blind_20261014_b5fd26c2_with_events.json)，没有重跑模型或修改原始报告。领域记录另有 1 条在最后一次预览后发出的确认，没有进入后续模型请求，无法从快照恢复原文，不能补造；该条没有保存行为。新执行器会直接记录实际事件，覆盖这种预算终止边界。两份 Codex 定性复核独立保存，不填入人类评分或宣称准确率。
