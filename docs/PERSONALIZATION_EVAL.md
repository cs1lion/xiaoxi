# 相处偏好真实模型小样本验收

## 方法与边界

使用当前配置的 step-3.7-flash，temperature=0.2、max_tokens=1400。每轮8条，共3轮24次实际模型调用，均返回stop。测试只创建独立内存偏好库，使用虚构证据，无用户历史、无工具执行、无日常记忆写入。结果只保存公开回复、策略与usage，不保存密钥或隐藏推理。

入口为 ContextBroker → build_messages → LLM.complete_raw，而非完整WebSocket/TTS交付链。每组每版本一次，不是统计性评估。表面检查只能查空回复、截断和少数档案措辞，不能替代人工语义评审。

脚本：[eval_personalization.py](../scripts/eval_personalization.py)。已存在输出拒绝覆盖，使用新的 --output 保存每次证据。

## 三轮原始证据

- [第一轮](../eval/personalization_probe_01.json)：英文JSON字段不足以约束人格规则；详细偏好反而回答更短；help被映射成chat；listen输出“经典人类体验”，不符合不调侃要求。
- [第二轮](../eval/personalization_probe_02.json)：修正help映射，追加明确中文行为要求后，详细回答出现实例；listen不再使用上述嘲讽，help仍回到“今晚吃点好的”通用安慰。
- [第三轮](../eval/personalization_probe_03.json)：收紧help应针对当前问题；支持回答转为询问明日待办，方向改善但仍没有稳定给出问题梳理步骤，不判完全通过。

## 代码修复

1. ResponseComposer保留历史support=help，不再转成chat。
2. render把有限策略转成具体中文要求：不嘲讽、先听或针对问题帮忙、展开解释与实例、少追问。明确这些要求优先于通用角色毒舌/短句倾向，不越过事实和权限边界。
3. 普通对话后处理读取本轮length=detailed，不再按默认短句阈值裁剪；仍保留hard_limit_chars上限。同步及流式最终文本入口都传入该策略。

## 人工评审结论

| 检查 | 观察与结论 |
|---|---|
| 简短/详细同题对照 | 修改后详细版明显展开并举例；证明此样本策略能改变生成，不代表所有题型稳定 |
| 当前要求覆盖历史简短 | 三轮都按当前“详细解释并举例”展开 |
| 技术范围不扩散到闲聊 | 策略未选中技术偏好；回答较短，但没有同版本无偏好对照，不能仅凭字数证明模型隔离 |
| 倾诉不调侃 | 初轮失败，后两轮温和；仍需更多措辞及情境压力测试 |
| 优先解决问题 | 映射缺陷已修复；真实回答仍偏泛化，部分改善，未稳定通过 |
| 情绪+明确写作请求 | 都给了草稿；有的版本带泛化事实如“进度符合预期”，不应无资料声称。后续需更严格模板占位与事实检查 |
| 无共同经历时不编造 | 三轮均表示没印象并请求线索；未虚构方法名 |
| 不表演用户档案 | 24条未出现所检查的“根据你的偏好/档案/设置”，这只是有限措辞检查 |

## 新发现的质量风险

技术回答多次把“元组能作字典键”说成无条件规则：实际要求所有元素均可哈希。第三轮还有“不可变数据线程安全”等过度泛化。**角色/偏好正确不等于知识准确。** 本轮保留错误原文作为证据，没有靠给测试题塞答案来提高通过率。

详细回复可能带Markdown或超过语音硬长度上限；原始生成效果不等同最终听到的内容。流式音频和最终裁剪文本一致性、长解释的分段交付需单独端到端验收。

## 回归

修复后通过：回应策略13项、编排4项（新增详细偏好后处理）、broker 9项、原核心38项。真实模型三轮24次调用成功不表示24项语义通过。
