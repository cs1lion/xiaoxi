# 根据当前姿态衔接动作

动作导演负责语义手势的播放时间；VRM 渲染器为动作启动、替换和取消增加一段从实际手臂姿态起步的过渡。这一过渡层保持台词锚点、动作窗口、冷却与互斥规则；日常角色的四种目标姿势另见[手势视觉校准](GESTURE_CALIBRATION.md)。

校准后的日常手势还提供[抬起与收回路线](GESTURE_PATHS.md)，先到身前准备姿势再接近目标。该路线改变本帧的采样目标，仍经过本文的实际姿态过渡层。

## 依据与执行

`PerformanceDirector.sample()` 在实际动作身份变化时附加稳定的 `transition: {id, reason, from, to}`。重复采样同一动作不会重复启动过渡；同一种手势重新播放仍属于新动作。自然姿态用 `rest` 表示。

渲染器收到新的过渡编号后，仅捕获一次当前肩肘与手腕的实际四元数。它测量这些朝向与请求强度下的目标姿势之间最大的角度差，将过渡时长限制在 80–350 毫秒，再平滑插值到本帧目标。本帧目标仍包含原有的动作进度、强度和减少动态效果设置；没有预先求解一条完整运动轨迹。

台词手势的开始时间和进度继续使用音频时钟。取消时，当前动作和待播动作立即清除；身体回收使用有上限的渲染帧时间，即使音频时钟挂起，手臂也能收回。取消后不继续旧动作的挥腕周期。350 毫秒是控制器累计帧时间的上限，低帧率设备可能需要更长的墙钟时间。

## 对照

打开 `http://127.0.0.1:8000/static/avatar_lab.html?model=daily&preview=transitions`，在“05 / 动作衔接”中重复播放：

- 自我强调 → 摊掌 → 收回。
- 招呼 → 中途打断。

打开“根据当前手臂姿态衔接”使用新过渡；关闭后使用原有逐帧指数平滑。两种方式使用同一模型、同一组目标姿势和同一套固定流程，均为静音预设，不调用回复模型或 TTS。状态区显示最近的动作切换及过渡时长。前端刷新即可生效。

## 边界

这一步读取实际关节朝向，没有求解手部目标位置、关节速度连续性、衣服碰撞或手指动画。语义动作间原有的收回空隙仍保留；没有为了连续性提前执行下一短语，也没有跨句编排或自动选择动作变体。实际穿插和姿态自然度仍需要逐模型视觉校准。

渲染器提供 `setPerformanceTransitions(enabled)` 与只读诊断 `getPerformanceTransition()`；未挂载或关闭时诊断为 `null`。诊断含编号、来源/目标动作、原因、角度差、时长、进度及是否仍在过渡。诊断是开发观察数据，不改变模型或语音协议。

## 验证

`node web/avatar/test_pose_transition.js` 覆盖稳定动作编号、同名重播、快速替换、目标强度角度计算、打断原因、冻结音频时钟回收，以及校准固定画面清除旧快照。语义计划、导演、Avatar 停止、VRM 映射和眼睛校准的相关测试通过。

`node scripts/test-pose-transitions-browser.mjs` 使用真实 daily VRM 与原生 AudioContext，测量切换和打断瞬间的实际关节四元数、连续帧变化、音频时钟挂起后的恢复，以及实验页两种模式的相同流程和停止操作。`node scripts/test-speech-performance-browser.mjs` 的 9 组语音动作回归也通过。结果与截图保存在 `eval/avatar/pose-transitions/` 和 `eval/avatar/speech-performance/`。

浏览器验证使用受控无头环境和静音流程。最初的目标姿势仍较粗，后续[日常手势校准](GESTURE_CALIBRATION.md)另有前后图和中间姿态检查；过渡测试本身不能证明服装权重或真实设备性能已经验收。
