### C10 规范记录的「已知缺口」只修了一半（2026-10-22 修订）

**初版写「已解、不需要协议变更」，四处都不成立。** 逐条改：

**① 偏离的不是 `closed_reason`，是规范自己给的 fallback。**
§4.9 表里已经写明免协议路径：「批准前只在 `commission_events` 里记一条 `kind=cancelled`」。
所以「绕不开协议所以只能这么干」讲不通。真正要写的是**为什么 `audit` 比规范指定的
`commission_events` 更好**——见下条。

**② 更好的理由存在，但它是「更便于消费」，不是「更保守」。**
世界拿的是 `GET /api/executive/commissions` 列表，`audit` 就在列表每项里（`PROTOCOL.md` 的 commission 列表字段定义）；
`commission_events` 是 `GET /commissions/{id}/events`，每单一次（`executive_api.commission_events`）。
要世界区分取消，走 `audit` 是零额外请求，走 `commission_events` 是 N+1。**这是理由，但不是「更安全」。**

**③ 「不新增字段所以不需要协议变更」不成立。**
`PROTOCOL.md` 把 `audit` 的形状写死了：
`{passed, layer, findings[], usage, scolding, retry_count, created_at}`。
往里加 `cancelled` / `cancel_reason` / `cancelled_at` 三个键，**是把一个文档化字段的 schema 扩了**。
JSON 容忍未知键所以不会崩，但项目红线是「不得自造 API 字段」，严格读这就是。
**处置**：`PROTOCOL.md` §19 补一行说明 `audit` 可能携带取消标记。**这一行归 Role 0（用户本人），团队不改。**
不补的话，这个字段从此有两套 schema，靠「有没有 `cancelled`」来分辨，下一个人读不出来。

**④ 最要紧：缺陷没修完 —— 语义记下来了，效果没变。**
全仓搜：`pixel-world/src` 里读 `cancelled` 的消费者**一个都没有**。
`projection.ts` 的 `parseCommissionRow` 只取 7 个字段、把 `audit` 丢掉；
`simulation.ts:435` 对任何 `finishedIds` 里的单都走 `finishActiveTask` → `accrueFaith()`。
**所以「取消单被当成交付、还加信仰点」这个用户看得见的现象，`fa488ea` 之后一模一样。**

**结论**：C10 记成「**记录已加，缺陷仍在**」，不是「已解」。

**四条可复用判据：**
1. 复用文档化字段并加键 = schema 变更，仍要同步文档，不能记成「无需协议」。
2. **有没有消费者**——没有消费者的记录只是日志，不是修复。
3. 规范自带 fallback 有没有被违反；违反了要写明理由。
4. **语义等价 ≠ 效果等价**。要问「改了之后，用户看到的那个现象还发生吗」。

**下一步该补的**（已派 World Builder 一部分，其余待用户授权）：
让投影读 `audit.cancelled`，取消单不进 `finished`、不加信仰。
但 `types.ts` / `projection.ts` 与用户本人的 Claude Code 线地盘重合，**须先报批**。

|---|---|

| **检查项零交集** | `evaluator.L1_CHECKS` 是 6 个交付卡检查（`required_fields` / `artifacts_exist` / `wired_not_dry` / `no_topbar_button` / `token_budget` / `acceptance_met`）；规范 §3.7 的 `CheckSpec` 是 7 种（`file_exists_nonempty` / `schema_valid` / `syntax_ok` / `exit_code_zero` / `csv_assert` / `rubric` / `ask_user`）。**交集是零** |
| **重试上限打架** | `evaluator.MAX_RETRY = 2`，`PROTOCOL.md`「`retry_count` 上限 2」也是 2；规范 §3.1 的 `Budget.max_retries` 默认 **3**，T16 用 `attempt < budget.max_retries`。**同一个概念两个数** |

**结论**：复用它的「确定性、不靠模型心情」原则和 `normalize_signature` 这类工具，
**别复用它当 Verifier 主体；逐条 criterion 的执行器必须新写。**
`MAX_RETRY` 必须从 `budget` 读，不准引那个常量。
