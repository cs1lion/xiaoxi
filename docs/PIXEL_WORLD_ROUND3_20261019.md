# 像素世界 · 第三轮：接真实台账

> **⚠️ 过期快照（2026-10-25 回填标注）**：本文为 2026-10-19 的历史记录，其后进展以 `git log` 与门禁命令输出为准；现行交付状态见 `docs/DELIVERY_PLAN_20261024.md`。

2026-10-19。这一轮把世界从自洽沙盒接到主服务的督办台账上，这是三轮里唯一一次
跨模块契约变更。

## 一、接的是什么，怎么接的

**真相源。** `GET /api/executive/commissions` 返回的督办列表（协议 §19），每条带
`id / title / agent_id / status / step_idx / blocked_question`。花名册的
`GET /api/executive/adapters` 提供 `agent_id → strengths`，用来把 7 个 Agent 归到三类活。

**没有督办相关的 WS 推送。** 我查了 `server/app.py` 的全部消息类型，只有轮次、语音、
积木、领航这些。所以要世界"实时"只有两条路：轮询，或加一个推送事件。

**选了加推送。** 因为用户要的是操作台与世界真的连起来，不是每两秒拉一次。

三层，每层都能单独测：

1. `projection.ts`（纯函数）：台账字段 → 世界事实。唯一的映射点。
2. `simulation.ts` 的 `sync` 命令：台账快照落进世界，和打字、按钮走同一条队列。
3. `ledger.ts`：运输层。REST 全量起步，WS 增量推进，断了退回轮询兜底。

## 二、服务端改动

`CommissionStore` 加一个订阅钩子，只挂在三个写入口之后（`create` / `transition` /
`record_step`），**都在事务之外**。订阅者拿到的是已投影的那一条，与 REST 同形，
所以消费方不必维护第二套字段映射。

`app.py` 加连接注册表与广播。有两个细节值得记：

- **回调可能来自任意线程**（写库路径不保证在事件循环里）。第一版用
  `get_running_loop()`，那会在非循环线程静默丢事件。改成 startup 时抓住主循环，
  回调里 `call_soon_threadsafe` 转过去。
- **推送是旁路。** 没有在线连接就静默丢弃；订阅回调抛异常一律吞掉——推送坏了不能
  连累写台账，也不能连累其它订阅者。

## 三、契约变更（AGENT_PLAYBOOK 红线确认）

- `PROTOCOL.md` §19 新增 `commission_update` 事件说明。
- `check_protocol.py` 新增第 11 类检查：协议文档、服务端广播、世界客户端三方必须
  认同同一个事件名。世界客户端不是 `web/app.js`，第四类检查看不见它，所以单独纳管
  （与 `INTERNAL_ROUTES` 同一类处理）。我故意改坏一次验证过它会 FAIL。
- 不改 REST 形状、不新增路由、不改既有事件。旧客户端读到未知类型整条忽略，纯增量。

**跨源问题用 Vite 代理解决**，没给主服务加 CORS：原型 dev server 把 `/api` 与 `/ws`
代理到 8000，浏览器看到的是同一个 origin，服务端那句同源写校验原样通过。

## 四、世界侧的四条纪律

这轮最要紧的不是"接上了"，是接上之后不撒谎：

1. **世界不编进度。** 台账的活一律 `determinate: false`，铺子上方不画百分比。
   真实工作跑多久只有台账知道，计时器估出来的那条线是假的。
2. **完成权在台账手里。** 台账说收工她才交付，撤单她就停手；沙盒的活才由计时器收尾。
   两条来源用 `TaskRecord.source` 区分，`stepWorkstations` 只自动收 sandbox 的活。
3. **台账是唯一真相。** 世界只读不写。断线时照常过日子，但状态行必须写"台账离线"。
4. **映射只在一处。** 换台账字段只改 `projection.ts`。

按用户拍板的方案：7 个 Agent 按能力归到 3 栋铺子。`blocked` 优先被挑出来（要请示），
`drafting` 不进世界（还没派出去的单不该让铺子开工），同级按 id 稳定排序。

## 六、已知不足

- **一个人干全部活。** 7 个 Agent 的单都归到她头上，台账一忙就会露怯。多角色是下一步。
- **两栋以上同类活会互相让。** 台账只挑优先级最高的一条派下去，其余排队；
  排队中的单在台账里看得见，世界里看不出来。
- **进度条对台账的活是空的。** 这是有意的（不撒谎），但视觉上不如沙盒热闹。
- CI 上 `test_workbuddy_worker_shim.py` 失败，与本次改动无关：本地 34/34 全过，
  CI 是 Linux 环境，那条测试依赖 Windows 的 `WorkBuddy.exe` 假执行体。未处理。
