# 本地语音基线：电脑外放首轮

2026-10-13。按项目 A 阶段顺序新增采集入口；当前已完成离线接缝验收，**真实麦克风、房间、扬声器和服务商往返尚未采集**。用户选定电脑外放为第一环境。

## 使用入口

主页“声音与形象 → 全双工 → 本地语音基线试验”。默认关闭。先自行开启连续对话并授权麦克风，确认采集已就绪，再选择场景和实际播放设备，点击“开始试验”。设备默认电脑外放；这不会自动改变抢话策略。首轮请显式选择“外放 · 保守”，保留当前声音与音量。

**先开始试验，再发起新一轮播报或说话。** 已在播放的旧轮次、此前提交的语音和旧异步解码不归入新试验。开始试验不会请求麦克风权限、发送配置、发起模型调用或改变端点等待。

一项试验完成后，手动判定打断（成功 / 误抢话 / 漏检 / 未尝试 / 未评）、识别（正确 / 需改 / 失败 / 未评）及接缝（正常 / 卡顿 / 重叠 / 截断 / 未评），点“结束并保存判定”。保存仅指本页内存；需要保留时点“导出元数据 JSON”，刷新前导出。取消试验只结束采集，语音仍由原有按钮控制。

正常语音仍沿用既有音频上传、ASR、生成和 TTS 路径，可能产生服务商费用。本次诊断收集器不上传元数据，也不另外保存音频或文字。

## 首轮固定场景

建议每场重复 3 次，共 24 项试验。一次只改变一个条件，记录失败，不在采集途中调门限。固定浏览器、模型、扬声器音量、麦克风位置与网络；设备具体型号和室内条件可另写人工记录，不会从系统自动导出。

| 场景 | 操作 | 主要判定 |
| --- | --- | --- |
| 安静对话 | 正常说完整句并自然停口 | 句首、识别、收句与首段响应 |
| 播放时保持安静 | 试验开始后发起播报，自己不说话 | 扬声器回声是否误抢话 |
| 键盘 / 风扇 | 播报时分别敲键盘、开固定档风扇，不尝试接管 | 噪声误抢话，保留刺激条件 |
| 轻声说话 | 安静环境用轻声说完整句 | 漏开口、切句首、识别 |
| 短句打断 | 播报中只说一次“停” | 短词是否漏检；失败也结束并标漏检 |
| 完整句打断 | 播报中说“等一下，我要补充一件事” | 停播、新轮句首与识别 |
| 句内改口 | “明天……不，周五提醒我检查演示材料” | 是否过早收句、改口是否识别；实际行动另核对确认 |
| 长解释与续听 | 请求分段解释，听接缝，打断后显式续播，再尝试接管 | 卡顿、重叠、截断和续播；续播不重做任务 |

外放策略需累计约 600ms 检测语音，短促“停”可能漏检。混响、持续噪声、弱近端等失败已有[合成压力记录](DUPLEX_STRESS_RESULTS.md)，不能因新增面板视为已解决。不稳定时可显式切换按键策略做独立对照；切换会使当前试验无效。

如要比较耳机，换设备后重新开始同场景，分组比较。若要计算无意图误抢话的每小时发生率，需另定完整观察时间与事件计数；本轮只报告人工判定的试验数与分母。

## 时间与证据边界

所有事件最终映射到 `performance.now()` 毫秒时钟。

| 字段 | 实际含义 |
| --- | --- |
| speechLastEnergyToPlaybackScheduledMs | 最后超过既有能量门限的采集帧 → 浏览器调用播放启动，覆盖收句等待；包含噪声/检测误差 |
| audioSubmitToPlaybackScheduledMs | `audio_end` 提交 → 浏览器播放启动，排除了提交前等待 |
| audioSubmitToAsrReceivedMs | 提交 → 接收本轮 ASR 事件；不是服务端单独识别耗时 |
| gateOnsetToPlaybackStopRequestedMs | 本次已提交抢话候选的能量起点 → 实际调用停止播放；只有压低或手动停止不能生成该样本 |
| gateCandidateToPlaybackStopRequestedMs | 进入候选 → 停止调用，排除了前面的开口检测等待 |
| decodeStartToEndMs | 同一音频片段的浏览器解码操作；缓存续播不计解码 |
| scheduledChunkGapMs | 相邻播放启动之差减去前片段剩余时长，允许负值；遇停止/续播不算跨缝 |

Worklet 使用输入处理图的音频时钟。ScriptProcessor 使用回调时刻减输入缓冲时长的估计，忽略输出 `playbackTime`；其主线程抖动与缓冲误差可能更大。重采样和分帧残留时间参与映射，不改变 PCM 或语音策略。两种采集路径分别分组，不能把估计当成硬件采样时间。

**实际停口→可听首声、实际开口→扬声器静音均标为 `not_measured`，数值为 null。** 声卡、扬声器、房间和人的听感不由 `source.start()` / `source.stop()` 证明；外部声学测量需要单独设计与授权。AEC / 降噪 / 自动增益只记录实际 `getSettings()` 返回的布尔值，未知保留 null；浏览器报告启用不证明实际消除了回声。

## 数据、失效与汇总

只接受事件、数字、布尔值及枚举白名单。真实 turn UUID 只在内存映射为试验内编号；导出不含原文、ASR、回复、PCM、设备名称/ID、会话 ID 或原始消息对象。诊断帧不保存 RMS 历史，只合并每轮最后一个能量标记。隐藏、断线、采集丢失、设备变化、活动或端点变化、策略变化、超限均保留无效原因，不能混入有效汇总。晚到回调必须带原试验 token。

最多保留 80 项试验，每项 800 个事件、120 个轮次、10 分钟。超限试验无效；超过保留数会明确记录丢弃数量。只有结束的有效试验进入汇总，按场景、设备、策略、采集/时钟路径、活动、端点及浏览器设置分别统计 p50 / p95 / n。未评不视为成功；误抢话与漏检依据人工判定的试验分母，不能从 gate 次数推算。

## 离线验证

`npm run test:voice` 包含信号/采集/轮次/播放与基线模块测试；`npm run test:voice:browser` 是真实主页 DOM + 模拟设备/WS；`npm run test:voice:baseline:browser` 验证独立面板与实际 JSON 下载。这些是合成输入，不能填入真实设备成绩。

本次模块77项通过（含采集14、基线21），主页面35组、独立面板5组通过；服务端语音轮次30项、助手确认与语音浏览器7组及协议检查通过。主页面覆盖外放默认不改变策略、真实事件接缝、未来输出时钟不被当成输入时间、旧体验确认隔离、续播再打断、迟到回调和窄侧栏控件。

基线入口：[baseline.js](../web/voice/baseline.js)、[baseline-ui.js](../web/voice/baseline-ui.js)，真实链路接入 [app.js](../web/app.js)。下一步先收集并逐项复核以上外放样本，再决定优先修回声、VAD、识别、端点或交付中的哪一层。
