# 项目发展判断与阶段路线

更新：2026-10-14，初审为 2026-10-13。基于当前工作目录源码、已有实验记录和并行审查。阶段顺序已按用户确认执行；下文区分历史诊断与当前验收状态，不代表全部路线能力已经实现。

首次全局审查只新增本文，曾只读访问当前服务的 `/api/health`、`/api/preferences/proactivity`、`/api/notes`、`/api/threads`，均返回200。后续 A 阶段已修改代码并完成隔离离线回归；用户指定项目推理配置及 `step-5-preview` 后完成一次12请求的真实记忆抽取。未读取真实用户库、采集真实麦克风或重启生产，所需连接凭据未输出。旧服务检查不作为最新代码部署证据。

## 1. 主线：有性格、能跨日接续的个人语音搭档

推荐定位：阿栖是一个有声音、有性格，能陪用户把尚未成形的想法逐渐想清楚，并在隔天接着讨论的个人搭档。语音创造的氛围和共同参与感是核心价值；判断、资料和记忆让这份陪伴有依据、有进展。独特性需要通过真实使用验证，不能仅凭“其他 agent 没有语音”成立。

三条用户路径分别提供不同价值：

- **一起聊**：回应当前诉求，保留分寸与角色连续性，接受纠正。
- **一起做**：围绕需要取舍、反复修改或跨日接续的事情，共同探索、形成判断、修改成果；需要行动时再使用任务与工具。
- **一起学**：围绕明确材料解释、尝试应用、选择是否保存学习结果。

“一起做”适合作为下一阶段主场景。复杂度看共同讨论能否带来收益：信息不完整、选择有取舍、目标会变化、成果需要迭代，都可能成立；不要求大量工具调用。一次简单问答、设提醒或改一句话直接完成，不强制创建事项或计划。短小交流仍可提供语音陪伴价值。

语音用于倾听、追问、表达判断和自然接续；完整资料、比较和作品版本放到可阅读的载体。事项在需要留下共识或下次继续时出现，不成为每轮对话的必经手续。“一起学”与共同创作也可验证这一能力。音乐、剧场及形象实验保留为探索入口，暂不同时扩大。

长期方向仍可以包括共同观看、有限主动参与和共同创作。应先证明阿栖能在明确范围内理解、接续和兑现，再逐步扩大共享内容与参与时机。

个人项目的核心指标是：用户是否愿意开口说尚未成形的想法；讨论是否改善思路或成果；隔天需要重讲多少背景；改口和打断后能否自然接住；说话与停嘴是否舒服；用户是否愿意再次让它参与同一件事。对话时长和功能数量不能替代这些指标。具体记忆适配见 [语音搭档与记忆实践](VOICE_COMPANION_MEMORY_PRACTICES_20261013.md)。

## 3. 优先处理的实际瓶颈

### 3.1 事实先可信，再扩大记忆

[现有记忆研究](MEMORY_RESEARCH_NEXT.md)及[原始隔离探针](../eval/research/memory_contract_probe_20261013.json)曾报告8个探针中6个拟定契约尚未满足。消息证据链先达到6/8，当前两项策略修复后[新报告](../eval/research/memory_contract_probe_strategy_20261013.json)为8/8满足。三份报告保留，这些是人工候选检验程序规则的结果，不是实际模型错误率。

历史诊断中的例子（现已完成程序层修复与离线反例验收）：

- 同批或分轮提供“在甲公司工作”和“岗位是设计师”，独立信息会因同主题被合并或使前者失效。
- 推测能让用户明确说过的偏好失效。
- 候选没有原消息证据，仍能以stated及高置信度被接受。
- “详细解释并举例”可能被当成假设过滤；不含语言名的脚本请求可能被识别为闲聊。

源码依据为 [extractor.py](../server/memory/extractor.py)、[manager.py](../server/memory/manager.py)、[composer.py](../server/dialogue/composer.py)和[broker.py](../server/interaction/broker.py)。

最小方向是“原消息 → 有证据候选 → 新增/重复/纠正/冲突决策 → 当前与历史视图”。主题用于分类，不能代替主体、属性和范围构成事实身份。来源标签必须由程序核对原消息，不能由模型自己宣称。原文存在只是第一层校验，还需要检查候选含义是否被原文支持。

消息顺序、持久删除代次和写事务守卫已补：`observe_turn`等待后复查，旧消息回放受 write_floor 限制，`forget_key`直接删除全部匹配历史。旧数据保留“未关联原话”标签；实际用户库尚未迁移。[固定真实抽取入口](MEMORY_EVAL.md)首轮暴露并存茶偏好被当冲突的问题；后续[偏好契约](MEMORY_PREFERENCES.md)已为有限句型补并存、程度、原话时间和持久退役顺序。下一步核对改后提示词的真实稳定性、语义支持及跨域删除，完整有效时间仍未实现。

验收先采用既有探针及中文改写反例：独立事实保留、推测不越权、明确纠正准确、当前/历史分别查询、删除与关闭后无晚到复活。随后才比较语义检索、关联图或不同更新算法。无需先换向量库。

### 3.2 语音要贯穿帮助过程

[app.py](../server/app.py)目前通过 `_present_reply` 把助手行动结果及确认后反馈接入共用分句 TTS 与轮次隔离，已有离线确认/中断回归。原审查中的“帮我做事时只给文字”断层已有源码实现；B阶段先核对部署和真实跨日场景，沿用交付路径补质量与恢复接缝。

应形成“听见请求 → 必要澄清/确认 → 执行 → 简短口头反馈 → 可查看回执”。口头反馈只表达实际状态；停止播报与撤销已经执行的操作继续分开。较长草稿完整交付到可阅读载体，语音给摘要和下一步，不通过无限朗读或硬裁剪替代文档交付。

延迟需分解为停嘴到端点、ASR、模型首段、TTS、解码与播放启动。旧提交后指标仍保留；新的[本地语音基线](VOICE_BASELINE.md)覆盖最后能量帧到浏览器播放启动、抢话起点到停止调用及解码/接缝，并区分 Worklet 输入处理时钟与回退回调估计。软件启动播放仍不能证明真实扬声器发声；真机听感和声学测量单独记录。

[双工压力报告](DUPLEX_STRESS_RESULTS.md)已经暴露混响、长回声、持续噪声误抢话和弱近端漏检。用户选择电脑外放为首个真实基线环境，按固定8场景采集，耳机作为对照，保留按键降级；按错误数据决定是否引入神经VAD、成熟AEC或流式ASR，避免靠继续调确认时长掩盖分类问题。

### 3.3 “一起做”需要一个可见的共同对象

当前源码已有主页事项选择、创建并关联和“继续这件事”入口；选中 ID 保存在 SQLite，取消关联也持久化。关联是单用户本地全局选择，切换时已有版本与迟到结果守卫。此前“只挑最近任务、选择重启丢失”的诊断已过时。详见 [SHARED_THREADS.md](SHARED_THREADS.md)；源码成立不等于本轮完成真实跨日验收。

下一阶段沿用入口，连接当前目标、已确认决定及其依据、未决问题、当前成果版本、下一步和相关回执。[事项依据第二增量](SHARED_THREAD_EVIDENCE.md)现已持久保存确认请求、事件版本及固定笔记引用；旧原话只在候选内存的缺口已补本地快照，但完整聊天消息引用链仍未实现。全局笔记选择与事项选择的组合不能代替每事项资料集合，关联资料也不证明其支持决定；任务描述中的笔记 ID 不能代替结构化关联。

普通聊天与行动助手的记忆上下文已在[第一增量](MEMORY_CONTEXT_DELIVERY.md)统一：共享主体、来源说明、证据状态/消息引用、偏好程度、范围和原话日期。事项域随后增加了明确 note id/version、确认请求与可打开的修订依据；后续补引用用途和范围，再按失败证据扩大检索。避免只升级抽取器，却在上下文转换中再次丢掉语义。

连接各域用ID、版本和来源。记忆回答“了解什么”，笔记保存“整理过的资料”，任务维护“要做什么”，事项表达“正在一起推进什么”，字幕是临时引用，授权单独维护。统一引用和归属，保留数据语义。

“创建了任务”“执行了工具”“用户表示已完成目标”应是不同事件。用户自述与系统回执都可以有用，但验证范围不同；缺少回执不代表未执行。

### 3.4 执行结果应能在重启后查清

现有确认绑定参数且单次使用，这是已有优势。仍有“确认已消费 → 工具副作用发生 → runtime回执落盘”之间的崩溃窗口；事项回执仅在service返回时桥接，REST直接修改或进程崩溃可能没有补录。

建议给每个写动作稳定操作ID，例如run与动作序号。任务库在同一事务记录业务结果与待投递事件，再投影到运行时和共同事项。恢复先查询实际结果，不盲目重放。先做好本机SQLite的有限闭环，无需引入分布式平台。

同时让health反映调度是否仍活着、最近成功扫描和构建/能力版本。当前调度循环未处理异常时会退出，而健康接口仍可能显示ok。备份脚本已有单库完整性检查，跨库一致时点及临时目录恢复演练仍需补充。

## 4. 阶段顺序与交付判断

按依赖推进，不给尚无基线的工作承诺固定工期。

| 阶段 | 用户能感知的结果 | 关键工作 | 结束条件 |
| --- | --- | --- | --- |
| A：可信基线 | 能知道当前能力与失败状态；被纠正和要求忘记后行为可靠 | 能力状态、隔离实验入口、消息证据、独立事实/来源保护、写入守卫；并行采集真机基线 | 既有合同缺口及反例通过，临时库重启/恢复可验证；明确区分真机与模拟证据 |
| B：跨日一起做 | 今天共同推敲一个方案或作品，隔天能接着修改和推进 | 沿用主页事项入口；统一证据/范围上下文，保存决定依据、显式资料/成果版本关联；含行动时补回执恢复和语音结果 | 讨论→改口→中断→重启→续接完整，成果与依据正确；含工具的路径另验确认/执行/回执，无串事项、重复副作用和假成功 |
| C：自然地一起学与聊天 | 一个片段能解释、练习并产生用户选择保存的成果；各路径保留角色气质 | 明确材料、返回来源、缺信息反馈、学习回顾；共享角色规则和交付方式 | 保留题集解释有依据，练习反馈基于文本；盲评改善自然度且不损害请求完成和事实准确 |
| D：有依据的主动参与 | 在用户允许时，对真实事项变化进行有限跟进 | 先到期/结果事件，后获授权回顾；去重、时机、拒绝与说明 | 来源、授权和时机可解释；忙碌时不抢话；不因沉默推断情绪；拒绝后不重复 |

每阶段绑定一个真实场景，不无限建设通用平台。推荐首个贯穿场景为“共同准备一次项目演示或观点表达”：讨论立场和提纲、比较方案、修改稿件、遇到问题、调整决定、隔天继续；只在需要时创建执行任务。A/B/C/D 是投入顺序，不是强制用户选择的流程；复杂学习或创作也能作为 B 的验收场景。

“一起听看”在C阶段继续做片段学习闭环。新增学习笔记或回顾须明确预览和保存，沿用不自动持久化邻近字幕的边界。持续全场旁听、自动插话、播放器定位和音频发音评估分别立项，以新证据决定是否投入。

## 5. 工程收敛与角色质量

现有原生前端、FastAPI、SQLite和模块边界仍适合当前单用户项目。优先改契约和接缝，不为了统一而进行全框架迁移。

建议逐步做到：

1. 一轮请求有明确session、turn、当前活动、引用对象/版本、操作与确认编号。普通对话、练习和剧场继续隔离上下文。
2. 测试通过应用工厂或明确依赖注入使用临时数据目录；限制绕过bootstrap的AST测试依赖，增加实际应用装配与路由验收。已有双重avatar路由及遗留memory路由装饰应在装配检查中清理。
3. 多个前端模块共享状态通知和挂载契约，逐步减少iframe与重复练习概念；保持草稿、焦点、取消语义。
4. 角色固定规则共享，事实/行动/学习材料按活动注入。体验路径可以改变任务方式，但不能让资料变成角色经历。

沿用用户选择的“自然”声音和已确认界面。角色提升优先关注“听懂当前需求、适时反对、纠正后改变、说具体的话”，再校准少量眼神、倾听动作和手势。短回复或离开不应自动触发冷淡惩罚；现有人设与当前回应策略中的冲突需要合并审查。

真实偏好评测已记录帮助泛化、补写草稿事实和技术知识错误；[后续记忆研究](MEMORY_RESEARCH_NEXT.md)还修正了部分“当前请求覆盖成功”的归因。应分别评分策略、原始生成和最终交付，不能因为最后回答展开了就推断协调层正确。

暂缓同时扩大多角色声音、原创音乐、专业动画、桌面外壳、自动画像、通用Shell/桌面操作与多用户云化。保留实验素材，待主体验和用户反馈给出明确收益后逐项解锁。微调与更多角色台词也应等到拥有足够可靠的正反例和盲评基线。

## 6. 验收方式：从通过数量走向使用结果

确定性边界测试继续保留；增加三条分层真实路径：日常跨日对话、共同事项推进、字幕学习。使用虚构资料和隔离库，真实模型运行预先固定输入、次数和成本上限，真机试用默认不保存诊断原音。

分别报告：

- **事实与记忆**：证据支持、独立事实保留、当前/历史正确、未知弃答、纠正/删除后行为。
- **完成当前请求**：产物是否有用、澄清是否必要、执行状态是否准确、确认与恢复是否增加负担。
- **语音**：停嘴到首声的p50/p95、开口到停播、误抢话与漏检、识别纠错、长解释接缝。
- **角色**：同题重复盲评的分寸、具体性、重复率和自然度；保持相同事实材料，避免风格遮盖错误。
- **运行**：重启后数据/回执一致、通知调度健康、版本可见、备份可恢复。

先取得基线再定性能目标，给样本数量、设备环境和失败例。模型裁判与关键词可辅助筛查，不能单独确认蕴含、执行真实性或听感。
