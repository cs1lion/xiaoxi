## 0. 一句话目标

阿栖不应该只是一个等待指令、从固定台词抽样、靠随机数制造性格的数字角色。
她要能**从共同经历中形成自己的理解**，在后台持续追问尚未解决的问题，把不同时间、
不同来源的记忆交叉联想成新的思想分支，并在合适时机把这些变化自然带回前台互动。

最终判据只有一条：经过一段时间的真实互动后，阿栖的**思想树、心境与个人观点**能从
真实经历中产生**可追溯**的变化；她的表达能体现这些变化，但绝不退化成随机参数控制的伪人格。

## 1. 两条不可违背的哲学

### 1.1 数值只控制物理阀门，不定义性格内容

严格区分两类状态：

- **数值型控制状态**：只回答“何时发生、发生几次、何时重估、资源怎么分”。例如 `heat`
  （某问题多值得重新思考）、`cooldown`、`confidence`（某记忆/审美判断的可信度）、记忆保留
  期限、主动事件触发时间、TTS 语速音高停顿、性格调整的安全边界与防抖。数值能影响一件事
  **什么时候发生、发生多少**，却不能直接规定阿栖该显得温柔、傲娇、失落或兴奋。
- **叙事型人格状态**：真正影响表达的心境、态度、品味、灵感，**必须以自然语言保存**并注入
  `server/persona.py` 的 Prompt Context。至少包含 `Attitude Drift`（态度漂移）、`Mood Inertia`
  （心境惯性）、`Latent Sparks`（潜在灵感）、`Self-Taste`（审美沉淀）、`Gentle Pushback`
  （温和异议）、`Circadian Context`（时段主观体验）。

叙事片段必须允许大模型自然发挥，**不得**把它们重新压缩成固定性格分数或规则模板。第一人称
心理叙事（例如“昨晚他为了那个接口折腾到很晚，我本来想损他一句……等他开始讨论代码结构时，
我再把昨晚想的简化方案抛出来”）才是人格演化的主要载体。

### 1.2 所有演化必须有真实来源，禁止伪随机进化

每次后台思考的输入必须来自**真实存在的材料**：未解决的好奇心种子、用户近期 `notes`、共同事项
`threads`、近期对话摘要、阿栖自己的历史日记、已形成的审美观点、过去的推理卡点。大模型负责从
这些材料里完成交叉联想、解释、反思和子问题派生。

禁止：随机抽台词、随机切换人格、随机改性格数字、无上下文自由作文来伪造自主性。所有重要演化
结果必须保留**可追溯的来源与关联**（`source_refs` / 图连线）。

## 2. 四层架构总览

```text
         ┌─────────────────────────────────────────────┐
         │  第一层  双螺旋好奇心树（思想引擎，最高优先级）      │
         │  seeds / reflections / epiphany 边 / 裂变       │
         └───────────────┬─────────────────────────────┘
                         │ 产出：新发现 / 子种子 / 顿悟
         ┌───────────────▼─────────────────────────────┐
         │  第二层  昼夜节律 + 心境惯性（跨轮次情绪连续）      │
         │  circadian context / mood_state               │
         └───────────────┬─────────────────────────────┘
                         │ 经由 persona.py 叙事注入
         ┌───────────────▼─────────────────────────────┐
         │  第三层  个人执念与温和反驳账本 self_identity_ledger│
         │  taste / worldview（富化：置信/支持/反例/演化史）    │
         └───────────────┬─────────────────────────────┘
                         │ 三梯度主动在场把后台成果带回前台
         ┌───────────────▼─────────────────────────────┐
         │  第四层  micro_act(20s) → mumble(45s) → proactive(90s)│
         └─────────────────────────────────────────────┘
```

后台自进化与前台舞台演出**解耦**：后台只负责产出思想（第一层），前台（Role 2/3）负责决定何时、
以何种方式把思想呈现出来（第四层）。这条解耦线是整套系统的脊椎。

## 3. 架构决策（Role 0 拍板，Roles 必须遵守）

### 3.1 保留现有结构，最小侵入扩展

V2 **不重建**现有系统，而是在其上做加法：

| 现有实现 | V2 扩展 | 归属 |
|---|---|---|
| `self_state`（`server/memory/store.py`）| `taste/worldview` 富化为 `self_identity_ledger`（加 `id/confidence/support/counterexamples/status/history`，旧字段保留可读）| Role 1 |
| `self_state.curiosity_seeds`（JSON `[{text,heat}]`）| 升级为独立 `seeds` 表（父子/状态/历史），旧 JSON 一次性迁移后保留只读 | Role 1 |
| `bias_block()`（`server/persona.py`）| 扩为叙事注入（心境 + 昼夜 + 执念 + 潜在异议），签名加法兼容 | Role 1 |
| `starmap_graph()` 计算边 | 新增 `seed/reflection/ledger/mood` 节点；`parent_child/epiphany` 边**持久化**，其余派生边保持计算 | Role 1 + Role 3 |
| `SelfEvolutionCycle`（`server/assistant/loop.py`）| 升级为“反思 + 强制裂变”的有界循环，保留 trace/不抛异常契约 | Role 1 |
| `lru_cache` 配置 | 叠加 `config/*.local.yaml` 无痕热重载层，`persona_cfg()` 等接口不变 | Role 1 |
| `deliver_reply()` / 固定回复交付器 | 承载 `mumble/proactive` 的语音交付；`micro_act` 走舞台事件 | Role 2 |

### 3.2 Seed 如何演化（第一层）

Seed 不是一次性待办，而是一颗能反复审视、与记忆碰撞、衍生子问题、拥有完整思想历史的节点。

1. 每轮自进化循环从**当前种子**里选一个具体问题。
2. Workspace Osmosis 在数据边界内选取相关材料（语义相关、新颖、跨时间、未解决程度优先，不是全量读取）。
3. LLM 完成一次**有证据来源的第一人称反思**，产出一个 `Reflection Record`。
4. 反思识别一个新发现/矛盾/盲点/跨域联系，据此派生 **1~2 个真正不同的子种子**（Self-Forking）。
5. 反思、来源引用、种子状态变化、父子关系、`epiphany` 连线全部持久化。
6. **原有种子不因一次反思删除**，进入 `digested/dormant` 等状态，保留历史，允许日后重新激活。

硬规则：一次成功反思必须产生 1~2 个有效子种子；缺子种子/格式错/重复/无实质区别 → 进入校验与
**有限重试**，绝不把空结果标成功；模型故障或持久化失败时保留待处理任务与错误状态，绝不记为已消化；
必须做去重与相似问题检查，防止近义节点无限繁殖；每个子种子必须带可解释的产生理由与来源引用。

Seed 生命周期：`active → incubating / digested / dormant → archived`，终态可逆（可重新激活），
不是“用完即弃”。`heat/cooldown/last_reflected_at` 只影响调度顺序，不代表思想深度或性格。

### 3.3 心境如何跨轮次延续（第二层）

新增 `mood_state` 持久化（单行当前心境 + 可选历史）。记录：当前心境自然语言描述、产生原因与来源
引用、产生时间与有效期、近期相关互动/后台思考摘要、下一轮人格注入时该如何延续或淡化、已被消化/
自然缓和的状态。

约束：换话题后保留少量余温但以当前话题为主；刷新/重连/重开**不清空**持久化心境；有效期结束自然
衰减或重估，不突然切换成相反性格；不把推测性情绪当作对用户心理的确定诊断；不利用心境惩罚用户、
制造负罪感或阻止用户结束互动。默认有效期 30 分钟，只作控制阀门。

### 3.4 审美如何沉淀（第三层）

`self_identity_ledger` 初期目标沉淀 3~5 条有连续性的审美/观点倾向，由真实反思、历史互动与持续验证
逐渐形成。自然语言是人格主体，`confidence` 只是管理成熟度的辅助指标，**不得反过来直接决定性格**。
每轮自进化可决定：新增候选、补充支持证据、发现观点冲突、因反例降可信度、合并重复、修正/归档过时观点。
**不要求每轮都改账本**——真正的独立性不等于每天都必须产生新执念。

`Gentle Pushback`：当用户话题与既有观点相关时，允许她提出不同审美判断、指出方案与目标的张力、
给出有理由的反差建议、必要时提个小范围对照实验。允许不同意但**必须有理由**；观点不相关时不强行
把话题拉回自己的执念，更不演成无意义对抗。

### 3.5 后台成果如何通过三梯度回到前台（第四层）

| 梯度 | 触发（默认）| 事件名 | 渠道 | 内容来源 |
|---|---|---|---|---|
| 1 | 连续空闲 20s | `micro_act` | 无声舞台微动作 | 适合当前心境与形象的微表情/动作；不发声 |
| 2 | 连续空闲 45s | `mumble` | 轻声碎碎念 + 可选微光气泡 | 优先用当前真实思考/心境/灵感；可忽略/可接话 |
| 3 | 连续空闲 90s 或返回 | `proactive` | 有内容价值的主动发言 | 最近新发现/新子种子/值得分享的顿悟/未说的灵感 |

固定台词只作示例或模型不可用时的降级素材，**不能成为自进化的替代品**。后台没有形成有价值的新成果时，
**不允许**声称自己完成了反思、发现了联系或准备了礼物。

### 3.6 昼夜节律如何注入

`server/persona.py` 基于**配置时区**的当前本地时间，生成时间段的自然语言背景（晨间微困、日间清晰、
晚间松弛、23:00 后轻柔感性），作为影响表达的背景，而非硬编码台词。时区可配置，前后端对同一时段
判断一致，**不得**把服务器时区直接当用户时区。

## 4. 无痕热修改与偏好学习

- **本地配置热重载**：监听 `config/*.local.yaml`（已加入 `.gitignore`），mtime 变化 → 重新解析校验 →
  原子切换到新快照；校验失败继续用上一份有效配置并记内部错误日志；不因配置损坏退出服务；高频变更防抖；
  异步/线程安全读取一致快照；默认配置与本地覆盖优先级明确；**不打印**“配置已更新”等机械提示；
  不把本地配置敏感内容打进普通日志。**不得**实现成只在启动时读一次。
- **自然语言偏好学习**（`preference.py`）：从自然对话中识别稳定偏好、反感项、风格反馈、审美倾向并融入
  人格演化。不得因一次偶然表达就永久改变人格；区分明确偏好/弱信号/临时情绪/未验证推断；设置信阈值、
  防抖与更新幅度上限；持久偏好与临时心境分开存；可调 Seed 调度权重但**不用权重直接决定性格文案**；
  后台调整无痕；用户要求查看/管理偏好时提供检查与修正入口。

## 5. 数据模型与迁移（详见 PROTOCOL.md §14-18）

新增表（加法，`SCHEMA_VERSION` 保持加法语义，旧库打开时补空表）：

- `seeds`：好奇心树节点（替代 `curiosity_seeds` JSON 成为唯一真源）。
- `reflections`：第一人称反思记录。
- `graph_edges`：**持久化**的 `parent_child` / `epiphany` 边（其余边仍由 `starmap_graph` 现算）。
- `mood_state`：当前心境余温（单行）。
- `self_state` 表 `taste/worldview` 条目的 JSON 富化（加字段，旧字段可读）。

迁移：打开旧库时，`curiosity_seeds` 的每条 `{text,heat}` 迁成 `seeds` 行（`status=active, question=text,
id=seed_<hash>`，保留原文本），随后旧 JSON 保留只读一版用于回滚。初始五颗种子来自 `config/seeds.yaml`，
仅在 `seeds` 为空时播种，不覆盖已有演化。

## 6. 配置面

- `config/seeds.yaml`：初始五颗种子池（V2 新增）。
- `config/response_examples.json`：`stage_samples`（`touch_head/touch_face/idle_mumble/idle_proactive/memory_spark_weave`）。
- `config/pacing.yaml`：`voice_delivery`（rate/pitch）、`speech` 重新调参、`ambient`（三梯度阈值）。
- `config/memory.yaml`：`self_evolution` 增 V2 键（裂变上下限、Osmosis 上限、去重阈值、mood、circadian.timezone）。
- `config/*.local.yaml`：本地私有覆盖，热重载，gitignored。

## 7. 验收判据（可执行；详见 docs/TASKS.md）

**自进化与种子**
- 初始五颗种子正确加载；一次成功反思生成 1~2 个有效子种子；子种子可追溯父种子/反思/原始来源。
- 已消化种子保留历史并可条件重新激活；同一问题不会繁殖成大量近义种子。
- 反思失败/模型故障/写库失败时，整轮**不得**被标为成功。
- 至少一个测试证明：能通过 Seed + 历史日记 + 用户 Note 的跨来源信息形成一条有效 `epiphany` 边。

**人格与心境**
- `persona.py` 读真实时间上下文；前一轮有效心境跨刷新/跨轮次保留；过期后自然衰减不无限维持。
- 自然语言叙事优先于固定性格数值；审美账本能记来源、接受反例、修正观点；相关时能温和反驳、不相关时不机械唱反调。

**热修改与偏好**
- 改本地覆盖后无需重启即生效；无效配置不覆盖上一份有效配置；修改不向用户输出机械确认；重复相同偏好信号不累加；能区分明确反馈与低置信推断。

**主动在场**
- 20s/45s/90s 分别对应正确事件；同一空闲周期不刷屏/不重复播放；用户重新活动后过期事件被取消或重估；
  `mumble` 可忽略或接话；`proactive` 成果可追溯到真实反思或星图节点；后台无新成果时不虚构发现。

**语音与 UI**
- 首包切分参数准确生效；流式切分不破坏语义和标点；星图能显示种子裂变关系与顿悟边；气泡/触摸调用统一事件接口；刷新/重连不制造虚假节点或重复演出。

不能只凭人工演示判断通过，至少提供单元/集成测试或可复现验证记录。
