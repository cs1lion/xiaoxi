# 非理想声学模拟：结果与放行边界

## 方法

脚本 `node scripts/simulate-duplex-stress.mjs`，输出 `eval/duplex-stress.json`。
12场景×3自动模式×5个确定性种子=180次模拟，每次4秒，20ms输入帧。远端/近端为独立低通伪随机波形，不是真实语音；幅度未校准成声压。每次只考察首次抢话，不将比例换算成每小时误触发率。没有模拟浏览器AEC、压低音量后的声学闭环、真实声卡或房间，因此是Gate输入层压力探针，不是完整端到端声学基准。

## 结果

三种自动模式在各场景的成功/失败次数一致，仅确认持续讲话的时长不同。

| 场景 | 每种模式5次的结果 |
|---|---|
| 单路径40ms回声 | 0次误抢话 |
| 非搜索网格精确对齐的40.4375ms回声 | 0次误抢话 |
| 低幅背景噪声叠加回声 | 0次误抢话 |
| 回声延迟中途改变 | 0次误抢话 |
| 限幅至0.018的回声 | 0次误抢话；限幅本身也降低音量，不能视为解决失真 |
| 多路径混响 | 5次误抢话 |
| 260ms回声（超过200ms搜索） | 5次误抢话 |
| 无播放参照但有回声 | 5次误抢话 |
| 高幅持续噪声，无近端用户 | 5次误抢话 |
| 较强独立近端叠加回声 | 5次检出：420/600/300ms |
| 很弱近端叠加回声 | 5次漏检 |
| 混响后再加入近端 | 5次在用户开始前已经误抢话，不能算成功检出 |

“外放保守”只是更长的时间确认，不等于更强声学模型。现有能量+单延迟线性相关无法解决多路径、噪声与很弱双讲，不应仅调低相关阈值让数据好看，可能进一步吞掉真实近端。

## 本轮改动

增加可选策略“播放时仅按键打断”：播放及260ms尾保护内不自动duck/抢话，按住麦克风按钮/空格仍可主动接管；播放完后仍保留连续收句。它是明确降级，不是真全双工，不自动开启，也不能保证播放结束后持续背景噪声不触发普通能量VAD。

已验证45项模块测试、16组页面模拟检查通过。压力场景中的自动模式失败仍保留，未篡改判定标准。

## 推荐放行范围

- 耳机安静环境：可继续实验试用，但要记录真实误抢话、漏检。
- 外放/混响/持续噪声：不建议默认语音抢话常驻；不稳定时用按键模式。
- 尚未做真实中文语音、录音设备、云ASR/TTS端到端验收。

## 下一步应替换哪层

1. 用真实但经用户同意的本地回声/双讲话音数据集评估，默认不上传或保存诊断原音。
2. 神经VAD识别语音而非仅能量；仍不能独自区分助手回声和用户。
3. 验证浏览器实际AEC设置和参照链路，再考虑成熟AEC/多路径自适应回声方案；加双讲保护，不在用户讲话时错误学习。
4. 用独立保留集同时看误抢话率与近端漏检率，不能只优化其中一个。
