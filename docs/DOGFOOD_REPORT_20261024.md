# DOGFOOD_REPORT — 自动化 dogfood（2026-10-24）

**方式：** 用户授权以合成语音替代人工 dogfood。SAPI Huihui 把 8 句话合成 16k 单声道 WAV
（`tmp/dogfood/`），Playwright 假麦克风喂给**常驻真实服务**（8000，当前 master），
走真实 VAD→ASR→快环→TTS 回放→记忆→委托→断线重连全链。
脚本：`scripts/dogfood-sim.mjs`（一天长跑）、`scripts/dogfood-sim-v3.mjs`（委托闭环聚焦）。
原始帧时间线：`eval/dogfood/frames.json`、`eval/dogfood/report.json`、`eval/dogfood/*.png`。

## 验证通过的（真实链路，非 Mock）

- **真实 ASR 对合成语音**：识别率良好，误差在「小溪→小西」级别；文本入会话账。
- **负向约束在真机成立**：库中无猫记忆时，她答「猫的名字我没印象了，你再说一遍？」——没有脑补。
- **记忆写入可见**：「我最近喜欢在傍晚出去散步」→ 记忆库真写入 → 同轮回复引用「傍晚散步挺好的」。
- **断线重连 + resume**（F4 真机验证）：`setOffline` 3 秒逼出断开 → 自动重连 → ready 帧回**原** session_id → 后续消息与断线前同账（sessions=[1 个]）。
- **打断**：多轮按住/松开重叠时 `interrupted` 帧正常触发（7 次），无页面错误。
- **接口面**：`/api/memories`、`/api/executive/commissions`、`/api/session/*/transcript` 全 200。

## 发现（按严重度）

### D1 · 委托路由对 ASR 词形过于脆弱（高）

`service.should_route` 的正则 `帮我(?:整理|写|安排|计划)` 是**前缀敏感**匹配。
真实语音 ASR 掉一个「帮我」（实测：「安排一个沙盒打样，生成并校验一个小文件吧。」）
→ 整句不路由到工具路径 → 任务根本不建单，且她回
「我没有工具权限，没法直接生成或校验文件。你得手动来，或者给我开权限。」

两个问题叠在一起：**路由脆**（一个助词丢失即失效）+ **文案误导**（真相是没路由，不是没权限，
且「你得手动来」把责任推给用户）。语音是主交互通道时这是日常高频路径。

### D2 · 语音不能完成确认，README 的「语音确认」与实现不符（中）

委托确认走 `waiting_confirmation` + 卡片按钮 `assistant_confirm`（协议 §118 不可逆动作须显式点击，
设计合理）；但 README 写「复杂委托→语音确认」。实测语音说「确认，就这样安排吧」只被当普通对话
（答「行，就这么定了」），单子仍不建。语音优先的产品里，用户的第一反应是说「确认」——需要
要么支持语音确认、要么把「请在卡片上点确认」说清楚。

### D3 · `/api/memories` 在老进程上 500（已随重启消失，记录在案）

10-21 启动的常驻进程上该端点 500，当前 master 代码对同一库副本正常（1 条记忆）、重启后 200。
结论：长期不重启的进程会漂移出不可服务状态；建议交付说明写明「升级后需重启服务」。

### D4 · 长语音被 30s 上限强切且不自动续录（低，设计内）

按住超过 30 秒会被 max-duration 切断，之后同一次按住不恢复录音。按住说话的模型下合理，
但连续说多句的用户会丢内容。交付说明里写明「一句一按」。

### D5 · 假麦克风每次按下从文件头重播（工具限制，非产品问题）

v2 逐句模拟因此每句都听到开头问候；v3 改为一句一实例规避。记录以备复用。

## 结论

核心链路（真实 ASR、记忆、负向约束、重连续会话、打断）在真机全绿；**唯一硬伤是委托入口的
鲁棒性（D1）与语音确认口径（D2）**。D1 建议在 Phase 4 后单独开票修（正则放宽 + 文案区分
「没路由到工具」与「无权限」），D2 需要产品口径决策（支持语音确认 or 明示点卡片）。
