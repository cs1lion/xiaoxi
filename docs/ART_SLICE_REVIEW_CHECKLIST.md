### 1.4 角色亮部最低规则

- 围巾 W15 与皮肤 W12 的亮边**原生 ≥2px**（400% 下视觉 ≥8px 块）。
- 眼睛 1px 可接受，但必须贴 ≥2px 皮肤块，不孤立悬浮。
- 旧斗篷亮部 `#3f6584` 并入 W13 后不得只剩 1px 孤点：补 1px 高光或删掉该亮部层。
- 多角色同框时角色之间亮部不粘连（间隔 ≥2px 暗部或留白）。

### 1.5 雨天用色纪律

- 雨滴 / splash / 烟统一 W16 `#d8dad3`（对最暗 W01 约 13.34:1）。
- 主角可读靠 W11 `#e3a13c` + W12 `#e0b48c`。
- 雨幕压暗用 W14 `#223a4d`，**alpha ≤ 0.28**；明令禁止用 W01 压雨（雨幕会发绿）。
- 雨天地面对比参考：主角亮部 ≥2 个相邻像素块可辨，雨幕 400% 无双灰阶色带。

### 1.6 已采纳的映射修正

1. `#8f7a4c`（祭坛/脚手架暖黄）→ **W10 `#c9a86a`**，不并 W09（色相偏暖）。
2. `#2f3b33`（定义槽，refs=0）→ **W03 `#2d3b2e`**，不并 W04（明度更稳）。
3. `#6b7c9c`（墨点）→ **W14 `#223a4d`**，不并 W01（太蓝）。

## 2. task-30 必拍 6 张（原生 480×320，各出 100% / 200% / 400% 最近邻）

### 2.1 拍摄前置（缺一项则这组图不作证据）

1. **清 localStorage**（否则旧存档的 `PlacedBuilding.palette` 会带旧色进画面，见架构审查 1-A）。
2. **zoom 处理**：`main.ts` 默认 zoom 2；原生帧需临时 `zoom=1`，或 960×640 最近邻降采样并在报告里写明方法。
3. **暂停固定帧 + 雨滴固定种子**（`weather.ts` 用 `Math.random`）：否则每张雨帧都不同，不可比。
4. **元素截图，勿 `toDataURL()`**（WebGL 下黑屏）。
5. 晴 / 雨 / 夜三组用**同一构图**。

### 2.2 清单与判定

| # | 切片 | 拍什么 | 判定标准 |
|---|---|---|---|
| 1 | 晴天正午 | 三栋建筑同框，100/200/400 | **人类项（待用户评审）**：用户 3 秒指认 forge / archive / workshop；**客观项**：三栋剪影高差 ≥2px、识别色互不相同（W11 窗光 / W10 饰边 / W16 浅饰边 / W13 冷屋顶）；建筑主体 vs 相邻地面 WCAG 对比度按实测取色点写进报告，**不设统一硬阈值**（低对比区必须在 400% 截图里仍能分清轮廓，否则记为风险，不阻断评审） |
| 2 | 雨天后 | 主角在路径上，100/200/400 | **人类项**：3 秒指认主角；**客观项**：雨幕 400% 无 ≥3px 色带；主角亮部 ≥2px 块 |
| 3 | 多角色 | ≥3 个 villager 同框 idle/walk 两帧，100/400 + smoke 两帧 | 客观项：两帧差异肉眼可辨（人工看帧差异，非 AI 判定）；角色间亮部不粘连 |
| 4 | 气泡出现/消失 | 两帧，100/400 | 客观项：DOM overlay 位置稳定、无 1px 抖动；文字 ≥8px 等效字号；气泡底/字号与 canvas 像素块同尺度 |
| 5 | 390px 窄视口 | 页面整图，100/200 | 客观项：布局不溢出、overlay 可读（overlay 自身不溢出；页面级 960px canvas 溢出属既有 P3） |
| 6 | 夜景只读试验 | 1.0 不做昼夜；同一基帧按写明公式（如 W14/W01 分别 α=0.40/0.50）离线合成，100/400 | **试验项**：路径/农田/石面明度差 ≥1.1:1 才算可辨 |

### 2.3 判定口径

- **色带**：400% 下同一色块内出现 ≥2 个不同灰阶条带即 FAIL（色带用抖动解决，不加色）。
- **DOM 割裂**：400% 下 overlay 文字/底色与 canvas 像素块尺度不咬合（文字 1px 缝、底色 3px 台阶）即 FAIL；此项按 D5-A 触发 ADR 调整。
- **人类项**：不以 Bot 或 AI 的「3 秒指认」冒充人类样本；报告只写「待用户评审」。本仓库唯一人类评审者是用户。
- **对比度**：按 WCAG 相对亮度比计算，报告写明公式与取色点。

## 3. 夜景与加色边界

- 1.0 不做昼夜循环（`README` 已记），夜景只是只读试验。
- 试验失败（明度差 <1.1:1 或路径并团）→ 记「16 色不支持夜景、需要 18 色」，**不擅自加色**。
- 任何加色（第 17 / 18 色）必须：截图证据 + ADR + 用户批准；`--strict` 会挡住未改预算的加色。

## 4. 未决与风险

- **workshop 识别度**：16 色下靠 W13 冷色屋顶，若切片评审失败 → ADR 裁量（18 色或改剪影）。
- **3 秒指认人类样本**：原方案要求「≥3 人」，实际只有用户一位人类评审者，本清单已改为用户判定；不得把 AI 判定写成人类结论。
- **截图唯一色数**：不作为验收口径；只有源码色数（16 / 8）可被脚本断言。
- 本文件不替代 task-30 的实测报告与截图归档；通过与否以实测证据 + 用户评审为准。
