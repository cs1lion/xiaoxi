# 记忆组合设计：范围、依据、时间与使用

2026-10-13。设计与实施顺序，基于[语音搭档与记忆实践](VOICE_COMPANION_MEMORY_PRACTICES_20261013.md)及静态源码审查。后续用户要求继续，第一增量已落实共享上下文、有效候选查询和文本签名缓存，详见[代码与离线验收](MEMORY_CONTEXT_DELIVERY.md)。项目 schema、完整时间和跨域管理仍是设计。

## 1. 要深化的判断

长期记忆的目标是让过去的信息在正确的对象、范围和时间条件下帮助当前讨论。评价看减少重复交代、保持决定连续、改善成果、允许纠正和遗忘，以及语音等待与管理负担。

“提取记忆”应拆成两项能力：从对话中提出值得保存的候选；在当前问题下找回可用证据。它们之间还有准入、归属、版本和生命周期管理，之后还有生成模型是否正确使用。因此分别记录抽错、存错、范围错、未找到和使用错误。

跨会话接续同一项目与跨项目迁移是两种能力。同一项目可以持续使用其有效决定；迁移到其他项目需要验证适用条件。项目内结论不能仅因多次出现就变成用户通用偏好或通用方法。

## 2. 组合互补职责

| 组成部分 | 负责回答 | 设计约束 |
| --- | --- | --- |
| 原始证据与引用 | 谁在何时说过什么，哪个资料/回执支持它 | 原消息、明确保存的资料版本、真实执行回执保留独立来源；摘要不替代原记录 |
| 结构化声明及当前视图 | 当前知道什么，哪些是候选/冲突/已修订 | 事实、偏好、决定、计划、完成分清；明确同一对象/属性/范围及变化依据才修订 |
| 事件与过程记录 | 为什么这样定，经过哪些变化，还有什么没定 | 保留决定依据、未决问题、修订关系与当前成果版本；事项不是必须执行工具的任务 |
| 可重建索引与摘要 | 怎样以小成本找到相关材料 | 先约束范围、状态和时间，再排序；摘要用于导航，必要时展开原记录 |
| 共用上下文转换 | 各种对话路径怎样正确使用材料 | 同一来源、程度、时间和不确定性不能在路径切换时丢失；预算不足整条省略关键记录 |
| 用户管理与变更传播 | 用户怎样改、停用、限制范围和删除 | 区分停止使用与删除记录/原话；相关派生物和待写任务遵守维护结果 |

这些组成部分可以继续使用 SQLite 和现有服务。组合设计不要求重复存储多份权威事实，也不要求同时部署 Mem0、Graphiti、Letta 和 LangGraph。

自动提取可追加新观察，程序维护当前视图，历史回答再读取事件链；这几项互补。以下则是替代策略，需要同数据、同预算的对照：写入时维护当前状态与读取时解释变化；现有词法检索与词法+语义；规则比较与语义候选比较；关系索引与图数据库。

## 3. 分开来源、应用范围和事实时间

### 来源

来源记录原会话、原消息/资料/回执 ID 与版本，必要时记录输入发起时明确选择的事项/项目。输入发起时固定归属，不能等待模型返回后使用另一个当前选中项。现有 session_id 主要表示证据来源，不是完整项目隔离。

### 应用范围

- 用户通用：明确适用于多个场景的称呼、沟通和个人偏好。当前明确请求仍可覆盖当轮行为。
- 项目或事项：该目标下的约束、预算、选项、决定、资料、当前稿和进度。
- 当前会话/当轮：暂时需求、探索性想法和临时解释材料。
- 可复用经验：带来源和适用条件的方法/模板；从项目结论提炼成经验要保留候选与用户认可过程。

范围是与内容类型独立的维度：偏好也可只属于一个项目，事实也可只描述过去某个时点。来源在项目 A，不表示一定只能在 A 使用；能够在 B 参考，也不表示它已成为 B 的决定。

先使用已有稳定事项 ID 支持事项内跨会话接续。事项与项目不等同；确有多个事项归属同一项目时再引入稳定 project ID 与关联。主题名“项目”不是 project ID，也不授予隔离或迁移能力。旧记录范围未知时标记未知，不批量猜归属或自动升为用户通用。

优先级用于同维度行为约束：当前明确请求 → 匹配范围内最具体的有效约束/偏好 → 用户通用默认 → 角色默认。事实查询按所问对象和时点选择证据，不采用“更具体的一条总能覆盖其他事实”的泛化规则。

### 时间

区分原话时间、事件发生时间、系统写入时间和已知有效期间。更新较新不证明事实发生较晚；消息晚到也不能推翻较新纠正。近期自述保留时间锚点，未确认延续不等于已过期。

“本周准备联系客户”是计划，“我周五联系过了”是用户完成陈述，工具发送回执只证明其验证范围。截止日过去不会自动把计划升级为完成。时间或含义无法确定时保留未知，必要时澄清。

## 4. 写入与读取的最小流程

写入：原记录先落地 → 模型提出小量候选 → 程序校验身份/角色/范围/字段/证据 → 新增、重复、修订或冲突 → 更新当前视图及派生物。较慢整理可后台运行；显式保存仍以真实落库结果反馈。

程序可以核对真实 ID、逐字证据和已知范围，不能仅用子串证明代词归属、同义属性、语义支持或真正互斥。模型负责提出这些解释，最终写入权限仍受程序约束。有限偏好规则不等于普遍语义理解。

读取：判断当前问题需要什么 → 按明确范围/状态/时间构造候选 → 精确引用或词法检索 → 必要时语义召回/重排 → 展开少量原记录 → 共用上下文转换 → 回答及可打开的依据。

直接找指定稿件版本、决定 ID 或回执不需要先经过相似度搜索。改写检索问题和摘要属于派生数据，不反向成为用户事实。简单问题使用较小预算，涉及决定变化和跨会话依据时再逐步展开。

跨项目复用优先复用带来源的引用与有条件经验，不复制成多份独立权威记录；这样纠正和删除才能沿依赖关系传播。每轮不必新增一条用户可见记忆卡；范围提升或歧义影响结果时再确认。

## 5. 改动前诊断与第一项改动

改动前普通聊天已携带有限偏好程度、时间范围和原话日期，行动助手省略这些信息及 evidence_state。现 [presentation.py](../server/memory/presentation.py)已统一记忆记录的上下文投影，两条路径分别沿用原预算。以下保留诊断和实施边界，不代表缺口仍全部存在。

第一项改动的边界：

1. 使用共享纯转换函数，将原记录转成有预算的模型可用数据；不在转换函数导入全局库、抽取器或默认服务。
2. 两条路径保留主体、来源、证据状态、偏好对象/程度/时间限定，以及可验证原记录引用。完整原话可按需查看，不必每轮大量注入。
3. linked 表示已关联原话，不表示完整语义一定正确；manual 表示用户手动保存而未关联原话，不冒称“原话曾这样说”；legacy 保留未知来源提示。不要把所有手动记录都变成每轮必须重新确认。
4. 保留开关关闭时零读取、敏感字段抑制、时间有限数值校验、来源及权限隔离。关键限定不能被预算裁掉后只留下主体结论。
5. 当前 retriever 使用 assistant.context 的文本过滤函数。抽出共享转换时使用中立依赖，避免 context 再反向导入 retriever 形成循环。

另有两个静态确认的检索缺口，现已纳入第一增量修复；下文是改动前机制：

- 索引取最近 5000 条 active，候选取最近 5000 条所有状态再排除历史。大量较新历史/冲突可以挤掉较旧但有效的候选，两个集合不一致：[retriever.py](../server/memory/retriever.py#L62)、[store.py](../server/memory/store.py#L446)。历史数量不应改变同一有效记录集合的召回。
- 索引依赖 store.version；原消息写入和使用统计也可改变该版本，造成不涉及记忆内容的索引失效。先测冷启动/内容变更/仅读统计，再拆内容版本和增量更新。没有规模测试，本轮不声称已测出慢或指定性能收益。

第一增量完成时尚无确认决定请求的持久追溯，后续第二增量已补本地请求快照和事件版本。普通记忆的完整项目范围、每事项完整资料引用集合、完整聊天消息引用链和跨域删除传播仍未实现，不能因存在 session_id 或主页事项入口就称已经完成。

### 第三增量：明确范围下复用

先启用明确用户通用信息与事项内记录分开使用，再按真实需求引入项目身份和有条件经验引用。新增范围/版本/删除依赖契约，旧数据不猜补。完成两项目切换反例后，才扩大跨项目迁移。

### 第四增量：按失败证据优化检索

取得同一记忆集的分层基线，再对照摘要展开、混合检索和关系索引。先修候选集合、过滤与内容版本失效粒度；有同义表达漏检才评估向量，有关系链漏检才评估图查询。预算和检索集合保持一致，分开报告能力增益与额外成本。

以下是拟定验收场景，不是本轮已通过测试：

| 场景 | 期望 |
| --- | --- |
| 长期最爱绿茶，最近也喜欢红茶 | 并存并保留程度、原话时间，近期回答不过度泛化 |
| 平时喜欢短答，本轮明确要详细设计 | 当轮展开，长期偏好不被永久改写 |
| A 项目用 PostgreSQL，B 用 MySQL | 分别归属；在 B 不把 A 当作当前决定 |
| 未决方案 A，后确认 B，再问为什么 | 区分曾讨论与已决定，能找回真实理由 |
| 计划联系客户，日期已过但无结果 | 不推定完成，明确现有证据范围 |
| 改口后旧抽取晚到；删除后重开/新会话 | 旧结果不覆盖或复活，派生物停止影响 |
| 旧有效信息前面新增大量历史记录 | 候选集合正确，不因状态混合上限漏掉有效条目 |
| 无关/矛盾/范围未知材料 | 按契约排除或说明不确定，避免伪造回忆 |

分别记录写入语义支持、范围/版本正确、证据召回、最终回答支持程度、删除/纠正行为、后台写入可见延迟、检索 p50/p95 与语音首段额外等待。另记录用户重讲和无必要确认次数。

当前会话无长期记忆、现有系统记忆、人工核验相关证据三组用于定位瓶颈；人工材料组只是诊断上限。冻结真实输出重放只验证程序，真实语义评分另行记录。新真实模型运行应使用固定保留题、重复样本和已获授权的预算；本轮没有追加调用。

管理入口在后续增量中逐步加入“这条适用哪里、何时说过、为什么使用、怎样纠正/停止使用/删除”。继续区分删除记忆与原对话、备份等生命周期，把底层复杂度留给系统，保持语音交流的低负担。
