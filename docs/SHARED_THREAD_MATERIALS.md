# 同一事项的资料、当前稿与成果

2026-10-14 实施记录。事项现在明确关联笔记的固定保存版本与用途。用户切到事项 B 后，个人笔记仍选着 A 时，系统不会把 A 当作 B 的稿件。

## 使用流程

在事项页「本事项资料」搜索已有笔记，选择保存版本及用途，再点击「关联到本事项」。查找、打开、预览不建立关联，也不改变个人笔记选择。每事项最多 12 份资料，只能有一份当前稿。

| 用途 | 使用方式 | 含义边界 |
| --- | --- | --- |
| 参考资料 `reference` | 默认只列元信息；明确要求「参考本事项资料」等才读固定版正文 | 不进入默认笔记修改流程，不授予编辑或执行权 |
| 当前稿 `draft` | 「解释这份笔记」「修改这份稿」等使用本事项唯一当前稿 | 无当前稿时说明缺少关联，不替用个人笔记或参考资料 |
| 成果 `artifact` | 用户明确指定某保存版为成果；正文仍按参考请求读取 | 不证明内容正确、事项完成、对外发布或实际阅读已发生 |

可修改同一笔记的关联版本或用途、解除关联。缺失的笔记保留关联项以便解除，不换成别的笔记。解除只移除关系，笔记及保存版本保留。保存新版不会自动更新材料版本、添加成果或标记事项完成。

没有选定共同事项时，沿用个人笔记页的显式版本选择。个人选择继续独立保存；有事项时不把两个选择自动组合成归属。主页「此刻」显示实际作用域、稿件和旧版提示；笔记页解释个人关联与事项当前稿的区别。

## 保存与范围契约

`thread_materials` 位于 `threads.db`，字段为 link ID、事项 ID、笔记 ID、固定版本、用途及建立/更新时间。外键使删除事项清除关联项，但不删笔记。数据库唯一约束保证每事项只有一个当前稿、同一笔记版本不能重复指定多种用途；改变用途需明确更新已有关系。

关联、更新和解除均需明确 `thread_id + expected_revision`，关系变更和事项 revision 递增在同事务内提交。相同 ID/版本/用途的精确重复请求在通过 CAS 后不再递增 revision；冲突不自动重试。旧库建立空材料集合，不根据个人选择、更新时间或历史事件引用猜补归属。历史事件中的旧笔记引用不被当前关系变化改写。

API：

| 操作 | 路由 |
| --- | --- |
| 列资料 | `GET /api/threads/{tid}/materials` |
| 关联保存版 | `POST /api/threads/{tid}/materials` |
| 改固定版或用途 | `PATCH /api/threads/{tid}/materials/{mid}` |
| 解除 | `POST /api/threads/{tid}/materials/{mid}/remove` |

成功返回 `{thread_id, revision, items}`，材料包含固定版标题、笔记当前版本和 `selected/stale/missing` 状态，`Cache-Control: no-store`。服务检查真正存在的笔记保存版，客户端不能提交正文、来源证据或授权字段。路由保留同源写入校验。409 保留页面待关联资料及编辑字段，需要用户核对后重新提交。

## 模型读取与候选

`ActivityFacade.working_source()` 先捕获事项，再定位其唯一当前稿，保存 `scope/thread_id/thread_revision/material_id/ref/purpose/status`。续答、候选与保存都使用原身份。切换事项不会改变已发请求的归属；解除、换固定版本、改变用途或删除原笔记后，后续读取及保存前校验失败，不改用新选择。失败候选草稿保留，可拒绝；读取、修改和确认返回 409 `draft_source_changed`，确认不会消费候选或保存笔记。

修改候选展示原作用域。事项候选保存后只打开精确新版本，并提供原事项资料入口；不会出现个人关联按钮。实际 `note.update` 回执仍记到原事项，准确引用保存的新版本；回执不是自动登记为成果。事务跨两个 SQLite 库，笔记保存成功后事项回执失败会明确提示，不重做保存。

确认时持有事项库的材料事务守卫，核对 link ID、稿件 ID/版本及 draft 用途，直到笔记 CAS 提交结束；另一连接的解除、换用途/版本或删除事项与保存串行。撤销先发生就拒绝保存，保存先发生则是真实成功，后续撤销另行生效。守卫不递增事项 revision，也不跨模型等待；释放后才写成果回执，避免嵌套事务。旧行动运行若只有事项 ID 与个人笔记引用、没有明确材料来源，不猜补归属，也不继续读旧正文；无事项的旧个人流程仍保留。

普通闲聊不读材料正文。明确参考事项资料时，读取参考/成果用途的至多 3 份固定版，正文合计最多 4000 字，凭据在截断前过滤，标明截断、缺失与省略数量。当前稿正文另沿用 4000 字限制。2026-10-14 后续已增加[最终动态上下文预算](CONTEXT_BUDGET_AND_USAGE.md)，在这些分域限制之后统一收口；仍不是完整提示、token 或费用上限。元信息不复制正文，参考资料作为不可信 user 数据消息，不变成行为指令、写权限、聊天记录或记忆提取证据。

关闭记忆时，这些模型入口零读取。用户主动打开事项管理页、保存或解除材料属于明确本地管理操作，沿用原界面行为。显式 `note.search/read` 工具仍可按明确 ID 查单用户笔记库；本轮实现自动上下文范围，未将本地单用户库改成多用户/多项目权限隔离。

已经发送给模型的内容无法撤回。普通笔记与材料读取不是跨库原子快照；确认保存额外持有上述材料守卫，但不宣称关系撤销能回收已读内容。没有增加向量库、图数据库、后台扫描或付费调用。

## 验证与实际试用

检查重点是：B 无当前稿时不读个人 A；A/B 同一笔记不同固定版不串稿；换选不重定向原候选；解除/改用途/改版本后不继续读写；新保存版不自动升关联；缺失与关闭时不回退；409 草稿保留；解除不删笔记、删除事项级联清关系。
