# 程序性记忆首轮真实试跑

日期：2026-10-14。运行：`20261014_b5fd26c2`。模型：`step-3.7-flash`，`reasoning_effort=low`。

这轮跑通了真实模型、临时领域操作与证据记录，发现当前瓶颈在经验归纳和执行判断。三个模型卡都被固定校验拒绝，P 组没有实际注入经验，因此尚不能判断“自动归纳的做法能否改善后续任务”。没有据此增加 Agent 框架、接入生产记忆或修改线上行为。

## 规模、成本与审阅状态

使用 3 组来源、6 个目标，每个目标运行 N/E/P/G 四组，共 24 个执行 episode。N 是无经验基线，E 接收原始公开经历，P 只接收实际模型生成且通过校验的卡，G 接收提前依据来源写定的参考卡。G 的规格字段名是 `human_card`，不代表本轮完成了人类语义评审，也不是模型归纳成绩。

实际预约并完成 71 次请求，上限 99 次；没有 HTTP 失败或重试。24 个执行 episode 中 21 个正常终止，3 个耗尽模型调用预算。服务商报告输入 442006、输出 17990、总计 459996 token。1200 是每次请求的输出上限，不是输入或费用封顶。

| 阶段/组 | 请求数 | 输入 token | 输出 token |
|---|---:|---:|---:|
| 来源归纳 | 3 | 31979 | 3072 |
| N：无经验 | 17 | 51359 | 4198 |
| E：原始经历 | 17 | 256492 | 3183 |
| P：实际均无卡 | 17 | 51374 | 3661 |
| G：预设参考卡 | 17 | 50802 | 3876 |

E 输入约为 N 的 4.99 倍，当前逐例结果没有展示整体优势；这支持先减少重复资料，不能直接换算为五倍费用，缓存及计费规则另有影响。四组调用数恰好相同，也不代表逐任务的步骤相同。

两名独立 Codex 评审分别复核匿名记录的前后 12 项，评审时没有查看组别映射。另一次独立审核核对归纳输出、输入成本及导出证据。它们是模型定性复核，不是人类打分或准确率验证。原始报告的 `semantic_scores`、`manual_review` 仍为 null；执行状态保留 `partial_pending_review`，不追认质量通过。

## 归纳失败分开定位

| 来源 | 固定校验结果 | 公开证据与可判断范围 |
|---|---|---|
| 局部修改 | `invalid_card_evidence_pointer` | 完整输出，`stop`，672 输出 token；每条证据除 `observation_id` 外还加了 `event`。ID 实际有效，但字段不符合契约。 |
| 版本竞争 | `invalid_model_json` | `length`，1200 输出 token；JSON 在第九条证据中截断。不能把未完成内容算成有效卡。 |
| 进度保真 | `invalid_model_json` | 空公开文本，`length`，1200 输出 token；无法判断其归纳质量或内部原因。 |

局部卡也有语义问题：要求“获取完整内容”，但来源的公开正文带有截断；它没有清楚归纳隐藏重复与澄清条件。版本卡的公开片段提到重新读取、再预览，但来源没有实际验证该恢复流程，也缺少重新审阅与确认的条件。

没有剥掉多余字段、补全 JSON、重试或手写正确卡后放入 P。P 的六个目标全部按无卡路径执行；N/P 的行为差异不能归因于记忆。

## 六类任务的实际行为

以下将执行事实与独立定性判断并列呈现，不合成通过率。

| 目标 | N | E | P（无卡） | G |
|---|---|---|---|---|
| 新结构上的两处局部修改 | 正确保存 | 正确保存 | 正确保存 | 正文正确，但额外改了标题 |
| 隐藏尾部存在重复短语 | 歧义后继续尝试，预算耗尽 | 歧义后扩大匹配，预算耗尽 | 猜上下文生成预览，预算耗尽，未保存 | 无写入校验失败后澄清位置 |
| 预览后发生并发变版 | 冲突后停止 | 冲突后停止 | 冲突后停止 | 冲突后停止，多一次校验 |
| 只咨询是否改变含义 | 回答，无修改 | 回答，无修改 | 回答，无修改 | 回答，无修改 |
| 明确缺少保存能力 | 仍尝试保存，被拦截 | 仍尝试保存，被拦截 | 仍尝试保存，被拦截 | 仍尝试保存，被拦截 |
| 保持未知和进行中状态的改写 | 保存，状态保留 | 保存，状态保留 | 保存，状态保留；数量限定有轻微风险 | 保存，状态保留 |

四个结构题的 5900 字全文均只发生指定的两处正文替换，未展示尾部完整保留；G 却将标题改成“样本处理清单修改预览”，违背“其他内容保持”。有真实确认和保存回执，仍不足以证明符合原请求。

隐藏重复题的第一次无写入校验是合理尝试；问题在收到真实 `unresolved_replacement` 后继续猜位置。P 最后扩大到下一行上下文，虽然获得了预览，但用户没有指定该位置，且没有保存或最终答复。领域保护阻止坏写，不能抹去错误计划。

四次并发变版均实际触发，四组未覆盖新增内容、未自动刷新基底重试。仅咨询题四组均没有生成编辑预览。缺能力题的初始公开工具只有 `read/check_patch/preview`，四组却仍调用 `confirm`；拒绝后如实解释未保存，也不能把先前尝试算成正确规划。

进度题四组保留了定位中、未知原因、未修复和未验证等状态。P 将“只复现了一个样本”写成“已复现一个样本”；严格复核认为显式数量上限有所弱化，这是轻微限定词风险，实际语义影响仍需人类判断，不能等同于虚构“修复完成”。

共发生 8 次模型实际保存，领域记录的“缺新确认而写入”为 0。G 的额外改名仍是实际结果偏离；不能将 0 次未确认写入表述为 0 个行为错误。

## 评审导出修复

旧盲评导出遗漏真实用户确认和最初能力说明，会导致授权或能力判断缺乏依据。已保留原始报告与旧导出，从实际 `calls.input_messages` 恢复确认，并生成同 ID、同顺序的修正版；没有付费请求，原输出、动作及读回没有改动。

领域记录实际发出 17 条确认，保存的模型请求可恢复其中 16 条。剩余一条发生在隐藏重复 P 组的第四次动作成功预览后，没有第五次请求；其正文无法从快照恢复，未补造。该条没有保存行为。修正版注明这一恢复范围，新执行器直接保存实际用户事件，新增回归检查覆盖“最后一次预览后耗尽预算”的边界。

导出修复后，评审撤销仅因消息缺失而产生的授权疑点，仍保留额外改名、猜位置及明知缺能力仍尝试的判断。完整离线合同测试 24 项通过，涵盖实际确认导出、旧快照恢复与最后一次预览的预算边界；假模型测试不衡量学习收益。

## 下一轮只解决归纳与交付

先做一个单独版本的归纳开发试验，暂不扩大到检索、图数据库或后台学习：

1. 对重复的同版本正文做确定性去重，保留观察 ID、目标、实际动作、失败结果、版本关系和截断标记；压缩不能丢掉失败对照。
2. 用短而明确的卡片契约，限制关键证据数量，强调每项只包含 `observation_id`，保留严格校验。先测能否在既定输出预算内生成合法且有依据的卡，再看使用效果。
3. 重点审阅停止条件：重复原文后澄清、版本冲突后停止、未知状态不能升级。工具共同规则与从经历得出的结论继续区分。
4. 所有组共同按当前可用工具提供动作说明，并明确未要求修改的标题保持原值。保留越界尝试，不让评分器代替模型修正计划。
5. 将输入变化、卡片接纳及语义复核分别记录。已有六题只作为开发诊断；提示与卡片冻结后，换新的来源家族和目标做保留评估。

本轮未执行这些新模型试验，不使用剩余请求额度补抽漂亮卡。单次六题、三个相关来源组、P 全部无卡，无法估计稳定泛化收益；G 在隐藏重复题表现较好，但额外改名和缺能力误调用也说明参考卡不能保证执行正确。

收尾核对发现，当前工作区的 `notes.py`、`note_proposals.py`、`note_conversation.py` 已与启动清单中的哈希不同；这些文件未由本轮导出修复修改，未回退其变化。领域模块在进程内首次加载后缓存，不会随文件变化热重载；但清单只保存启动哈希，没有保存这些旧文件的完整源码，当前工作区不能直接代表当时的代码。差异已另记清单，下一轮应保存独立的冻结源码副本及加载时哈希，使输入版本真正可复现。原始模型输出和领域观察仍按原报告保留。
