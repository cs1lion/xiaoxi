# ============================================================
# 需求契约 —— 每一项都能验证，不是愿望清单
# ============================================================

## 主场景（第一版只做这一个）
个人中文聊天角色：文字 + 语音，日常聊几次，记得重要经历，性格稳定，
暂时不做直播、游戏控制。

## 角色契约
见 `config/persona.yaml`。四层结构：
身份 / 稳定倾向 / 互动方式 / 可变状态，每层都写了"因此会做出什么不同的事"，
每条性格都配了正例、反例、边界。

## 记忆契约
见 `config/memory.yaml`。四类记忆（fact / episode / todo / self_state），
每类回答了六个问题：什么值得记、何时存、何时用、冲突怎么办、不确定怎么办、用户怎么管理。

硬规则：
- 没有检索到记忆 ≠ 这件事没发生过
- 检索到记忆 ≠ 它仍然准确
- 三档来源必须分开显示：**你明确说过的 / 我推测 / 我不确定**
- 删除是真删除（行 + 检索索引 + 派生统计一起消失），不是隐藏

## 节奏契约
见 `config/pacing.yaml`：回复长度、追问上限、话题延续次数、
主动发言的授权开关与冷却、拒绝后的冷静期、语音打断。

## 姿态契约
见 `config/avatar.yaml`。形象的所有可调项都在这里，代码里没有魔数：
外观配色 / 中位姿态 / 每个参数的跟随速度 / 7 种情绪的表情目标 / 手势关键帧轨道 / 自动触发器。
情绪标签与 `persona.yaml` 的 `tts_emotions` 一一对应，所以"听起来什么语气"和"看起来什么表情"
不会各说各话。

实现分四层驱动，按优先级叠加（低 → 高）：待机微动 → 情绪表情 → 手势轨道 → 口型。
同一个参数默认是**叠加**而不是覆盖（眯眼 + 眨眼 = 真的闭上），
只有口型驱动会显式独占 `ParamMouthOpenY`（说话时手势不能抢嘴）。

硬规则：
- 口型必须由**已知文本**推出，不用 MFCC 从波形猜。中文的字就是口型的真相来源
- 口型时间轴按每段音频的**真实时长**摊平，不依赖任何 TTS 音素时间戳
- 打断时嘴要立刻还回中位，不允许停在半个口型上
- `emotion` 到达前不预演情绪；情绪只在文本到达后切换，不跟着音量抖

## 验收
`eval/scenarios.json` 是 9 个场景，`scripts/eval_scenarios.py` 跑它们。

## 明确不做（第一版）
多 agent、游戏控制、直播弹幕、Live2D / VRM 三维形象
（形象层已经把参数名对齐 Live2D ParameterModel，换渲染后端时驱动和配置可以整体搬过去）、
向量数据库（先用可重建的 TF-IDF 混合检索，换库不影响上层）。
